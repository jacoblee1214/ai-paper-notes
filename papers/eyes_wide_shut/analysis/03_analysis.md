# 03 검증: 표 재계산, 통계, 토이 (arXiv:2401.06209)

모든 수치는 `analysis/*.py`(numpy·scipy·PyMuPDF·PIL, CPU 수 초)가 만들고 결과는 `*_results.json`에 있습니다. 입력은 논문 표(`paper_tables.py`), PDF 벡터에서 읽은 그림 6(`figure_extract.py`, 눈금선 보정, 마커와 막대의 차이 ≤ 0.1), 공개 데이터(`data/`, HF `MMVP/MMVP`, `MMVP/MMVP_VLM`, 2026-11-26 내려받음, gitignore)입니다. 코드·모델 실행, 설치, API 호출은 하지 않았습니다.

**표본의 단위.** MMVP는 150쌍(300문항)이고 점수는 쌍 단위입니다. 모든 구간은 쌍을 독립 시행으로 보는 Wilson 95%입니다. 모델 간 비교는 같은 문항에서 하므로 짝지은 검정이 맞지만 문항별 결과가 공개되지 않아, 불일치율 ψ를 가정한 정확 이항 검정과 MDE ≈ 2.80·√(ψ/n)(`little_power/`)로 근사합니다.

## 1. 채점과 우연 수준 (`chance_toy.py`, `chance_results.json`)

### 1.1 파일 구조 (C1)
`Questions.csv` 300행에서 연속 두 행이 한 쌍입니다. 150쌍 모두 질문·보기가 같고 **정답이 다릅니다**. 더 강한 구조가 있습니다. **150쌍 전부에서 홀수 번째 행의 정답이 (a), 짝수 번째 행이 (b)**입니다. 보기는 모두 2개이고 Yes/No 질문이 122문항(61쌍)입니다. 이 구조는 논문에 없습니다.

### 1.2 이미지를 보지 않는 응답의 쌍 점수 (C2, C3)
- 항상 (a), 항상 (b), 항상 Yes, 항상 No 같은 **결정적 응답은 쌍 점수 0%**(문항 단위로는 정확히 50%).
- 이미지와 무관하게 질문마다 독립으로 P((a)) = p로 답하는 응답자의 쌍 점수는 p(1−p)이고 p = 0.5에서만 25%입니다. 몬테카를로(20만 번, 150쌍)가 일치합니다: p=0.5 → 평균 25.00, SD 3.53; p=0.2 → 16.0; p=0.063 → 5.9(`chance_results.json` C3). 즉 **25%는 이미지를 보지 않는 모든 응답의 상한**입니다.
- 두 질문에 같은 답을 내는 경향(이미지가 거의 같아서 둘을 구별 못 하는 모델)이 상관 ρ로 표현되면 쌍 점수는 p_a(1−p_a)(1−ρ)입니다. ρ=0.5에서 12.5%, ρ=0.8에서 5.0%, ρ=1에서 0%(C4).
- 이미지를 보고 비율 d의 쌍을 맞히고 나머지는 이미지를 보지 않는다면 점수 = d + (1−d)·p(1−p) ≤ d + (1−d)/4이므로 **d ≥ (점수−25)/75**. GPT-4V 38.7 → d ≥ 18.3%, Gemini 40.7 → ≥ 20.9%, PaliGemma 47.3 → ≥ 29.7%, 사람 95.7 → ≥ 94.3%(C3b). 가정은 "맞히지 못한 쌍은 이미지 정보가 없다"는 단순 모형입니다.

### 1.3 논문의 "우연 수준 이하" 주장 점검
논문은 "GPT-4V와 Gemini 외 모델은 무작위 추측 수준(25%) 아래"라고 쓰고 그림 4에 "Random Guess 25.0"을 막대로 그립니다(§2.3, 그림 4). 확인 결과:
- **25%는 독립 무작위 추측(질문마다 동전 던지기)의 기대값**입니다. 쌍 단위 구조에서 이미지에 둔감한 모델은 이보다 낮은 값이 정상이고(§1.2), 상한이 25%이므로 "무작위보다 나쁘다"를 "이미지를 적극적으로 오해한다"로 읽을 근거가 없습니다. LLaVA 6.0은 P((a))가 0.06인 이미지 무관 응답과 같습니다(C3).
- 25%와 정확 이항 검정: Gemini 40.7 p=2.7e-5, GPT-4V 38.7 p=2.1e-4(둘 다 **25% 초과**), LLaVA-1.5 24.7 p=1.0(우연과 같음), Bard 19.0 p=0.07, Bing 17.3 p=0.03, InstructBLIP 16.7 p=0.02, mini-GPT4 12.7 p=3e-4, LLaVA 6.0 p=2e-9(`stats_results.json` S2). 150쌍에서 우연 수준 SD는 3.54%p입니다. 7개 모델을 한꺼번에 검정하면(보정 기준 0.007) "25% 미만"이 유의한 것은 mini-GPT4와 LLaVA뿐이고 Bing(0.03)·InstructBLIP(0.02)은 단독 기준에서만, Bard(0.07)와 LLaVA-1.5(1.0)는 구분되지 않습니다.
- 의미가 있는 비교는 "25%보다 낮다"가 아니라 "**25%보다 높은 모델이 둘뿐이다**"입니다.

### 1.4 채점 코드와의 대조
`gpt_grader.py`는 GPT-4(`gpt-4-0314`, 온도 0.2)에게 질문·정답 글자·모델 응답을 주고 예/아니오를 받습니다. 연속 두 줄이 모두 "yes"일 때만 쌍 1점이고 판정 불명("Could not determine yes or no.")은 오답입니다. 논문은 판정자를 쓴다는 말도 하지 않습니다(§2.3, 부록 B.1). 닫힌 모델은 웹 UI·ChatGPT로 질의했으므로 이 스크립트가 쓰였는지 알 수 없습니다(`04` D1, D2).

### 1.5 MMVP-VLM의 우연 수준 (C5)
15쌍, 두 텍스트가 각자 두 이미지 중 하나를 고르는 쌍 채점이므로 독립 무작위는 25%이고 **한 패턴 15쌍의 우연 SD는 11.2%p**입니다. 두 텍스트에 같은 이미지를 고르는 인코더(임베딩이 거의 같음)는 0%입니다. 정답은 질문 번호 홀짝(`qid % 2 == 1` → 첫 이미지, 코드 L76–77)으로 정해지므로 CSV의 쌍 순서가 정답입니다.

### 2.2 모델 간 차이 (비짝지은 Fisher, 보수적)
Gemini − GPT-4V = 2.0 (p=0.81). GPT-4V − LLaVA-1.5 = 14.0 (p=0.013), Gemini − LLaVA-1.5 = 16.0 (p=0.0045), GPT-4V − Bard = 19.7 (p=2e-4). ### 2.3 최소 검출 차이
짝지은 MDE(α=0.05, 검정력 80%): ψ=0.1 → 7.2%p, 0.2 → 10.2%p, 0.3 → 12.5%p, 0.5 → 16.2%p. 비짝지은은 p≈0.4에서 15.8%p. 해석: **150쌍에서 10%p 아래의 모델·방법 차이는 판별되지 않습니다.** 부록 B.3의 보기 순서 절제(+1.6, 2쌍)와 표기 절제(−1.4, 2쌍)는 "차이 없음"이라고도 "차이 있음"이라고도 말할 수 없고(MDE 10.2), 논문이 이를 "언어 환각이 아니라 시각 한계" 증거로 쓰는 것은 같은 보기 순서 구조(§1.1)에서도 점수가 같다는 것만 확인해 줄 뿐입니다.

## 3. CLIP-blind 선별과 선택 효과

### 3.1 선별 절차 (§2.1)
후보 쌍 → CLIP ViT-L-14 코사인 > 0.95 AND DINOv2 ViT-L-14 코사인 < 0.6 → 사람이 시각 차이를 찾아 질문 작성 → 150쌍. 코퍼스 크기, 통과 쌍 수, 탈락 비율은 논문에 없고 선별 코드도 없습니다(GitHub 이슈 #10에 저자가 "CLIP 이미지 인코더 출력의 코사인"이라 답한 기록, 최종 층·CLS 여부는 미확인). 이슈는 외부 보고라 우리가 확인하지 않았습니다.

### 3.2 구조적으로 보장되는 것
1. **CLIP ViT-L-14에 대한 적대적 선택**: 모든 쌍은 CLIP 코사인 0.95 이상이므로 이 인코더의 전역 임베딩은 두 이미지를 거의 구별하지 못합니다. 이 인코더를 쓰는 LLaVA(224)·LLaVA-1.5(336)가 낮은 것은 부분적으로 선별의 결과입니다. 이 선별에 쓰이지 않은 인코더(SigLIP, DFN 등, 표 1 37.8–39.3%)가 OpenAI ViT-L보다 높은 것도 같은 구조에서 예상됩니다.
2. **DINOv2에 대한 우호적 선택**: 모든 쌍은 DINOv2 ViT-L-14 코사인 0.6 미만이라 DINOv2 전역 임베딩이 두 이미지를 구별합니다. DINOv2를 섞은 모델이 이 쌍들에서 좋아지는 것은 부분적으로 "시험이 DINOv2가 구별하는 쌍을 골랐다"는 것과 구별되지 않습니다.
3. **완화 증거**: 선별에 쓰이지 않은 MAE(+2.6)와 MoCo v3(+2.0)도 비슷한 이득입니다(표 6). 그러나 세 변형(26.7, 27.3, 28.0)의 차이는 ≤ 2쌍이라 구분되지 않고, 각각의 기준선 대비 이득(+3, +4, +5쌍)도 단독으로 유의하지 않습니다(§6.3). **이득이 DINOv2 특이적인지 SSL 일반인지 판별할 수 없습니다.**
4. **교란**: 표 3·6·7의 LLaVA-1.5 대 I-MoF 비교는 해상도(336 대 224)와 시각 토큰 수(576 대 512)가 달라 인코더 추가 효과만이 아닙니다(§6.3).

### 3.3 토이 (`selection_toy.py`, `selection_results.json`)
의미 s와 세부 d를 가진 합성 이미지, 인코더 A(의미 위주, CLIP 비슷), B(세부 위주, DINO 비슷), C(둘을 같은 비중으로 섞은 제3 인코더)를 만들고 A는 비슷(코사인 상위 30%)·B는 다른(하위 30%) 쌍을 고른 뒤 두 이미지의 속성(d의 한 좌표 부호) 차이를 선형 읽기로 맞히게 했습니다. 40시드 평균(선별 쌍 약 263개):
- 선별 없는 쌍: A 64.7, B 82.7, C 77.5, A+B 83.3, A+C 78.7.
- A≈, B≠ 선별 쌍: A 63.8, B 86.7, C 80.8, A+B 86.8, A+C 81.4. A는 소폭 낮아지고 B·C는 오릅니다.
- "A에 더하는 인코더의 이득"은 선별 없는 쌍에서 A+B 18.6, A+C 14.0, 선별 쌍에서 A+B 23.0, A+C 17.6이라 **A에 불리한 선별만으로도 무엇이든 세부를 담은 인코더를 더하는 이득이 약 4%p(3.6–4.4) 부풀어 오릅니다.**
- 같은 B를 더할 때 "B로 선별"한 경우와 "C로 선별"한 경우의 이득 차이는 0.4%p(시드 SD 4.3, SE 0.7)로 **선별에 쓴 인코더에 특이적인 순환 이득은 이 토이에서 확인되지 않았습니다**. C 쪽은 2.2(SE 0.7)입니다.
- 토이는 방향을 보는 것이지 크기를 맞추는 것이 아닙니다(선형 읽기, 가우시안 특징). 실제 MoF는 LLM 위의 학습이라 다릅니다.

결론: 선별은 MMVP 점수를 **CLIP ViT-L-14 모델에 불리하게, 세부를 담은 다른 특징에는 유리하게** 기울이는 구조이고, 이 크기(토이 약 4%p)는 150쌍 MDE(10–16%p)보다 작아서 표본이 이를 가립니다. MMVP는 "MLLM의 일반 시각 능력"이 아니라 "이 인코더 쌍의 불일치 위에서 만든 시험"으로 읽는 것이 안전합니다(`construct_validity/`).

### 4.3 이것이 "CLIP이 병목"을 뒷받침하는가
- **CLIP 기반이 아닌 모델의 상관도 높습니다.** Gemini 0.72, Bard 0.79(표 5)는 CLIP이 아닌(또는 알려지지 않은) 인코더를 쓰는 모델이고 InstructBLIP(0.61)과 비슷합니다. 이 상관은 CLIP이 병목이어서가 아니라 **패턴의 공통 난이도**(모든 모델이 방향·글자를 어려워함)로도 설명됩니다. MLLM끼리의 상관도 높습니다: Gemini–GPT-4 0.82, LLaVA-1.5–Gemini 0.71(S4_mllm_vs_mllm_r).
- **선별과 얽힘:** 쌍이 OpenAI ViT-L-14에 대해 선별되었으므로 이 인코더의 패턴별 점수는 선별 때문에 낮습니다. 표 1의 한 행과의 상관을 보면 LLaVA-1.5는 OpenAI 224(선별에 쓰인 인코더)와 **0.88**, 실제로 쓰는 336 인코더와는 **0.32**, InstructBLIP은 EVA01(선별과 독립)과 0.43입니다(S4_single_clip_row_r, 점 9개라 모두 구간이 넓고 사후 탐색입니다). 인코더 내재 약점이 MLLM으로 전달되기보다 선별 기준이 만든 난이도가 공유되었을 가능성을 배제할 수 없습니다.
- **칸 크기:** 패턴별 MLLM 점수는 MMVP 문항을 GPT-4로 나눈 묶음이고(라벨 미공개) 그림 값이 하나의 쌍 수 n의 k/n으로 설명되는 패턴은 6개(가능한 최소 n: 색 13, 상태 15, 수 11, 위치 23, 글자 4, 방향 12)이고 3개(구조, 시점, 존재)는 어떤 n ≤ 40으로도 설명되지 않습니다. 한 칸의 Wilson 구간이 ±20%p를 넘습니다. 매핑 파일은 GitHub 이슈 #3에서 공개를 약속했다가(외부 보고) 이번 clone에는 없습니다(`04` D11).

## 7. 데이터 감사와 사람 성능 (`image_stats.py`, 공개 CSV)

- **이미지:** MMVP 300장과 MMVP-VLM 270장이 **전부 224×224**입니다(PIL, `image_results.json`). 정사각형이라 공식 평가 스크립트의 중앙 자르기(`image_processor.preprocess`)는 자르지 않습니다. 해상도 336·384 모델은 확대된 224 이미지를 봅니다. 그림 1에 GPT-4V가 "image is small and low resolution"이라 답한 예가 있고 PaliGemma는 448px 입력에서 MMVP 47.3입니다. 해상도가 점수에 미치는 영향은 이 이미지로는 시험되지 않습니다.
- **정답 오류 의심 2쌍:** GitHub 이슈 #30·#14(열림, 외부 보고)가 99/100과 279/280의 정답을 의심합니다. 우리가 이미지를 직접 본 결과 **99(짧은 상아)가 (a) 길다, 100(긴 상아)이 (b) 짧다로, 279(벤치에 앉은 노인)가 (a) 서 있다, 280(업은 노인)이 (b) 앉아 있다로** 정답이 서로 바뀐 것으로 보입니다(사람 한 명의 육안 확인, 저자 확인 없음). 사실이면 150쌍 중 2쌍이 틀려 **정직한 완벽한 모델의 상한이 98.7%**입니다. 사람 점수와 MoF 점수의 크기(1쌍 = 0.67%p)에 비해 작습니다.
- **사람 성능 95.7%(§2.3, 그림 4, 부록 B.4):** 자원자 4명이 300문항을 풀고 "질문의 평균"입니다. 4 × 300 = 1,200 답에서 1,148.4개는 정수가 아니라 사람별 점수의 평균입니다. 모델 점수는 쌍 단위인데 같은 문단에 쌍 단위 정의가 함께 적혀 있어 사람 점수가 어느 단위인지 불분명합니다. 질문 단위 95.7%이면 독립 가정의 쌍 단위는 약 91.6%, 쌍 단위 95.7%이면 질문 단위는 약 97.8% 이상입니다. 4명이라 사람 간 변동은 추정할 수 없고 질문별 "이 질문은 좋지 않다" 표시(그림 8) 결과는 보고되지 않았습니다. 두 단위의 차이(약 4%p)는 150쌍 MDE보다 작아 "사람 대 모델"의 결론은 바뀌지 않습니다.
