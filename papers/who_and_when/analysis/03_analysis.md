# 03. 재계산과 검정: Who&When

모든 수치는 `analysis/data_stats.py`(공개 데이터 통계, 결과 `data_stats_results.json`)와 `analysis/recompute_tables.py`(표 값을 옮겨 적은 뒤 계산, 결과 `recompute_results.json`)로 다시 만들 수 있습니다. 그래프는 `analysis/plot_figures.py`입니다. 공개 데이터는 공식 저장소의 `Who&When/`(커밋 `b2bae5c`)를 썼고, 모델은 한 번도 호출하지 않았습니다. 논문 표 값은 v3의 Table 1–4를 옮겨 적었습니다.

한계부터 적습니다. **개별 예측이 공개되지 않아서** 표의 정확도에서 맞힌 수 k를 거꾸로 추정했고, 방법 간 비교는 짝지은 검정(McNemar)이 아니라 비짝 Fisher 정확 검정입니다. 같은 궤적을 같은 모델로 평가하므로 짝지은 검정이 더 강력하고, 아래 유의하지 않다는 판정은 "이 표만으로는 확인되지 않는다"는 뜻입니다.

표 값이 어떤 N에 대해 k/N(반올림 또는 버림)으로 나오는지 찾았습니다(`recompute_results.json`의 `denominator_fit`).

| 셀 묶음 | 결과 |
|---|---|
| 손수 만든 에이전트 수준 12셀 | 모두 k/58 |
| 손수 만든 단계 수준, AAO·SBS 8셀 | **k/57** (5.26=3/57, 7.02=4/57, 3.51=2/57, 8.77=5/57) |

해석: 손수 만든 단계 수준 AAO·SBS에서 로그 하나가 분모에서 빠져 있고(57), 이 이유는 논문에 없습니다. 알고리즘 생성 셀은 단일 분모에서 나오지 않았습니다(GAIA와 AssistantBench 부분집합 평균이나 반복 평균일 수 있으나 논문은 밝히지 않았습니다). 아래 알고리즘 생성 검정은 N=126을 가정한 근사입니다. 공식 평가 코드는 분모를 폴더의 파일 수(58, 126)로 고정합니다(`04` D6). 따라서 57은 공개 코드로 재현되지 않습니다.

## 3. 표 1 Random 행: 두 값이 자리가 바뀐 것으로 보입니다

공개 데이터에서 균등 무작위의 기대 정확도를 계산했습니다. 에이전트 수준은 궤적마다 1/(서로 다른 에이전트 이름 수), 단계 수준은 1/(로그 길이)의 평균입니다.

| 셀 | 논문 표 1 | 재계산 |
|---|---:|---:|
| 알고리즘 생성, 에이전트 | 29.10 | **29.10** |
| 알고리즘 생성, 단계 | 19.06 | **12.00** |
| 손수 만든, 에이전트 | 12.00 | **19.06** |
| 손수 만든, 단계 | 4.16 | **4.16** |

네 값이 같은 정의(소수 둘째 자리까지)로 모두 정확히 나오고 **두 값(12.00, 19.06)만 자리가 바뀌어 있습니다.** 표 PDF를 직접 확인했으나(그림으로 판독), 저자가 의도한 다른 정의가 있을 가능성은 남습니다. 그러나 두 값이 모두 이 정의에서 정확히 재현되는 이상 단순 오기입이 가장 합당합니다. v1과 v3 모두 같은 값이고, DoVer(arXiv:2512.06749)의 표 5도 같은 배치를 옮겨 적었습니다.

**결과에 미치는 영향.**

- 본문 §4.3은 "all-at-once는 평균 성능이 무작위보다 낮아 실용성이 없다"고 말합니다. 알고리즘 생성의 무작위 단계 정확도는 19.06이 아니라 **12.00**이므로 AAO의 12.50(정답 있음), 13.53(정답 없음)은 무작위보다 낮지 않고 같은 수준입니다(이항 검정 p = 0.44, 0.34). 손수 만든 AAO 단계 수준(5.26, 3.51)도 무작위 4.16과 구분되지 않습니다(p = 0.42, 0.69; 평균 4.39 대 4.16).
- 초록의 "일부 방법은 무작위보다 낮다"가 성립하는 셀은 알고리즘 생성 SBS 에이전트 수준(정답 없음) **26.02 < 29.10** 하나입니다(p = 0.79로 같은 수준이라는 뜻). 바로잡은 기준선에서는 "무작위보다 낮다"보다 "무작위와 구분되지 않는다"가 정확합니다.
- 반대 방향으로 약해지는 곳도 있습니다. 알고리즘 생성 SBS(정답 있음) 단계 수준 25.51은 잘못된 무작위(19.06)와는 p = 0.048이지만, 바로잡은 12.00과는 p < 0.001로 오히려 더 유의합니다. 즉 이 부분집합의 SBS·BS 우위는 표의 Random 오기에도 살아남습니다.

비짝 Fisher 정확 검정(양측)입니다. 방향은 모두 논문과 같고, 유의한 것만 적었습니다. 전체 목록은 `recompute_results.json`의 `tests.method_pairs_fisher`입니다.

- 세 방법 모두 모든 허용 오차에서 균등 무작위에 대한 단측 이항 검정 p > 0.09(N=58)입니다. SBS는 ±3에서 무작위(24.2)보다, ±5에서도(33.62 대 34.11) 낮습니다. **발견 5("허용 오차를 주면 AAO가 경쟁력을 얻는다")는 AAO가 무작위와 구분되지 않는 영역에 들어온다는 뜻에 더 가깝습니다.** 그래프는 `own_tolerance_vs_random.png`입니다.

- **프롬프트 형식 민감도.** DoVer(arXiv:2512.06749, 부록 A)는 같은 GPT-4o AAO에서 단계 번호를 로그에 명시하면 단계 정확도가 6.04%(자체 재현)에서 20.69%(손수 만든, 정답 있음)로 올라갔다고 보고합니다. 그리고 논문 프롬프트로는 예측 단계 번호가 로그 길이를 넘는 경우가 손수 만든 13.8%, 알고리즘 생성 20.6%라고 합니다. 이 값은 DoVer의 보고이고 우리가 재현하지 않았습니다. 표 1의 단계 수준 수치가 모델 능력보다 프롬프트 형식에 얼마나 의존하는지 보여 줍니다.

## 7. 표 3, 표 4, 그림 7 일치와 검정

**표 3 대 표 1·4.** GPT-4o 손수 만든 58건의 설정 둘을 합쳐(분모 116 또는 114) 표 1에서 풀링하면 표 4와 모두 일치합니다(AAO 에이전트 63/116 = 54.31, AAO 단계 5/114 = 4.39, SBS 에이전트 39/116 = 33.62, SBS 단계 9/114 = 7.89, BS 에이전트 51/116 = 43.97). 표 3은 이와 **다릅니다.**

| 표 3 셀 | 표 3 값 | 표 1·4에서 풀링한 값 | 판정 |
|---|---:|---:|---|
| AAO 에이전트 | 57.02 (65/114) | 54.31 (63/116) | 불일치 |
| SBS 에이전트 | 35.96 (41/114) | 33.62 (39/116) | 불일치 |
| BS 에이전트, 단계 / AAO·SBS 단계 | 43.97, 6.90 / 4.39, 7.90 | 같음 | 일치 |

AAO·SBS의 에이전트 수준만 표 1·4와 다르므로(분모도 114로 달라짐) 다른 실행이거나 다른 부분집합일 가능성이 있지만 논문은 밝히지 않습니다. 혼합 방법의 에이전트 수준 57.02는 AAO와 같은 값이라 혼합이 에이전트 수준에서 개선을 주지 않는다는 점은 변함이 없습니다.

**혼합(발견 7).** 단계 수준 12.28 = 7/57(95% 구간 6.1–23.2%). 단일 최고 방법과의 비교(SBS 9/114 대 약 5/57 환산)는 p = 0.76이고, "항상 마지막 단계" 12.07과도 구분되지 않습니다(p = 0.54). 토큰 비용은 AAO(17,106)의 약 9배, BS(34,659)의 약 4배인 149,177입니다.

**표 4(o1, R1).** 값은 모두 k/58로 재현됩니다(41.38 = 24/58, 56.90 = 33/58 등). 같은 궤적이라는 점을 무시한 비짝 Fisher로 GPT-4o(풀링 값 환산)와 비교하면 8개 비교 모두 p ≥ 0.19입니다. 본문 "R1이 GPT-4o보다 4개 중 3개에서 낮다"는 표 값으로 맞지만(AAO 단계 3.45 대 4.39, SBS 에이전트 32.76 대 33.62, SBS 단계 6.90 대 7.90), 차이는 모두 잡음 범위입니다. 한 번의 실행입니다.

**그림 7(추론 프롬프트 절제).** 본문 수치(알고리즘 생성 AAO 에이전트 7.4%p, SBS 단계 4.4%p 하락)는 그림 값(52.7 대 45.3, 20.4 대 16.0)과 맞습니다. 그러나 Fisher p = 0.31, 0.42(N=126), 손수 만든 두 비교는 p = 0.58, 1.0(N=58)입니다. "큰 성능 향상"은 표본으로는 확인되지 않습니다. 설정 둘을 합친 값이라 N은 더 크지만 동일 궤적 반복이어서 효과적인 표본은 늘지 않습니다.

## 9. AgenTracer 표 1의 Who&When 열과 단순 기준선

AgenTracer 분석(`agentracer/analysis/recompute_tables.py`의 표 값)의 w/ G 값을 가져와 같은 단순 규칙과 Fisher 검정으로 비교했습니다(분모 58, 126은 이 폴더의 데이터로 확인).

| AgenTracer 셀 | 값 | 단순 규칙 | p |
|---|---:|---|---:|
| 손수 만든 에이전트 | 69.10 | 마지막 발화자 60.34 | 0.44 |
| 손수 만든 에이전트 | 69.10 | 항상 WebSurfer 56.90 | 0.25 |
| 손수 만든 단계 | 20.68 (12/58) | 항상 마지막 단계 12.07 | 0.32 |
| 알고리즘 생성 에이전트 | 69.62 | 첫 발화자 49.21 | 0.001 |
| 알고리즘 생성 단계 | 42.86 (54/126) | 항상 0단계 15.87 | < 0.001 |

AgenTracer 기준선 모델도 같은 방식으로 비교하면(예: Claude-Sonnet-4 알고리즘 생성 단계 40.65) 알고리즘 생성 단계 수준은 단순 규칙보다 분명히 높고, 손수 만든 58건에서는 단순 규칙과 구분되지 않습니다. 이 점에서 AgenTracer가 주장하는 손수 만든 Who&When 우위(`agentracer/analysis/03` §3에서 이미 Fisher로 약하다고 본 비교)와 같은 방향입니다. AgenTracer의 "최대 18.18%"는 이 폴더에서 검증하지 않았습니다.

## 10. 한계와 확인되지 않은 것

- 개별 예측이 없어 짝지은 검정과 부트스트랩을 할 수 없습니다. 알고리즘 생성 셀의 k는 N=126 가정에서 반올림한 근사입니다.
- 단순 기준선 중 "항상 WebSurfer"와 "항상 마지막 단계"는 정답 분포를 본 상수입니다. 새 데이터에서의 정확도가 아니라 이 데이터에서의 기준입니다. "마지막 발화자", "첫 발화자", "최다 발화자"는 라벨을 쓰지 않는 규칙입니다.
- 논문 정확도가 공식 `evaluate.py`로 만들어졌는지 알 수 없습니다. 이 평가기는 부분 문자열 일치로 손수 만든 단계 수준의 무작위 정확도를 4.16에서 8.89%로(항상 마지막 단계는 12.07에서 20.69%로) 부풀립니다(`04` D1). 알고리즘 생성은 단계가 한 자리라 영향이 없습니다. 이 평가기가 쓰였다면 손수 만든 단계 수준 표는 과대일 수 있고, 쓰이지 않았다면 영향이 없습니다.
- 식 4의 반사실 검증이 실제 라벨에는 적용되지 않았으므로(`01` §2) 라벨이 "맞는다"는 보장이 없습니다. 표의 정확도는 사람 주석과의 일치도입니다.
- 모델 재실행, 새 라벨링, API 호출은 하지 않았습니다.
