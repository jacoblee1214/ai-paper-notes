# 01. 논문 분석: Which Agent Causes Task Failures and When? (Who&When)

분석 대상은 arXiv v3(2025-06-02, camera-ready)입니다. v1(2025-04-30)과 v3의 표 수치는 같고(숫자 토큰 비교), 달라진 것은 참고문헌 추가와 초록의 코드 주소입니다. ICML 2025 스포트라이트(PMLR 267, 76583–76599)로 출판되었습니다. 근거 위치는 절·표·식 번호로 적었고, 우리 검증은 `03`(표·통계)과 `04`(코드·데이터)를 가리킵니다.

## 1. 문제

LLM 다중 에이전트 시스템이 실패했을 때 **어느 에이전트(who)가, 어느 단계(when)에서** 결정적 오류를 냈는지 자동으로 찾는 문제입니다(§1, §2). 지금까지는 사람이 로그를 읽어 찾았고, 저자들은 이 작업의 사람 비용(주석자 3명이 각각 23.2–30.9시간, 그림 2a)을 동기로 듭니다(§3.3).

## 2. 정식화 (§2, 식 1–5)

- 식 1: 시스템 M = ⟨N, S, A, P, φ⟩. 턴제로, 시간 t에 정확히 한 에이전트 φ(t)만 행동합니다.
- 식 2: 궤적 τ의 결과 Z(τ) ∈ {0, 1}(1이 실패).
- 식 3–4: 단계 t의 행동 a_t를 "올바른" 행동으로 바꾼 개입 I(i,t)를 가했을 때 성공하면 (i, t)를 **결정적 오류**로 정의합니다. 지시자 Δ_{i,t}(τ) = 1이면 결정적 오류입니다.
- 식 5: 결정적 오류가 여럿이면 **가장 이른 시간**의 쌍을 정답 (i\*, t\*)로 둡니다.

주의할 점은 이 정의가 반사실 재실행을 전제하지만, 실제 라벨은 재실행이 아니라 **사람의 판단**으로 붙였다는 것입니다(§3.2, 부록 F의 지침: "약간의 주관성을 허용", "뚜렷한 실수가 없으면 마음속에서 한 에이전트를 정한다"). 식 4의 의미 그대로 검증된 라벨이 아닙니다. 이 차이는 `03` §10과 `04`에서 이어서 다룹니다.

## 3. 데이터셋 Who&When (§3, 부록 C)

| 부분집합 | 시스템 | 과제 출처 | 수 | 로그 길이 | 근거 |
|---|---|---|---:|---|---|
| 알고리즘 생성 | CaptainAgent가 질문마다 만든 팀(전부 GPT-4o), 최종 구성만 사용 | GAIA 98 + AssistantBench 28 | 126 | 5–10 | §3.1, 표 5 |
| 손수 만든 | Magentic-One(에이전트 5개) 한 시스템 | GAIA 30(무작위) + AssistantBench 28 | 58 | 5–130 | §3.1, 표 5 |

- 합계 184개 주석 과제, "127개 시스템"은 CaptainAgent 126개 + Magentic-One 1개입니다(초록, §3). 실패한 실행만 남겼습니다(§3.1).
- 각 항목은 질문, 실패 로그, (알고리즘 생성의 경우) 시스템 정보, 주석(실패 에이전트, 실패 단계, 자연어 이유)으로 구성됩니다(§3).
- 주석 절차(§3.2): 전문가 3명, 3라운드(독립 주석, 불확실 항목 합의, 교차 검증). 불확실하다고 표시한 비율은 15–30%, 투표 전 초기 불일치율은 그림 2c에 있습니다. **카파나 일치 계수는 보고하지 않았습니다.**

## 4. 세 가지 귀인 방법 (§4.1, 부록 A, G)

| 방법 | 절차 | 비용(부록 D) |
|---|---|---|
| All-at-once(AAO) | 질문과 전체 로그를 한 번에 주고 에이전트와 단계를 묻습니다 | C + n·T_l (식 6) |
| Step-by-step(SBS) | 로그를 한 단계씩 늘려 가며 "이 단계에 오류가 있나"를 묻고, 처음 "Yes"에서 멈춥니다(알고리즘 1) | i\*·C + T_l·i\*(i\*+1)/2 (식 7) |
| Binary search(BS) | 로그를 반으로 나눠 오류가 앞쪽인지 뒤쪽인지 묻고 반복합니다(알고리즘 2) | ⌈log₂ n⌉·C + Σ n·T_l/2^(i−1) (식 8) |

설정은 **정답 있음(w/ GT)**과 **정답 없음(w/o GT)** 두 가지이고 표 1의 수치는 기본 GPT-4o 결과입니다(§4.2). 지표는 에이전트 수준 정확도, 단계 수준 정확도, 허용 오차를 둔 단계 정확도입니다(§3 도입부, 3.1절 앞).

## 6. 한계 (논문이 적은 것과 우리가 찾은 것)

논문이 적은 것: 안정적이지 않은 사람 주석(§3.3), 큰 계산·토큰 비용으로 다른 모델은 손수 만든 부분집합만 평가(§4.4), 추론 모델 프롬프트 수정(§4.8).

우리가 찾은 것:

1. **표 1의 Random 행 오배치.** 재계산하면 알고리즘 생성 단계 무작위는 12.00, 손수 만든 에이전트 무작위는 19.06입니다(`03` §3).
2. **무작위 기준선 정의가 약합니다.** 손수 만든 시스템의 에이전트 수를 역할 문자열(예: `Orchestrator (thought)`)과 `human`까지 세어서 19.06이 나옵니다. 부록 표 5는 에이전트를 최대 5개로 셉니다. 기본 에이전트로 세면 무작위 42.2%입니다(`03` §4).
3. **단순 규칙이 LLM과 비슷합니다.** 손수 만든 58건에서 "마지막 발화자"는 60.3%, "항상 WebSurfer"는 56.9%로 GPT-4o 최고(55.2%)와 구분되지 않습니다(`03` §4).
4. **표 3의 에이전트 수준 값이 표 1·4와 맞지 않습니다**(`03` §7).
5. **셀의 분모가 일정하지 않습니다.** 손수 만든 단계 수준 일부 셀은 k/57, 나머지는 k/58입니다. 알고리즘 생성 셀은 k/126으로 설명되지 않습니다(`03` §2).
6. **단일 실행입니다.** 시드, 반복, 신뢰구간이 없습니다. 모델 출력이나 개별 예측도 공개되지 않아 짝지은 검정을 할 수 없습니다.
7. **라벨의 유효성.** 식 4의 반사실 검증 없이 사람 판단으로 붙인 라벨이고, 이후 연구(DoVer)는 29건 중 14건의 라벨이 불확실하다고 보고합니다(`02` §3).
8. **판정 모델과 데이터 생성 모델이 같은 계열입니다.** 알고리즘 생성 로그는 전부 GPT-4o가 만들었고 기본 판정 모델도 GPT-4o입니다. 자기 선호 효과는 분리해 보지 않았습니다.
9. **공식 코드와의 차이**는 `04`(D1–D10)에 있습니다.

## 7. 한 문장 요약

실패 귀인을 처음으로 벤치마크로 만들고 세 가지 단순한 LLM 판정 방법을 비교했습니다. 가장 강한 결론은 "에이전트 수준은 절반 정도 맞고 단계 수준은 거의 못 맞힌다"인데, 우리 재계산에 따르면 이 격차의 상당 부분은 단순 규칙 기준선이 이미 설명합니다.
