### 이 목록에서 읽을 수 있는 흐름

1. **정확도 경쟁**: RAFFLES, CDC-MAS, EMFA 등이 단계 정확도를 한 자릿수에서 20–36%로 올렸다고 주장합니다. 이 수치들은 각자 다른 프롬프트, 모델, 평가 규약을 씁니다. DoVer가 Who&When AAO 단계 정확도를 GPT-4o에서 6.04%(재현)에서 +Step Index 프롬프트로 20.69%까지 올린 것에서 보듯, **프롬프트 형식만으로 몇 배가 바뀝니다**(`03` §6).
2. **라벨 비판**: DoVer(라벨 불확실성), Auditing(표면 단서), CatchBench(지름길)가 모두 "라벨이 무엇을 재는가"를 묻습니다. 우리 `03` §4의 단순 규칙 기준선(마지막 발화자 60.3%)과 같은 방향입니다.
3. **라벨 생성 방식의 이동**: 사람 판단(Who&When)에서 반사실 재실행(AgenTracer), 재생 후 결함 주입(Who&When Pro)으로 옮겨 갑니다.
4. DoVer의 표 5 "Random" 행은 Who&When 표 1의 값을 그대로 옮겨 **같은 자리 바뀜(12.00과 19.06)을 이어받았습니다.** 이 오류가 후속 연구에 전파되는 사례입니다.

## 3. DoVer가 보고한 Who&When 라벨 불확실성

DoVer(원문 §3, 부록 A)는 Who&When 손수 만든 부분집합의 GAIA 29건을 독립 재검토했다고 합니다. 14건(48%)에서 정답 라벨이 불확실하며, 9건은 한 세션 안에 여러 번의 시도가 있어 단일 단계 귀인이 본질적으로 모호하다고 적습니다. 불확실한 14건의 GPT-4o 단계 정확도는 24%, 나머지 15건은 44%였고(GPT-5는 7%와 53%), 이 분해는 표본이 14건과 15건이므로 가볍게 읽어야 합니다. 우리는 이 재검토를 재현하지 않았습니다.

## 4. AgenTracer와의 관계 (이 저장소 3번, `agentracer/analysis/03_analysis.md`와 대조)

- **부분집합 크기 확인.** AgenTracer 분석(`agentracer/analysis/03` §5)은 Who&When 두 부분집합 크기를 알 수 없어 N=58, 126을 추정했습니다. 이 폴더의 공개 데이터 집계로 **손수 만든 58, 알고리즘 생성 126이 맞음**을 확인했습니다(`03` §1). 그쪽 Fisher 검정의 분모 가정은 유지됩니다. 또 AgenTracer 표 1의 손수 만든 열 일부 셀(33/58=56.90, 40/58≈69.10, 12/58=20.69)이 58로 나뉘는 것도 맞습니다.
- **기준선 수치 대조.** AgenTracer 표 1은 Who&When 원 논문의 GPT-4o 행이나 Random 행을 싣지 않고, 새 모델(Claude, R1, GPT-4.1, Gemini 등)을 같은 설정으로 다시 돌린 값만 있어서 두 표를 셀 대 셀로 맞출 수는 없습니다. 같은 규모인지만 볼 수 있습니다. AgenTracer 기준선의 손수 만든 에이전트 수준 42–57%는 Who&When GPT-4o AAO 55.2%와 같은 범위이고, 손수 만든 단계 수준 1.7–17%, 알고리즘 생성 단계 수준 4–41%는 Who&When 원 논문의 SBS·BS 범위(7–26%)보다 넓습니다. 새 모델이 좋아진 것인지, 평가 규약이 다른 것인지는 AgenTracer 저장소에 평가 코드가 없어 가릴 수 없습니다.
- **단순 규칙 기준선과의 비교(우리가 새로 계산).** AgenTracer-8B(w/ G)가 단순 규칙을 이기는지: 손수 만든 에이전트 수준 69.1% 대 마지막 발화자 60.3%(Fisher p = 0.44), 대 WebSurfer 상수 56.9%(p = 0.25); 손수 만든 단계 수준 20.7% 대 항상 마지막 단계 12.1%(p = 0.32). **유의하지 않습니다.** 알고리즘 생성 단계 수준 42.9% 대 항상 0단계 15.9%(p < 0.001)와 에이전트 수준 69.6% 대 첫 발화자 49.2%(p = 0.001)는 **유의합니다**(`03` §9).
- AgenTracer의 "Who&When 최대 18.18%" 주장은 이 논문이 아니라 AgenTracer 쪽 수치이며, 그쪽 분석에서 재현되지 않았습니다. 이 폴더에서는 그 수치를 검증하지 않았고, 기준선 분모만 확인했습니다.

## 5. MAST와의 관계 (이 저장소 8번, `mast/`)

MAST(Why Do Multi-Agent LLM Systems Fail?, arXiv:2503.13657)는 실패 **유형**(14종 모드)을 분류하고, Who&When는 실패의 **위치**(에이전트와 단계)를 찾습니다. 두 문제를 합치면 "어디서(위치) 무엇이(유형) 틀렸나"가 됩니다. `mast/`는 다른 작업이 진행 중이어서 읽지 않았고 폴더 링크만 둡니다: [`../mast/`](../mast/). Who&When의 라벨은 위치와 자연어 이유뿐이고 유형 라벨이 없다는 점이 두 분류를 잇는 빈칸입니다.
