## 1. 문제와 주장

- **문제.** MLLM 연구는 LLM을 키우는 데 쏠려 있고 비전 쪽 설계(인코더, 연결기, 데이터, 학습 레시피, 평가)는 시각 표현 학습 연구와 떨어져 충분히 탐색되지 않았다. 언어에 기대는 지름길이 시각 표현의 약점을 가리고, 기존 벤치마크는 시각 근거화를 제대로 재지 못한다(초록, §1).
- **다섯 기둥** (그림 1, §1): 시각 표현(§3.4), 연결기 설계(§4), 지시 튜닝 데이터(§5), 지시 튜닝 레시피(§3.3), 벤치마킹(§3.1, 3.2).
- **번호 매긴 발견 8개** (본문):
  1. 대부분의 벤치마크는 비전 중심 능력을 제대로 재지 못하고, 재는 것은 문항이 적다 (§3.1).
  2. 기존 비전 벤치마크를 VQA로 바꿔 쓸 수 있다 (§3.2).
  3. 2단계 학습이 유익하고 어댑터 데이터가 많을수록 낫다 (§3.3, 그림 5).
  4. 시각 인코더를 푸는 것이 대체로 유익하다(언어 지도 모델은 항상, 자기지도는 비전 중심에서 특히) (§3.3, 그림 5).
  5. 고해상도 인코더가 차트와 비전 중심 벤치마크를 크게 올리고 ConvNet이 이에 적합하다 (§3.4, 그림 6).
  6. 언어 지도의 이점은 크지만 자기지도도 데이터와 튜닝이 충분하면 격차를 줄일 수 있다 (§3.4, 그림 7).
  7. 자기지도 포함 여러 인코더를 결합하면 성능이 오르고 특히 비전 중심에서 그렇다 (§3.5, 표 3).
  8. 공간 귀납 편향과 LLM 층 안에서의 깊은 상호작용이 시각 특징을 더 잘 모으고 압축한다 (§4, 표 4–6).
- **결과 주장** (§6, 표 9): Cambrian-1(8B, 13B, 34B)은 시각 토큰 576개로 LLaVA-NeXT, Mini-Gemini-HD(2,880개)보다 OCR·차트, 비전 중심에서 앞서고 일부 독점 모델(GPT-4V, Gemini-1.0 Pro, MM-1)과 비슷하다.

## 2. 방법

### 2.1 평가 프로토콜: MLLM을 시각 표현 평가기로 (§3, 부록 D, F)

- **고정 조건:** LLM Vicuna-1.5-7B, 시각 인코더 23종(표 10; 언어 지도 9, 자기지도 7, 기타 7: SAM 2, MiDaS 2, SD2.1, 지도 ViT 2), 2단계 학습(어댑터 데이터 1.2M ShareGPT4V-PT로 연결기만 학습 → 737K 지시 튜닝 데이터로 연결기와 LLM 학습), 시각 인코더 동결(비교 가능한 가장 넓은 모델 범위를 위해, §3.4). 연결기는 MLP 투영기. 하이퍼파라미터(표 23): 어댑터 lr 1e-3, 지시 튜닝 lr 2e-5, 배치 512, 미동결 실험의 시각 lr 1e-5.
- **737K 혼합:** LLaVA-665K에 AI2D 15,501, DocVQA 14,999, DVQA 13,000개를 더한 것(부록 E.5). 5M 혼합은 Cambrian-10M에 단일 출처 상한 t=150k를 적용한 것(부록 E.5).
- **벤치마크 16개 열**(표 3, 12–16): General(MME-P, MMBench, SEED-I, GQA), Knowledge(ScienceQA-IMG, MMMU, MathVista, AI2D), OCR & Chart(ChartQA, OCRBench, TextVQA, DocVQA), Vision-Centric(MMVP, RealWorldQA, CV-Bench 2D, CV-Bench 3D). "Average"는 16개 열의 단순 평균이며 MME-P는 20으로 나눕니다(각주 6, 우리 검산에서 전 표 일치, `03` §0). CV-Bench가 두 열이라 비전 중심에서 두 번 센다.
- **시각 입력 유무 비교 (§3.1, 그림 3 왼쪽):** 같은 23개 MLLM을 이미지를 넣었을 때와 뺐을 때, 그리고 문항 형식에서 계산한 우연 수준과 비교한다. 벤치마크는 "이미지 있음-없음" 평균 차이로 정렬한다. 군집(그림 3 오른쪽)은 벤치마크 점수에 PCA를 해 General, Knowledge, OCR & Chart, Vision-Centric 네 묶음으로 라벨링했다(MMMU는 문항 성격에 따라 Knowledge에 배정, 부록 B). 상관행렬은 그림 15.

### 2.2 CV-Bench (§3.2, 부록 C, 표 1, 그림 4, 16)

- **구성:** ADE20K·COCO 2D 과제(Spatial Relationship 650, Object Count 788)와 Omni3D 3D 과제(Depth Order 600, Relative Distance 600), 합계 2,638문항. 정답은 원 데이터셋 주석에서 프로그램으로 만들고 사람이 accepted/modified/rejected로 거릅니다(수정·기각 문항 수는 보고하지 않음, `03` §5).
- **질문 생성:** 두 객체 범주가 있는 이미지에서 경계 상자(시각적 프롬프트)로 대상을 지정. Counting은 정답에 가까운 선택지("2, 3, 4, 5, 6")와 존재 확인(정답 0)을 만든다. 깊이 순서는 한 객체의 가장 먼 꼭짓점이 다른 객체의 가장 가까운 꼭짓점보다 일정 오프셋 이상 가까울 때만 "더 가깝다"고 정의한다.
- **지표:** 정확도 = ½ × ((ADE20K + COCO)/2 + Omni3D) (부록 C, HF README).
- **크기 주장:** RealWorldQA의 3.5배, MMVP의 8.8배.

### 2.3 인코더 결합과 SVA (§3.5, §4, 그림 8, 식 (1), 부록 D.3, F)

- **단순 결합(§3.5):** 인코더 출력을 576토큰으로 보간하고 특징 차원으로 이어 붙임(A-MoF, [127] 방식).
- **SVA:** C차원 학습 가능 잠재 토큰 x를 L×L 격자로 반복해 질의 X ∈ R^{L²×C}를 만들고, N개 인코더의 특징 F_k(해상도 m_k L × m_k L × C, m_k 양의 정수)를 키와 값으로 쓴다. 질의 (i, j)는 모든 인코더 특징 맵의 부분 영역 F_k[m_k·i : m_k·(i+1), m_k·j : m_k·(j+1)]만 본다(공간 귀납 편향). 갱신된 질의는 식 (1):
  q*_{i,j} = softmax( q_{i,j} · [k_{i,j,1}, …, k_{i,j,N}]^T / √C ) [v_{i,j,1}, …, v_{i,j,N}],
  q = W^Q x, k_{i,j,k} = W_k^K F_k[부분 영역], v_{i,j,k} = W_k^V F_k[부분 영역], W^Q, W_k^K, W_k^V ∈ R^{C×C}. 하나의 토큰이 Σ_k m_k²개의 특징을 모은다(토큰 수 축소).
- **다층 집계:** 교차 어텐션을 LLM 층 사이에 여러 번 끼워 넣는다(그림 8 오른쪽). 하이퍼파라미터: D(교차 어텐션 층 수), G(독립 질의 그룹 수, 병렬 집계 후 이어 붙임). LLM 안의 층은 D=G=1.
- **부록 F 세부:** m_k>1일 때 학습 가능한 m_k×m_k 위치 인코딩, 질의에 전역 풀링 특징을 이어 붙임, ConvNeXt는 4개 stage 특징을 96×96으로 보간해 채널 방향으로 연결(m=4, L=24), 나머지 인코더는 576×576(m=1)으로 보간. 실험은 D=3, G=1, LLM 층 사이 stride 3. 최종 모델의 stride는 8B/13B/34B에서 3/4/9.
- **최종 구성(§6, 부록 F, 표 23):** 인코더 4개(OpenAI CLIP ViT-L/14@336, SigLIP ViT-SO400M/14@384, OpenCLIP ConvNeXt-XXL@1024, DINOv2 ViT-L/14@518), SVA, 어댑터 2.5M(ShareGPT4V 1.2M + MiniGemini 1.2M), 지시 튜닝은 Cambrian-7M, 시각 토큰 576개. LLM: Llama-3-Instruct-8B, Vicuna-1.5-13B, Hermes-2-Yi-34B.

### 2.4 데이터 (§5, 부록 E)

- **Cambrian-10M:** 약 9,784K 문항. 범주 비율은 OCR 27.6%, General 33.3%, Language 23.8%, Counting 8.5%, Math 3.2%, Science 2.9%, Code 0.8%(그림 9). 과학 데이터 부족은 데이터 엔진(Wikipedia 주제 → 이미지·캡션 → LLM으로 Q&A)으로 161K를 만들어 메웁니다(§5.1, 부록 E.3).
- **큐레이션:** 출처별 상한 t를 150k/250k/350k/450k로 바꿔 보고 250k–350k를 고른 뒤(표 7, "elbow") 범주 비율 실험 5개(고정 1.35M, 그림 11, 표 20)에서 exp-5를 골라 Cambrian-7M을 만든다(표 8).
- **시스템 프롬프트:** 짧은 답만 하는 "answer machine phenomenon"을 줄이려고 학습 데이터에 형식 지정 프롬프트를 붙임(§5.3, 표 18).

## 4. 한계 (논문 §7, 우리 관찰)

논문이 드는 것: (1) any-resolution 전략을 쓰지 않아 V*Bench 같은 초고해상도 과제에 약함, (2) 지도 미세조정만 다루고 강화학습 기반 후속 정렬은 미탐색, (3) 데이터 큐레이션이 초기 단계, (4) 벤치마크 점수만으로는 대화 능력·창의성·신뢰성을 못 잼("answer machine" 경고).

우리가 추가로 본 것 (자세히는 `03`, `04`):

1. **모든 비교가 학습 한 번의 결과입니다.** 시드·분산이 없고, 분석 표의 범주 평균 차이 일부는 단일 벤치마크의 표본 오차만으로도 설명됩니다 (`03` §4, §6, §7).
2. **그림 3의 결론은 23개 모델의 평균입니다.** 모델별 이미지 없음 점수가 공개되지 않아 단일 모델에 대한 결론은 아닙니다. 평균은 SAM·MoCo처럼 이미지를 거의 못 쓰는 인코더를 포함합니다 (`03` §1).
3. **MME의 우연 수준(50)은 쓰인 점수 정의와 맞지 않고(37.5), MMVP의 이미지 없음 0점은 쌍 지표의 필연입니다.** 두 막대의 "우연보다 나쁨"은 해석에 쓰기 어렵습니다 (`03` §1.3).
4. **군집 라벨 넷 중 General과 OCR & Chart만 상관행렬에서 안정적이고, Knowledge는 군집이 아닙니다** (`03` §2).
5. **인코더 결합(발견 7)은 ConvNeXt 추가에서만 뚜렷하고 DINOv2 추가 효과는 표 3의 통제 비교에서 평균 -0.01입니다** (`03` §4).
6. **표 24의 13B 행이 8B 행의 복사로 보입니다.** 10칸 중 9칸이 같고 표 9의 13B와 맞지 않습니다. v1부터 있었습니다 (`03` §9).

8. **공식 코드가 논문과 다른 설정을 씁니다.** DINOv2 giant@378(논문 ViT-L@518), in-LLM 교차 어텐션 stride 7(34B, 논문 9), 학습률, 퍼지 매칭 구현 등 (`04`).
