## 1. 풀려는 문제

에이전트 벤치마크는 과제 환경, 도구, 비정형 출력(코드·텍스트·환경 상태)을 채점기로 판정합니다. 그래서 점수가 능력을 재는지 채점기 허점을 재는지 알기 어렵습니다. 논문은 타당성을 두 조건으로 나눕니다(그림 1, §3).

| 조건 | 정의 | 위반 예 |
|---|---|---|
| 과제 타당성 (task validity) | 과제를 풀 수 있는 것과 목표 능력을 가진 것이 동치 | τ-bench에서 아무것도 안 하는 에이전트가 풀 수 없는 과제를 "성공"으로 통과 |
| 결과 타당성 (outcome validity) | 채점기가 성공이라 하는 것과 실제 성공이 동치 | SWE-bench Verified에서 틀린 패치가 약한 테스트를 통과 |

주장: 이 두 조건이 깨지면 성능이 "최대 100% 상대 오차"까지 과대·과소 추정됩니다(초록). 이 주장의 단위(상대 오차인지 절대 %p인지)는 곳마다 다릅니다(`03` §5).

## 2. 방법: ABC 점검표 (§4, 그림 2–4)

항목 수는 **43개**입니다(그림 기준 O 20 + T 10 + R 13). 위반 여부는 항목마다 1/0 점수입니다(§3 "Benchmark Assessment").

| 부분 | 항목 | 내용 |
|---|---|---|
| 과제 타당성 T.1–T.10 (그림 2) | 도구(T.1–3), 환경(T.4–6), 구현(T.7–10) | 도구 버전 명시, API 접근 보장, 상태 초기화, 정답 정보와 격리, 환경 고정, 정답 검증, 풀 수 있음 검증, 오라클 풀이기, 채점 우회 취약점 없음 |
| 결과 타당성 O.a–O.i (그림 3) | 20개. 채점 방식별로 묶음 | 문자열 일치(a, b), LLM 판정자(c), 단위·E2E 테스트(d, f), 퍼징(e), 상태 일치(g), 답 일치(h), 품질 척도(i) |
| 보고 R.1–R.13 (그림 4) | 투명성(R.1–6), 결함 완화(R.7–9), 해석(R.10–13) | 공개, 오염 방지, 갱신 계획, 구성 명시, 결함의 영향 정량화, 신뢰구간, 사람 기준선, **트리비얼 에이전트 결과(R.13)** |

항목 출처는 부록 C 표 4입니다(자체 경험, 기존 모범 사례, 이전에 보고된 문제, 해당 기법의 영역별 제안). 점검표 자체의 타당성(항목을 따르면 정말 평가가 나아지는가)을 재는 실험은 없습니다. CVE-Bench 사례 하나(§5.3)가 유일한 적용 예입니다.

## 3. 평가 대상과 결과

- **수집(부록 B):** 2024-01~2025-03에 주요 AI 업체가 쓴 벤치마크 78개 중 에이전트형 25개(표 2), 그중 17개를 표 3에 올렸고, 오픈소스이면서 능력·채점 방식을 고루 덮는 **10개**를 점검했습니다(표 1: SWE-bench, SWE-Lancer, KernelBench, BIRD, Cybench, MLE-bench, GAIA, τ-bench, WebArena, OSWorld).
- **점수(그림 5, 부록 D 표 5–14):** 항목당 1/0, 해당 항목 평균. 과제 타당성 위반 7개, 결과 타당성 위반 7개, 보고 한계 10개(전부). 80%는 결함 인정이 부족하다고 씁니다(§5.1).
- **새로 찾은 문제와 정량(§5.2, 부록 E):**

| 벤치마크 | 문제 | 보고 수치 | 위반 항목 |
|---|---|---|---|
| τ-bench | 풀 수 없는 과제는 DB가 안 바뀌면 성공이라 do-nothing이 통과 | 항공 38%, 소매 6.0% | O.b.3, O.g.3 |
| τ-bench | 정답이 DB 문구 그대로인 과제에 DB를 통째로 쏟는 에이전트가 통과 | 항공 40%, 소매 9.6% | O.b.2 |
| WebArena | 부분 문자열 일치가 군더더기를 허용, N/A 과제에서 LLM 판정자가 빈 응답을 통과 | 과대 1.4–5.2%, do-nothing 4.4% | O.b.2, O.c.2, T.10 (본문 §5.2는 O.c.1이라 적었으나 표 11은 O.c.1=1) |
| SWE-Lancer | 테스트가 든 zip의 디렉터리 목록·덮어쓰기에 비밀번호가 불필요 | 100% 점수 | T.5, T.10 |
| KernelBench | 퍼저가 값만 바꾸고 shape·메모리 배치는 안 바꿈 | 정답률 약 31% 과대 | O.e.1–3 |
| OSWorld | 웹사이트 변화로 chrome 과제 13/46의 HTML 선택자가 깨짐 | UI-TARS 28% 과소(chrome) | T.6 |
| SWE-bench Verified | 불충분한 테스트 (UTBoost 인용) | 과제의 5.2–5.3%, 해결률 2.3% 과대 | O.d.2 |

## 4. CVE-Bench 개선 사례 (§5.3, 그림 6)

점검표를 적용해 두 결함을 고쳤습니다. (a) 시간 기반 SQL 인젝션을 DB 로그에 SLEEP 문자열이 있는지로 판정해 아무 데나 SLEEP을 넣어도 통과(O.g.1): 과대 32.5%. (b) 외부 요청 서버가 같은 docker 네트워크에서 접근 가능해 지름길(논문 본문은 "T.9"로 적었지만 그림 2 번호로는 T.10): 성공률 10% 하락. 초록의 "33%"는 (a)의 32.5% 반올림이고 절대 %p라고 서론이 적습니다. 그림 6에는 막대 값 표기가 없어 숫자는 확인할 수 없습니다.

## 5. 부록 F: BIRD 보고 예와 신뢰구간 (표 15)

R.1–R.13 각각의 모범 문장 예를 BIRD로 보입니다. R.9의 식 (1)은 정답 질의의 오류율 e=11.65%(Arcwise 재주석의 500문항 표본 추정, 각주 4)를 반영한 정규 근사 구간이고, 표 15가 BIRD 61개 제출의 점추정, 구간, "가능한 순위"를 냅니다. 이 표의 계산은 `03` §6에서 재현했고 구간 방향에 문제가 있습니다.

## 6. 한계 (논문이 적은 것, 부록 A)

## 7. 내 눈에 보이는 한계 (우리 검증에서 나온 것, 근거는 03·04)

- 점검표는 **항목 번호가 문서마다 다릅니다.** 그림 3은 O.f.1·O.f.2, 부록 D 표는 O.f.2·O.f.3, 저장소 `ABC.md`는 I.f.2·I.f.3이며 `ABC.md`는 T.6(환경 고정)이 빠진 42항목입니다(`04` D1).
- 점수 분모가 **고정/가변이 섞여** 벤치마크끼리 비교가 어렵고, 해당 없음(도구·API 미사용)을 1점으로 셉니다(`03` §2).
- 결과 타당성 점수가 높은 벤치마크는 점검 항목 수가 적어서입니다(Cybench·MLE-bench·GAIA: 1–2항목).
- 표 15의 구간이 점추정을 포함하지 않는 행이 61개 중 44개입니다(`03` §6).
- 위반 사례의 정량 중 τ-bench 항공, WebArena N/A는 과제 정의에서 정수로 정확히 재현되지만, KernelBench 31%·WebArena 1.4–5.2%·CVE-Bench 32.5%는 공개 자료만으로 재계산할 수 없습니다(`03` §4, `04` D5–D7).
