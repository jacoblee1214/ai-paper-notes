## 1. 식 유도

기호: 한 행 w ∈ ℝ^{d_col}, 입력 X ∈ ℝ^{d_col×n}, H = 2XXᵀ. 한 행의 목적함수 L(w') = ‖(w'−w)X‖² = ½ δᵀHδ, δ = w'−w.

### 1.1 OBS 한 단계 (식 2의 δ)

w_q를 값 t로 고정(t = quant(w_q))하고 나머지 가중치를 L이 최소가 되게 움직이는 문제: min ½δᵀHδ s.t. e_qᵀδ = c, c = t − w_q.

- 라그랑주 L = ½δᵀHδ + λ(e_qᵀδ − c). 정상 조건 Hδ = −λe_q → δ = −λH⁻¹e_q.
- 제약에 대입: −λ[H⁻¹]_qq = c → λ = −c/[H⁻¹]_qq. 따라서 **δ = c·H⁻¹_{:,q}/[H⁻¹]_qq = −(w_q − quant(w_q))/[H⁻¹]_qq · H⁻¹_{:,q}** (식 2의 δ_F와 같음).
- 손실 증가량: ½δᵀHδ = ½c²·(e_qᵀH⁻¹HH⁻¹e_q)/[H⁻¹]²_qq = **½c²/[H⁻¹]_qq**. 그래서 OBQ가 고르는 q는 c²/[H⁻¹]_qq가 최소인 것(식 2의 argmin).
- 검산: `test_obs_update_is_exact_constrained_minimizer`가 같은 제약 문제를 최소제곱(lstsq)으로 직접 풀어 1e-9 이내로 일치함을 확인합니다.

### 1.2 식 (3): 한 가중치를 고정한 뒤의 H⁻¹

w_q를 고정하면 남은 문제의 Hessian은 H에서 q행·열을 지운 H_{−q}이고, 필요한 것은 그 역행렬입니다. H = [[A, b],[bᵀ, c]]의 블록 역행렬 공식(s = c − bᵀA⁻¹b)에서 (H⁻¹)_{qq} = 1/s, (H⁻¹)_{Aq} = −A⁻¹b/s, (H⁻¹)_{AA} = A⁻¹ + A⁻¹b bᵀA⁻¹/s 이므로 **A⁻¹ = (H⁻¹)_{AA} − (H⁻¹)_{Aq}(H⁻¹)_{qA}/(H⁻¹)_{qq}** 입니다. 이것이 식 (3)입니다(H⁻¹ 한 번만 구하고 이후는 rank-1 소거). `test_eq3_rank_one_update_equals_submatrix_inverse`가 1e-10 이내로 확인합니다. 식 (4), (5)는 q가 집합 Q일 때의 같은 유도(블록 크기 |Q|)입니다.

### 1.3 Step 1: 같은 순서면 H_F⁻¹이 모든 행에서 같다

H_F = 2X_FX_Fᵀ는 **가중치가 아니라 입력 X의 열 부분집합**에만 의존합니다. 모든 행이 같은 열 순서를 쓰면 단계 j마다 F_j = {j, …, d_col−1}이 행과 무관하므로 H_{F_j}⁻¹을 한 번만 갱신(식 3)하고 d_row개 행에 모두 적용합니다.

- OBQ: 행마다 (d_col 단계 × 식 3의 O(d_col²)) = O(d_col³) → 행 d_row개: **O(d_row·d_col³)**.
- GPTQ: 식 3은 열마다 한 번 O(d_col²)×d_col = O(d_col³), 가중치 갱신은 단계마다 (d_row × 남은 열) = O(d_row·d_col²) 합 → **O(d_row·d_col² + d_col³)**. 논문의 O(max{d_row·d_col², d_col³})와 같음.
- 측정(`layer_checks.py` F, d_row=4, float64, CPU): d_col=128에서 GPTQ 3.8 ms, 행별 식 3 탐욕 OBQ 63 ms, H_F를 매번 역행렬 계산하는 순차 OBQ 115 ms. d_col 16 → 128(8배)에서 GPTQ 5배, 순차 OBQ 46배 증가. 작은 크기라 점근 비교는 아님.

### 1.4 Step 3: Cholesky가 식 (3)의 반복과 같은 것

M = H⁻¹(양정치)에서 첫 변수를 소거하면 Schur 보수 M₂₂ − M₂₁M₁₂/M₁₁이고 이것은 식 (3)입니다. M = UᵀU(U 위삼각)의 Cholesky 첫 행은 [√M₁₁, M₁₂/√M₁₁]이고 나머지 블록은 같은 Schur 보수입니다. 따라서 **U의 j행(대각부터) = H_{F_j}⁻¹의 j행 / √[H_{F_j}⁻¹]_jj**, F_j = {j,…,d_col−1}. 이를 식 (2)에 넣으면 단계 j의 갱신은

δ = −(w_j − q_j)/[H_{F_j}⁻¹]_jj · (H_{F_j}⁻¹)_{j,:} = −e_j · U_{j,:}, e_j = (w_j − q_j)/U_jj

이고 이것이 **알고리즘 1의 E_{:,j−i} = (W_{:,j} − Q_{:,j})/[H⁻¹]_jj, W −= E·H⁻¹_{j,·}** 입니다. `test_cholesky_rows_are_scaled_inverse_rows`가 모든 j에서 1e-10 이내로 확인합니다. 효과: 식 (3)을 d_col번 반복 적용하며 쌓이는 수치 오차를 LAPACK Cholesky 한 번으로 대체합니다.

- 예측 손실: 단계 j의 손실 증가 = ½(w_j−q_j)²/U_jj² (1.1의 ½c²/[H⁻¹]_qq). 합계가 ½ΔW(H+λI)ΔWᵀ의 대각합과 같음을 `test_predicted_loss_equals_dampened_objective`가 1e-9 상대 오차로 확인합니다(공식 코드가 출력하는 `error`가 이 값).

### 1.5 Step 2: 지연 갱신은 순차와 같다

단계 j의 갱신은 j열 이후 모든 열에 대한 **선형** 연산(−e_j·U_{j,:})이고, j열의 반올림 결정은 j열 값에만 의존합니다. 블록 [i1, i2) 안에서는 블록 내부 열만 갱신하며 e_j를 모으고, 블록 밖 열에는 합 −E·U_{[i1,i2),[i2,:)}를 한 번에 적용하면 순차 갱신의 합과 같습니다. 결과는 블록 크기와 무관해야 하며 `test_block_size_does_not_change_result`(B = 1, 16, d_col)와 `test_gptq_equals_sequential_obq`(B = 1, 3, 5, 100)가 확인합니다.

### 1.6 dampening의 역할 (논문 4절 Step 3)

논문은 "λ = 평균 대각의 1%"를 수치 안정화로 설명합니다. 실제로는 두 가지 역할이 섞입니다: (a) H가 특이일 때 Cholesky를 가능하게 함, (b) 보정 표본이 부족할 때 능선(ridge) 정규화로 작용. 측정은 `03` §3.

## 3. 층 하나 실험 (`layer_checks.py`)

오차는 mean_n ‖(W − Ŵ)x_n‖²(식 1을 n으로 나눔), 시드·표본은 각 항목에 적었습니다.

### 3.1 합성 활성: RTN, 탐욕 OBQ, GPTQ (A)

상관이 있고 열 크기가 다른 합성 활성, 시드 10개, 부트스트랩 95% CI. RTN 오차 대비 비율(작을수록 좋음).

| 층 크기(d_row × d_col), 비트 | GPTQ / RTN | 탐욕 OBQ / RTN | GPTQ / 탐욕 OBQ |
|---|---|---|---|
| 16×32, 3 | 0.654 [0.599, 0.707] | 0.829 [0.787, 0.865] | 0.787 [0.741, 0.836] |
| 16×64, 3 | 0.626 [0.591, 0.658] | 0.827 [0.802, 0.851] | 0.757 [0.719, 0.793] |
| 16×64, 4 | 0.609 [0.572, 0.641] | 0.836 [0.806, 0.865] | 0.729 [0.688, 0.762] |

- GPTQ가 RTN보다 낮은 오차인 시드가 모든 설정에서 10/10입니다.
- **논문 4절 Step 1("탐욕 순서의 이점은 임의 순서 대비 작다")과 다른 방향의 결과:** 이 작은 합성 층에서는 우리 탐욕 OBQ(식 3, OBQ의 이상치 우선 반올림 같은 보조 휴리스틱은 넣지 않음)가 고정 순서 GPTQ보다 **더 나빴습니다**(비율 0.73–0.79). 해석: 탐욕은 오차가 작은 가중치를 먼저 반올림하고 큰 오차의 가중치가 마지막에 남아 보상할 자유 가중치가 적을 때 반올림됩니다(논문도 같은 메커니즘을 언급). 이 구현에는 OBQ 원 구현의 휴리스틱이 없고 층이 매우 작아(d_col ≤ 64) 이 결과가 "탐욕 순서는 소용없다"로 일반화되지는 않습니다. 논문 표 8(OPT-125M)에서도 GPTQ가 OBQ보다 낮았고(31.12 대 32.52, 3비트 53.85 대 69.32) 저자들은 OBQ 휴리스틱의 비전 모델 편향을 원인으로 추측합니다(5절).

### 3.2 dampening (B)

합성 활성, d_col = 96, 학습 표본 **n = 64 < d_col**(H가 특이), 시드 10개, 새 표본 2000개에서 held-out 오차. 3비트, B = 32.

| λ / mean diag | 학습 오차 | held-out 오차 | 비고 |
|---|---|---|---|
| 0 | - | - | **Cholesky 실패 10/10**(float32, float64 모두) |
| 1e-6 | 769 | 3758 | RTN의 3.0배 |
| 1e-3 | 426 | 2123 | |
| **1e-2** | 443 | 1613 | (논문 기본값) |
| 1e-1 | 588 | 1337 | |
| 1 | 824 | 1203 | RTN(1247)과 거의 같아짐 |
| RTN | - | 1247 | |

(float64 기준. float32도 같은 순서: λ=1e-2에서 held-out 1562, RTN 1223.)

- **λ = 0은 H가 특이하면 시작도 못 합니다.** λ가 작을수록 학습 오차는 낮지만 held-out은 크게 나빠집니다(과적합). 표본이 모자라는 이 합성 조건에서는 1%도 RTN보다 held-out이 나쁩니다.
- 이는 dampening이 **수치 안정화이자 정규화**임을 보여 줍니다. 논문은 안정화 역할만 설명합니다(4절).
- **언어 모델 설정에서는 영향이 없었습니다.** GPT-2 3비트 행별에서 λ = 1e-3 대 1e-2의 perplexity 차이는 −0.0002 nat(95% CI [−0.027, +0.021], p = 0.99, n = 150문서). 보정 토큰 수(64 × 512 = 32768)가 d_col(≤ 3072)보다 훨씬 많기 때문입니다.

### 3.3 act-order (C): **논문 알고리즘 1에는 없고 공식 저장소에 나중에 추가된 휴리스틱**

열을 diag(H) 내림차순으로 양자화(큰 활성 크기의 열을 먼저).

- 합성 활성(d_col 128, 시드 10개, RTN 대비 비율): 열 크기 편차 10^1에서 GPTQ 0.597 [0.578, 0.615] → act-order **0.352** [0.345, 0.360](10/10 시드). 편차 10^3에서 0.766 → 0.596.
- 실제 GPT-2 층(D, 아래): 상대 층 오차가 act-order로 48개 값 모두에서 줄었고(0.7–23%, 중앙값 5%). 예: 블록 0 mlp.c_proj 4비트 0.0113 → 0.0091.
- 모델 전체 perplexity는 §5.

### 3.4 GPT-2 실제 층: 보정 대 held-out (D)

GPT-2 small, 블록 0, 5, 11의 선형 4개, 4·3비트(행별, B = 128). 상대 오차 = mean‖ΔWx‖²/mean‖Wx‖². 보정 Hessian은 보정 문서 64개 × 512토큰, held-out은 서로 다른 문서 64개 × 512토큰. 전체 표는 `layer_checks_results.json`의 `D_real_gpt2_layers`.

| 층, 비트 | RTN (보정 / held-out) | GPTQ | GPTQ act-order |
|---|---|---|---|
| 블록 0 attn.c_proj, 4 | 0.0085 / 0.0085 | 0.0012 / 0.0015 | 0.0012 / 0.0014 |
| 블록 0 mlp.c_proj, 3 | 0.2554 / 0.2507 | 0.0429 / 0.0556 | 0.0359 / 0.0506 |
| 블록 5 mlp.c_fc, 4 | 0.0056 / 0.0056 | 0.0024 / 0.0027 | 0.0023 / 0.0026 |
| 블록 5 mlp.c_proj, 3 | 0.2920 / 0.2975 | 0.1248 / 0.1547 | 0.1134 / 0.1475 |
| 블록 11 mlp.c_proj, 3 | 0.1755 / 0.1715 | 0.0294 / 0.0422 | 0.0236 / 0.0387 |

- **24개 층·비트 조합 모두에서 GPTQ < RTN**이고(보정과 held-out 48개 값 모두), 오차는 RTN의 1.7–7.6분의 1입니다(블록 0 attn.c_proj 3비트 0.0401 → 0.0054).
- GPTQ는 보정 입력에서 오차를 줄이도록 최적화되므로 **held-out 오차가 보정 오차보다 크고**(예 블록 5 mlp.c_proj 3비트 0.125 → 0.155, 블록 11 0.029 → 0.042: 약 +24–44%), RTN은 두 입력에서 같습니다. 그래도 held-out에서도 RTN보다 훨씬 낮습니다.
- 층 오차가 가장 큰 곳은 `mlp.c_proj`(입력 3072차원, 활성 이상치)이고 이 층은 GPTQ의 이득도 큽니다.

### 3.5 그룹 격자 매개변수를 잡는 시점 (E)

공식 코드는 그룹 격자를 `W[:, i1+i : i1+i+g]`(전역 W, 블록 시작 시점 값)로 잡으므로 g < B이면 블록 안에서 이미 이루어진 보상 갱신이 빠진 값입니다(`04` D6). 이 구현의 기본은 "현재 갱신된 값", `stale_group_params=True`가 공식 방식입니다. GPT-2 층 3개, 3비트, B = 128:

- g = 128이면 두 방식이 **비트 단위로 같고**(g = B이면 블록 시작이 곧 그룹 시작), g = 32, 64에서 상대 오차 차이는 최대 1.0%(블록 11 mlp.c_proj g32: 0.00509 대 0.00504). 영향은 무시할 만합니다. `test_stale_group_params_differs_only_when_group_smaller_than_block`이 g < B에서만 달라지는 것을 확인합니다.

## 4. 모델 전체 측정 설정

- **모델:** GPT-2 small(124M, `openai-community/gpt2`, 학습된 절대 위치, 컨텍스트 1024), Pythia-160M(`EleutherAI/pythia-160m`, RoPE). 양자화 대상은 블록 안 선형 4개(GPT-2: c_attn, attn.c_proj, c_fc, mlp.c_proj / Pythia: query_key_value, dense, dense_h_to_4h, dense_4h_to_h)이고 임베딩, 위치 임베딩, LayerNorm, lm_head는 FP32로 둡니다(논문과 같음).
- **변형:** 논문 5절의 **블록 단위 순차**: 블록 i의 입력은 양자화된 앞 블록의 출력이고, 블록 안 4개 층의 Hessian은 FP 상태의 블록으로 한 번에 모은 뒤 4개를 양자화합니다. 블록 안 층 간 순차(true-sequential)는 쓰지 않았습니다(원 논문 방식). **모의(fake) 양자화**(가중치를 격자 값으로 바꿔 FP32 저장, 비트 패킹·커널 없음). 격자는 행별 비대칭 min-max(그룹이면 g = 128개 열마다 행별). 블록 B = 128, λ = 1%.
- **보정 데이터:** pile-10k(Pile 앞 1만 문서)를 시드 0으로 섞은 순서의 앞 5000개 문서에서 문서당 하나, 길이 **512**, **64개**(32768 토큰). 논문은 C4 2048토큰 128개(262144 토큰)이므로 보정량이 약 1/8입니다(시간 제한으로 줄임). 보정 시드는 기본 0, GPT-2 3비트와 4비트 행별은 시드 1, 2도 돌림.
- **평가 데이터:** 같은 섞은 순서의 뒤쪽 문서(보정과 겹치지 않음) 중 토큰 길이 ≥ 512인 문서 **150개**의 첫 512토큰. 위키텍스트가 아니라 **pile-10k held-out**이고 문서 앞 512토큰이므로, 논문 표의 숫자와 직접 비교하지 않습니다. GPT-2와 Pythia는 토크나이저와 문서 집합이 다르므로 서로의 절대 perplexity도 비교하지 않습니다.
- **통계:** perplexity의 95% CI는 문서 단위 부트스트랩 2000회(시드 0). 방법 비교는 같은 문서의 NLL 차이에 대한 부트스트랩 CI와 부호 뒤집기 검정(20000회, 시드 0), Holm 보정은 (모델별) GPTQ 대 RTN 8개 비교, GPTQ 대 FP 8개 비교, 변형 4개로 각각 한 가족. 분산 원천은 평가 문서 표집이고, 보정 시드의 영향은 GPT-2 시드 3개로 따로 봅니다.
- **자원:** CPU(8 스레드), 최대 RSS 3.5 GB(메모리 가드 4 GB 이내). 양자화 시간 GPT-2 26 s, Pythia-160M 21 s(64×512 보정, 블록 12개).

### 6.3 양자화 시간과 지연의 plausibility (4.2시간, 표 6)

**FLOPs 모델**(보정 N = 128 × 2048 토큰, 층마다 자기 입력으로 H를 따로 누적한다는 공식 코드 구조 가정): Hessian 누적 1.60 × 10¹⁷, 열 갱신 8.5 × 10¹⁵, Cholesky 등 1.2 × 10¹⁶ FLOPs. A100의 FP32 피크 19.5 TFLOPS(공개 사양, 기억에 의함; 공식 코드는 TF32를 끔)로 나누면 **2.57시간**이고, 보고된 4.2시간은 피크의 약 61% 효율에 해당합니다. 즉 4.2시간은 **하한(피크)을 만족하는 값**이고 비합리적이지 않습니다. 비용의 대부분은 H 누적(약 89%)이며, d_col³ 항이나 열 갱신이 아닙니다. 블록 통과 2회(FP16)는 별도.

- 표 2의 시간/파라미터: OPT 13B 1.61, 30B 1.50, 66B 1.45, 175B 1.44 분/10억 파라미터로 **거의 선형**입니다(점근적으로 d·파라미터 증가를 암시하는 d_col³ 항이 지배적이지 않음).

**지연과 메모리 대역폭**: 토큰마다 가중치를 한 번 읽는다고 보면 3비트 가중치 바이트(약 62 GiB)를 A100 71 ms에 읽는 유효 대역폭은 0.94 TB/s, A6000 130 ms에서 0.51 TB/s입니다. FP16(약 325 GiB)은 A100 230 ms에서 1.52 TB/s, A6000 589 ms에서 0.59 TB/s입니다(레이어를 GPU에 나눠 한 번에 한 GPU만 일하는 파이프라인). 순수 대역폭 한계의 속도비는 바이트 비 16/3 = 5.2배인데 실제는 3.24배(A100), 4.53배(A6000)입니다. A100은 사양상 약 2.0 TB/s, A6000은 0.77 TB/s이므로(기억에 의한 공개 사양) 3비트 커널은 A100에서 대역폭의 약 47%, A6000에서 약 67%를 씁니다. A100에서 이득이 작은 이유는 3비트 해제 연산이 상대적으로 크기 때문이라는 해석이 가능하지만 이 분석에서 직접 확인하지는 않았습니다.

### 6.4 24 GB 맥에서 들어가는 모델 크기

가정: 통합 메모리 24 GiB, GPU가 쓸 수 있는 한도는 **RAM의 2/3 = 16 GiB**(이 저장소의 24 GB 로컬 기기 양자화 사례 분석이 M4 Pro 24 GiB에 쓴 가정과 같음. macOS 설정에 따라 바뀜), 런타임·활성 1.5 GiB. 비트/가중치 = b + (16 + b)/g(g 없음이면 b). 임베딩 FP16 비중은 무시(큰 모델 기준).

| 형식 | 비트/가중치 | 16 GiB 한도, KV 0: 최대 파라미터 | KV 2 GiB 포함 |
|---|---|---|---|
| FP16 | 16 | 7.8 B | 6.7 B |
| 8비트 | 8 | 15.6 B | 13.4 B |
| 4비트 행별 | 4.0 | 31.1 B | 26.8 B |
| 4비트 g128 | 4.156 | 30.0 B | 25.8 B |
| 3비트 행별 | 3.0 | 41.5 B | 35.8 B |
| 3비트 g128 | 3.148 | 39.6 B | 34.1 B |
| 2비트 g128 | 2.14 | 58.2 B | 50.2 B |

- 한도를 3/4(18 GiB)로 보면 4비트 g128은 KV 2 GiB 포함 30.0 B, 24 GiB 전체를 쓰면(비현실) 42.4 B입니다(`paper_arithmetic_results.json`의 `mac_24GiB_max_params`).
- 모델 크기별 가중치 용량(GiB): 7B는 FP16 13.0 → 4비트 g128 3.4 → 3비트 g128 2.6, 13B는 24.2 → 6.3 → 4.8, 34B는 63.3 → 16.5 → 12.5, 70B는 130.4 → 33.9 → 25.7. 즉 **16 GiB 한도에서 4비트 g128은 약 30B급까지**(KV와 런타임 포함 25.8B), 70B는 2비트 g128(17.4 GiB)로도 한도를 넘습니다.
- 이 표는 **가중치만의 메모리 예산**입니다. 정확도가 4비트에서 얼마나 유지되는지는 모델마다 다릅니다(§5: GPT-2 +4–7%, Pythia-160M +26–44%). 큰 모델이 양자화에 더 강하다는 논문 관찰은 우리 소형 측정으로는 확인되지 않았고, 이 맥에서의 실제 속도(토큰/초)는 이 분석 범위 밖입니다(GPTQ 커널은 CUDA 전용, `04` D8).
- **소형 모델은 임베딩이 FP16로 남아 압축이 덜 됩니다.** GPT-2(임베딩 0.039 B / 124 M)에서 4비트 행별은 FP16의 48.8%(유효 7.8 비트/파라미터), Pythia-160M은 60.8%(9.7 비트)입니다.
