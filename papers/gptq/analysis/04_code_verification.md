## A. 논문 ↔ 코드 차이 D1–D11

| ID | 논문 | 코드 | 영향 | 우리 구현에서 |
|---|---|---|---|---|
| D1 | 알고리즘 1: 열 순서 고정, 블록 B = 128, `Cholesky(H⁻¹)ᵀ`, λ = 평균 대각의 1% | `gptq.py: fasterquant`가 `cholesky(H)` → `cholesky_inverse` → `cholesky(upper=True)`로 위삼각 인자를 얻고, 열마다 `err = (w−q)/d`, 블록 안 `W1[:, i:] −= err·Hinv1[i, i:]`, 블록 끝에 `W[:, i2:] −= Err1·Hinv[i1:i2, i2:]`. 기본 `blocksize=128`, `percdamp=.01` | **일치.** 알고리즘 1을 그대로 구현 | 같은 호출 순서. 순차 OBQ와의 일치를 pytest로 확인(`03` §2) |
| D2 | H = 2XXᵀ(식 2 위) | `add_batch`가 `H *= n/(n+tmp); H += 2/n·XXᵀ`(**시퀀스 수 n으로 나눈 이동 평균**) | 척도만 다름. λ가 평균 대각에 비례하고 반올림·갱신은 H의 상수배에 불변이라 결과는 같음. 단 예측 손실(`Losses`)의 절대값은 논문 식과 다름 | H = 2/n_tokens·XᵀX로 같은 성질 |
| D3 | 죽은 열 처리 언급 없음 | `dead = diag(H) == 0` → `H[dead, dead] = 1`, `W[:, dead] = 0` | 입력이 항상 0인 열의 가중치를 0으로 만듦. 논문의 알고리즘은 이 경우 H가 특이일 수 있음 | 같은 처리(`test_dead_columns_zeroed_and_finite`) |
| D4 | 격자는 "양자화 전에 고정"(3절) | `Quantizer.find_params`는 행별 min-max(0 포함, `sym=False` 기본)를 **원본 W**(죽은 열을 0으로 만들기 *전*)에서 잡음 | 죽은 열 값이 min/max에 들어갈 수 있음(미미). 논문 "행별 비대칭 min-max"와 일치 | 죽은 열을 0으로 만든 뒤 격자를 잡음(미미한 차이, 그 외 같은 격자) |
| D5 | 보정은 C4에서 무작위 2048토큰 128개, 과제 데이터는 보지 않음(5절 Setup) | `opt.py`의 위치 인자 `dataset`이 **보정 데이터**를 정함(`get_loaders(args.dataset, nsamples=128, seed=0)`), 평가는 그 뒤 `wikitext2`, `ptb`, `c4`를 모두 돌림. README의 예시 명령은 `c4`를 보정으로 씀 | 논문 표 3·4(Wiki2)는 C4 보정 + Wiki2 평가여야 하고, 같은 실행의 C4 평가는 **보정과 같은 분포**(표 11·12 각주가 인정). `wikitext2`를 첫 인자로 주면 Wiki2에서 보정하고 Wiki2에서 평가하게 되어 zero-shot이 아님 | 보정과 평가를 문서 단위로 분리 |
| D6 | 그룹 양자화: 격자는 "그 시점의 갱신된 가중치"(5절 Additional Tricks) | `fasterquant`는 `(i1+i) % groupsize == 0`에서 `find_params(W[:, (i1+i):(i1+i+groupsize)])`를 호출하는데 **W는 블록 시작 시점의 전역 행렬**(블록 안 갱신은 `W1`에만 있음) | g ≥ B(g = 128 = B)이면 동일. g < B이면 블록 안 앞 열들의 보상 갱신이 빠진 값으로 격자를 잡음. 우리 측정에서 층 오차 차이는 최대 1.0%(`03` §3.5) | 기본은 갱신된 값. `stale_group_params=True`가 코드 방식 |
| D7 | 알고리즘 1만 있음 | `--act-order`(diag(H) 내림차순 순열), `--static-groups`(격자를 미리 고정), `--true-sequential`(`llama.py`: 블록 안 층을 [k, v, q], [o], [up, gate], [down] 순서로 순차) | **논문 이후 추가된 휴리스틱**(README "Update July 2023"). README는 LLaMa-7B Wiki2가 7.15 → 6.09(act-order + true-sequential), OPT-66B 3비트가 14.16 → 9.95로 개선된다고 적음(우리 확인 아님). 논문 표에는 포함되지 않음 | act-order는 별도 옵션으로 측정(`03` §5.3), true-sequential은 미구현 |
| D8 | 표 6: 3비트 커널로 3.24×, 4.53× | `quant.py: Quant3Linear`와 `quant_cuda_kernel.cu`는 **3비트만**(4비트 커널 없음), 행별 `scales`·`zeros`(shape `(out, 1)`)만 받고 **그룹 격자는 표현 못 함**, `forward`는 `x.shape[-1] == x.numel()`, 즉 **토큰 한 개**만 지원(아니면 ValueError), 입력 크기 가정(1024×1024 블록 배수) | 속도(표 6)는 3비트·행별·배치 1에서만 해당. 4비트나 그룹 설정의 속도 주장은 이 저장소에 근거가 없음. 이 맥에서는 CUDA가 없어 실행 불가 | 모의 양자화만 |
| D9 | 표 5·7: 그룹 g128, g1024, 2비트 | `opt_pack3`/`--save`는 `quantizers[name]`의 `scale`·`zero`를 패킹하는데, 그룹 사용 시 `self.quantizer`는 층 안에서 **마지막 그룹의 격자로 덮어써짐**(`find_params`가 그룹마다 재호출) | 그룹 설정의 perplexity는 모의 양자화(가중치 덮어쓰기)로 평가한 것이고 `--save`로 저장한 그룹 체크포인트는 마지막 그룹의 격자만 담을 것으로 읽힘(정적 읽기에 의한 추정, 실행 안 함) | 해당 없음 |
| D10 | A.2.1: 검증 세트 전체를 이어 붙여 2048토큰 단위로 평가 | Wiki2·PTB는 전체를 `"\n\n"`로 이어 평가(일치). **C4는 검증 shard에서 길이 ≥ 2048인 문서를 무작위로 256개 골라 각각 2048토큰 구간을 이은 것**(`get_c4`) | C4 perplexity는 "전체 검증 세트"가 아님(256 구간). `--new-eval`이 PTB·C4 전처리를 바꾼 판(camera-ready용)이라 논문 표 9–12의 수치는 어느 판인지 표에 명시가 없음 | pile-10k 문서 150개 |

### 이후 문헌 (제목·초록 수준, 본문 미확인)

- **GPTQ가 실무 표준 형식이 됨:** AutoGPTQ(별 5066, 2025-04 아카이브), GPTQModel(별 1296, 2026-11-28 활발), llama.cpp는 별도 계열(`02` §3). 후속 방법(AWQ, QuIP/QuIP#, OmniQuant)은 GPTQ를 주요 비교 기준선으로 삼는다고 알려져 있으나(초록·제목 수준) 이 분석에서 표를 대조하지는 않았습니다.
- **QuIP(arXiv:2307.13304):** 초록은 incoherence 처리와 적응 반올림으로 2비트 양자화를 제안한다고 적음. GPTQ 계열의 층별 2차 보상과의 관계를 정리하는 분석을 포함하는 것으로 알려져 있음(본문 미확인).
