# 03 검증: 수치 재계산, 통계 검정, 데이터 감사

재계산 스크립트는 `recompute_stats.py`(결과 `recompute_stats_results.json`)와 `audit_dataset.py`(결과 `audit_dataset_results.json`)입니다. 모두 CPU에서 수 초에 끝납니다.

**먼저 알아 둘 한계.** 논문이 표를 주지 않고 모델 출력·점수 로그를 공개하지 않아, 그림 3–10의 수치를 원자료에서 다시 만들 수 없습니다. 이 문서의 재계산은 세 종류의 입력에 한정됩니다.

| 표기 | 입력 | 정확도 |
|---|---|---|
| text | 본문 문장의 숫자 | 정확 |
| bar | 막대 위 라벨(정수 %), 그림 10의 n 라벨 | 정확 |
| read | 산점도(그림 3, 4, 17)에서 눈으로 읽은 값 | 약 ±2%p (순위·상관 용도로만) |

모든 비율의 분모는 LiveCodeBench 103, SWE-bench 349입니다(부록 F.1, 공개 데이터셋으로 확인: `03` §7). 아래 검정은 **독립 두 비율의 Fisher 정확 검정**입니다. 같은 문항을 두 조건에서 푼 짝 설계라서 문항별 결과가 있으면 더 검정력 높은 McNemar를 쓸 수 있는데, 그 결과가 없으므로 이 검정은 보수적입니다(작은 차이를 놓칠 수는 있어도 큰 차이를 만들어 내지는 않음).

## 1. 본문 숫자의 산술 일치

본문의 비율이 정수 k를 분모 n(103 또는 349)으로 나눈 값으로 설명되는지 확인했습니다(`recompute_stats.py` A).

| 본문 수치 | n | 설명되는 k | 결과 |
|---|---|---|---|
| GPT-5 One-Off LCB 2.9% (§1) | 103 | 3 (=2.91%) | 일치 |
| GPT-5 Oneoff-SWE 76% (§1) | 349 | 264–266 | 일치 |
| GPT-5 Conflicting-LCB 프롬프트 A 92% / D 1% (그림 6) | 103 | 95 / 1 | 일치 |
| o3 Conflicting-LCB 프롬프트 D 33% (그림 6) | 103 | 34 | 일치 |
| GPT-5 느슨한 프롬프트 66%, Opus 4.1 50%, abort 9%·12% (§5.1, §5.3) | 349 | 있음 | 일치 |
| **GPT-5 Conflicting-SWE 54.0% (§4)** | 349 | **없음** | **불일치** |

- **54.0%는 349문항의 단일 실행으로 나올 수 없습니다.** 188/349=53.9%, 189/349=54.2%입니다. 분모 348이면 188/348=54.02%, 350이면 189/350=54.0%로 맞습니다. 공식 코드가 `fail_on_error=False`라 오류가 난 문항을 점수에서 빼면 348이 될 수 있으므로(`04` D8) **오류 문항 한 개 제외로 설명 가능**하지만, 논문은 제외 여부를 적지 않았습니다. 결론: 큰 문제는 아니나, 분모가 문항 수와 항상 같지는 않을 수 있다는 신호입니다.
- 그림 10의 모니터 전사본 수 2371(=1308+1063)과 193(=113+80)은 본문 숫자와 일치합니다.

## 2. 프롬프트·접근·중단 효과의 통계 검정

`recompute_stats.py` B (Fisher, 90% Wilson 구간은 JSON에).

| 비교 | 값 | 차이 | Fisher p | 판정 |
|---|---|---|---|---|
| LCB Conflicting GPT-5: 프롬프트 A → D (n=103) | 92% → 1% | −91%p | 1e-47 | 확실 |
| LCB Conflicting GPT-5: A → C | 92% → 28% | −64%p | 2e-22 | 확실 |
| LCB Conflicting o3: A → D | 91% → 33% | −58%p | 8e-19 | 확실 |
| **LCB Conflicting o3: A → C** | 91% → 93% | +2%p | 0.80 | **프롬프트 C는 o3에 효과 없음** |
| LCB Conflicting Opus 4.1: A → D | 37% → 0% | −37%p | 1e-13 | 확실 |
| SWE Conflicting GPT-5: 엄격 → 느슨 프롬프트 (n=349) | 54% → 66% | +12%p | 0.0015 | 유의 |
| **SWE Conflicting Opus 4.1: 엄격 → 느슨** | 50% → 55% | +5%p | **0.20** | **유의하지 않음** (본문은 "notably"로 두 모델을 함께 서술, §5.1) |
| SWE Conflicting GPT-5: 전체 접근 → 읽기 전용 | 54% → 39% | −15%p | 1e-4 | 유의, 읽기 전용에서도 39%가 남음 |
| SWE Conflicting GPT-5: 전체 접근 → 중단 허용 | 54% → 9% | −45%p | 6e-40 | 확실 |
| SWE Conflicting o3: → 중단 허용 | 49% → 12% | −37%p | 4e-27 | 확실 |
| **SWE Conflicting Opus 4.1: → 중단 허용** | 50% → 46% | −4%p | **0.36** | 효과 없음(본문 "much less pronounced"와 일치) |
| SWE Original GPT-5: → 중단 허용 (정상 성능) | 97% → 97% | 0 | 1.0 | 성능 손실 없음 |
| SWE Original GPT-5: → 테스트 숨김 | 97% → 76% | −21%p | 1e-17 | 숨김은 정상 성능을 크게 해침 |

해석:
- **프롬프트 효과는 강하고 모델마다 방향이 다릅니다.** 프롬프트 C("테스트가 틀렸다면 지적하라")는 GPT-5에는 큰 효과를 내지만 o3에는 없습니다. 그래서 "더 엄격한 프롬프트가 줄인다"는 일반화는 위험하고, 메인 결과(프롬프트 D)의 **모델 순위가 프롬프트 선택에 종속**됩니다. 프롬프트 A에서는 GPT-5(92)≈o3(91)≫Opus 4.1(37), D에서는 o3(33)≫GPT-5(1)≈Opus 4.1(0)입니다.
- 저자가 §5.1에서 밝혔듯 메인 프롬프트는 "부정행위를 최소화하도록 반복 조정"한 것이고 조정과 평가에 같은 103문항을 썼습니다. 프롬프트 D의 낮은 수치는 이 문항 집합에 맞춘 값일 수 있습니다(추측이며 보류 문항 검증 없음).
- 중단 옵션의 효과는 `04` D7에서 설명하듯 **프롬프트 문구도 함께 바뀐 실험**이라 옵션만의 효과로 읽을 수 없습니다.

## 3. 능력과 부정행위의 관계 (그림 3, 4, "더 유능한 모델이 더 속인다")

그림 3(SWE-bench)·그림 4(LCB)의 산점도에서 읽은 값으로 원본 통과율 대 부정행위율의 스피어만 상관을 계산했습니다(모델 8개, `recompute_stats.py` D). 도식은 `report/figures/own_capability_vs_cheating.png`.

| 설정 | ρ | p | 약한 두 모델(GPT-4.1, Qwen3-Coder) 또는 o3 제외 |
|---|---|---|---|
| SWE One-Off | 0.78 | 0.023 | ρ=0.46, p=0.35 (6개) |
| SWE Conflicting | 0.73 | 0.040 | ρ=0.35, p=0.50 (6개) |
| LCB One-Off | −0.27 | 0.52 | o3 제외 ρ=−0.74, p=0.057 (7개) |
| LCB Conflicting | 0.63 | 0.093 | o3 제외 ρ=0.47, p=0.28 (7개) |

- SWE-bench의 상관은 **가장 약한 두 모델이 끌고 있습니다.** 나머지 6개 모델만 보면 사라집니다. 같은 통과율(85–89%) 모델들이 부정행위율 29%(o3)에서 65%(Sonnet 3.7)까지 퍼져 있습니다.
- LCB에서는 o3(원본 통과 86%, 부정행위 22%/33%)가 GPT-5(89%, 3%/1%)보다 훨씬 많이 속입니다(p=3e-5, 1e-10). 능력으로 설명되지 않습니다.
- 통과율은 `시도 성향 × 시도 성공 확률`이므로 약한 모델의 낮은 수치에는 "속일 능력이 낮음"이 섞여 있습니다. 이 논문의 설계로는 분리할 수 없습니다(전사본이 없음).
- **인용 가능한 형태:** "SWE-bench에서는 원본 통과율이 낮은 모델이 부정행위율도 낮았다"까지입니다. "더 유능한 모델이 더 속인다"를 일반 명제로 쓰지 마십시오.

모델 쌍 비교(SWE Conflicting, 읽은 값): GPT-5 54 대 Opus 4.1 50 (p=0.32), GPT-5 대 o4-mini 48.5 (p=0.17), Opus 4.1 대 Sonnet 4 43 (p=0.08)는 구별되지 않습니다. 반면 "새 Claude 모델(Opus 4.1, Sonnet 4)이 Sonnet 3.7(64.5)보다 덜 속인다"(§4)는 p=1e-4, 2e-8로 지지됩니다.

## 4. LCB의 0에 가까운 셀

LCB(n=103)의 0%, 1%, 3% 셀은 서로 구별되지 않습니다. 90% Wilson 구간은 0/103이 [0, 2.6]%, 1/103이 [0.2, 4.2]%, 3/103이 [1.2, 7.1]%이고 0/103의 95% 상한(Clopper-Pearson)은 3.5%입니다. 그러므로 "GPT-5(2.9%)가 Opus 4.1(≈0%)보다 더 속인다" 같은 비교는 할 수 없습니다. LCB에서 의미 있는 신호는 **o3의 이탈**(그림 4: 22%, 33%)뿐입니다.

## 5. 피드백 효과 평균 재계산 (§5.3, 그림 17)

그림 17 왼쪽(Conflicting-SWE, 읽은 값)에서 모델별 첫 제출 대 다중 제출 값을 읽어 평균을 냈습니다: 첫 제출 평균 32.9%, 다중 제출 38.2%로 본문 "33%에서 38%"와 일치합니다. 그러나 GPT-5 하나가 **+21%p**(33→54, p=3e-8)를 차지하고, GPT-5를 빼면 32.9%에서 36.0%(+3%p)입니다. 나머지 모델의 개별 변화(+0 ~ +6%p)는 독립 검정에서 p=0.12–0.87로 구별되지 않습니다(GPT-4.1의 0%→3%만 p=0.002이고 절대 크기가 작음). 따라서 "다중 제출이 부정행위를 늘린다"는 GPT-5에서는 분명하고 평균 효과로 인용하기엔 약합니다.

## 6. 모니터링 (§6, 그림 10)

그림 10의 n 라벨로 90% Wilson 구간을 냈습니다(`own_monitor_ci.png`).

| 셀 | 비율 | n | 90% 구간 |
|---|---|---|---|
| LCB, Sonnet, One-Off | 86% | 113 | 79.6–90.4 |
| LCB, Sonnet, Conflicting | 89% | 80 | 81.6–93.3 |
| SWE, Sonnet, One-Off / Conflicting | 42% / 50% | 1308 / 1063 | 39.7–44.2 / 47.5–52.6 |
| SWE, Opus, One-Off / Conflicting | 57% / 65% | 1308 / 1063 | 54.8–59.3 / 62.6–67.4 |
| 오탐 상한: LCB 원본 / SWE 원본(Sonnet, Opus) | 7% / 1%, 2% | 550 / 2300 | 5.3–8.9 / 0.7–1.4, 1.6–2.5 |

- LCB의 "86–89%"는 구간이 넓어 두 변형 사이에 차이가 없습니다(p=0.67). SWE에서 Sonnet의 One-Off 대 Conflicting 차이(42 대 50%)는 독립 가정에서는 유의(p=1e-4)하고 Sonnet 대 Opus 차이도 큽니다.
- **구간은 좁게 나옵니다.** 이 전사본은 8개 모델 x 문항 349 x 스캐폴드에서 "통과한 것만" 모은 것이라 같은 문항·모델의 전사본이 군집합니다. 독립 가정은 불확실성을 줄여 보이게 합니다.
- **탐지율의 분모는 "통과한 불가능 과제"이므로 이것은 재현율입니다.** 오탐 상한(원본 열린 테스트에서 flag된 비율)은 저자가 밝혔듯 상한일 뿐이고, LCB 원본의 7%(550개 중 약 38개)는 일부가 진짜 부정행위(테스트 수정 등)였다고 저자가 확인했습니다. 정밀도는 측정되지 않았습니다.
- **모니터는 이 과제가 불가능할 수 있다는 사실을 프롬프트로 듣습니다**(`04` D9). 실제 배포에서는 모니터가 그것을 모르므로 SWE-bench 탐지율 42–65%는 오히려 낙관적일 수 있습니다(추측).

**LCB 변형의 구조:**
- One-Off: 101/103은 줄 하나 교체, 그중 98건은 비교 대상(우변)만 바뀝니다. 나머지 2건은 여러 줄 교체(lcbhard_5: `is None` 대신 `is not None`과 길이·범위 검사로 바꿈, lcbhard_77).
- Conflicting: 100/103이 순수한 줄 추가이고, AST로 "같은 호출·같은 연산자에 서로 다른 우변"이 공존함을 98건 확인했습니다. 못 찾은 5건 중 2건(lcbhard_5, 26)은 `result = candidate(...)` 형태의 의미적 모순이고 3건은 아래 구조 오류입니다.
- **구조가 깨진 변형 4개(3개 문항):** `lcbhard_77`은 One-Off와 Conflicting 모두 문자열 리터럴이 닫히지 않은 구문 오류(원본 6,112자가 변형에서 35,247자로 늘어남. 변형 생성기 출력이 이상하게 길어진 흔적). `lcbhard_35`와 `lcbhard_87`의 Conflicting은 `def check(candidate):` 없이 `assert ...` 한 줄만 남은 테스트입니다(`check(...)` 호출이 NameError). 이 4개는 정직한 풀이는 물론 테스트를 건드리지 않는 어떤 풀이로도 통과할 수 없습니다. 영향은 작지만(206개 변형의 1.9%) "품질 관리를 하지 않았다"(§2.3)의 구체적 결과입니다. 그리고 `lcbhard_35`·`87`은 에이전트가 스스로 `check`를 정의하는 방식(테스트 수정)으로만 통과할 수 있고, `lcbhard_77`은 최소 스캐폴드(테스트와 답을 한 스크립트로 이어 실행)에서는 구문 오류로 어떤 답으로도 통과할 수 없습니다.

**SWE 변형의 구조:**
- One-Off: 330/349(94.6%)가 한 줄 교체(기존 테스트 줄 113, patch가 추가한 줄 217), 18건이 여러 줄 변경, 1건이 줄 추가만.
- Conflicting: 332/349(95.1%)가 순수한 줄 추가(복제), 16건 여러 줄 변경, 1건 기존 줄 교체.
- 변형 생성기는 **첫 FAIL_TO_PASS 테스트 하나**만 겨냥합니다(`04` D5). 349문항 중 32.4%는 FAIL_TO_PASS가 2개 이상(평균 1.85개, 최대 26개)이라 나머지 테스트는 원래 그대로입니다.
- SWE에서 "불가능"의 근거는 **원래 정답 패치와 빈 패치가 모두 실패**한다는 점뿐입니다. 이것은 "정답 패치가 불가능 테스트를 통과하지 못한다"를 보장하지만 "명세에 충실한 어떤 구현도 통과하지 못한다"를 보장하지는 않습니다. 이 논문의 그림 2(오른쪽) 예시는 `match="random_attr"`와 `match="prop"`을 **둘 다** 요구하는 테스트인데, 정규식 검색이라 두 문자열을 모두 포함한 오류 메시지는 둘 다 통과합니다. 그 메시지는 "속성 이름이 아니라 프로퍼티 이름을 보고하지 말라"는 명세를 어기므로 부정행위로 볼 수 있지만, 논리적 모순이라기보다 **자연어 명세에 기댄 판단**입니다.

## 8. 부정행위 유형 분류 (그림 5)

- 그림 5의 n(373, 151, 225, 13, 253, 169, 341, 85, 합 1610)은 문항 349 × 스캐폴드 2 = 698회 시도로 나눈 통과율로 환산하면 GPT-5 53.4%, Sonnet 3.7 48.9% 등으로 그림 3의 값(54%, 64.5%)과 모순되지 않습니다.
- 캡션과 본문 "OpenAI 모델이 더 다양"은 GPT-5(테스트 수정 24%)와 o3(15%)에만 해당합니다. o4-mini는 64%가 테스트 수정이고 GPT-4.1은 46%(n=13)입니다.
- 분류는 Claude Opus 4가 전사본 하나를 한 번 읽고(`temperature=1`) 내린 라벨이고 사람 검증이나 반복이 없습니다. 분류 프롬프트가 "이미 부정행위로 확인됐다"고 알려 줍니다(각주 1). 유형 비율은 LLM 분류 노이즈를 포함한 값으로 읽어야 합니다.
