# 03. 재계산과 검정: AgenTracer

모든 수치는 `analysis/recompute_tables.py`(표 값을 옮겨 적은 뒤 계산)와 `analysis/data_*.py`(공개 데이터 릴리스 계산)로 다시 만들 수 있습니다. 결과는 `recompute_results.json`, `data_release_stats.json`, `data_release_steps.json`, `data_label_consistency.json`, `data_overlap_check.json`에 있습니다.

## 1. 표 셀이 k/N으로 나오는가

표 1과 표 2의 셀은 소수점 둘째 자리까지 쓰였습니다. 각 열이 하나의 분모 N에 대해 k/N으로 나오는지 확인했습니다. 셀당 허용 오차는 0.005%p입니다.

| 열 | 셀 수 | 모든 셀이 맞는 N(20–1000) | 셀이 가장 많이 맞는 N | 논문에 적힌 테스트 크기 | 해석 |
|---|---:|---|---|---|---|
| Who&When 수작업 agent | 18 | 없음 | 58(10/18) | — | 58에 가까우나 정확하지 않음 |
| Who&When 수작업 step | 18 | 없음 | 58(12/18) | — | 같음 |
| Who&When 자동 agent | 18 | 없음 | 126(10/18), 63 | — | 126에 가까움 |
| Who&When 자동 step | 18 | 없음 | 126(10/18) | — | 같음 |
| TracerTraj 코딩 agent | 18 | 없음 | **127**(9/18), 147은 1/18 | **147**(표 3) | 공개 릴리스 127과 맞음 |
| TracerTraj 코딩 step | 18 | 없음 | 127(8/18) | 147 | 같음 |
| TracerTraj 수학 agent | 18 | 없음 | 63(6/18) | 63 | 크기는 맞으나 셀이 완전히 맞지 않음 |
| TracerTraj 수학 step | 18 | 없음 | 63(8/18) | 63 | 같음 |
| TracerTraj 일반 agent | 18 | 없음 | 없음(최고 4/18, N=327) | **56**(표 3) | 56으로는 0/18. 공개 릴리스 600으로도 맞지 않음 |
| TracerTraj 일반 step | 18 | 없음 | 없음 | 56 | 같음 |

**결론.** 어느 열도 단일 분모로 설명되지 않습니다. 가능한 원인은 (a) 여러 시드나 실행의 평균, (b) 셀마다 다른 표본, (c) 수치 오기입니다. 논문은 어느 것인지 밝히지 않습니다.

표 3과 표 2가 어긋나는 곳은 두 가지입니다. 코딩 테스트는 표 3에서 147이지만 표 2의 코딩 열은 127에 맞고, 공개 릴리스의 코딩 테스트도 127입니다. 일반 에이전트 테스트는 표 3에서 56이지만 어떤 N에서도 맞지 않습니다.

## 3. 검정(Fisher 정확 검정, 양측)

분모는 1(추정 N)과 2배(민감도)로 계산했습니다. 셀 값이 k/N에 정확히 맞지 않으므로 검정은 근사치입니다.

| 비교 | 셀 차이 | p (N) | p (2N) | 판정 |
|---|---|---|---|---|
| 수작업 agent w/G: AgenTracer 대 Claude | +12.2 | 0.249 (58) | 0.077 (116) | 유의하지 않음 |
| 수작업 agent w/G: AgenTracer 대 Gemini | +17.38 | 0.087 (58) | 0.011 (116) | 표본에 따라 다름 |
| 수작업 agent w/oG: AgenTracer 대 Claude | +13.8 | 0.189 (58) | 0.046 (116) | 경계 |
| 수작업 step w/G: AgenTracer 대 Claude | +3.4 | 0.813 (58) | 0.616 (116) | 차이 없음 |
| 자동 step w/G: AgenTracer 대 Claude | +2.2 | 1.00 (63) | 0.798 (126) | 차이 없음 |
| 자동 step w/G: AgenTracer 대 R1 | +11.5 | 0.269 (63) | 0.067 (126) | 유의하지 않음 |
| 수학 step w/G: AgenTracer 대 Gemini | +25.4 | 0.007 (63) | <0.001 (126) | 유의 |
| 수학 step w/oG: AgenTracer 대 Claude | +11.6 | 0.285 (63) | 0.077 (126) | 유의하지 않음 |
| 일반 step w/G: AgenTracer 대 Qwen3-8B | +22.7 | 0.015 (56) | <0.001 (112) | 유의 |
| 일반 step w/G: AgenTracer 대 Claude | +5.8 | 0.688 (56) | 0.396 (112) | 유의하지 않음 |
| 코딩 agent w/G: AgenTracer 대 Coder | +3.7 | 0.579 (127) | 0.434 (254) | 유의하지 않음 |

**해석.** 이 논문이 가장 강하게 주장하는 "작은 모델이 큰 상용 모델을 이긴다"(수작업 Who&When)는 표본이 작아 통계적으로 확인되지 않습니다. 사례 대부분에서 AgenTracer의 우위는 기준선 대비 차이가 몇 %p이고 p > 0.05입니다. 수학과 백본 대비 큰 차이는 유의합니다. 단일 실행이고 시드 분산이 없으므로, 이 검정은 "잡음 한계를 넘는가"의 하한 확인입니다.

## 4. 공개 데이터 릴리스 계산 (v1.0.0, 논문 버전과 다름)

릴리스 README는 논문 버전과 "정확히 같지 않고 추가 샘플이 있다"고 적습니다. 그래도 구조와 누수를 볼 수는 있습니다.

| 영역 | 학습 행 | 테스트 행 | 특이점 |
|---|---:|---:|---|
| 일반 에이전트 | 1,500 | 600 | 모든 행의 주체 라벨이 `assistant`(1종). 에이전트 수준 평가 불가. 단계 번호는 history의 `step` 필드와 모두 맞음 |
| 코딩 | 1,141 | 127 | 주체 라벨 5종. 정답 단계의 `name`과 `mistake_agent`가 **127/127, 1141/1141 일치** |
| 수학 | 567 | 63 | 질문 470종(한 질문에 최대 2행). 테스트 63행 중 **21행(33%)이 학습과 질문 문장이 같음**. 그중 5행은 학습 사본과 정답 단계가 같음 |

- 수학 누수는 논문 9:1 분할이 궤적 단위였다면 생길 수 있는 문제입니다. 논문은 분할 방식을 적지 않았습니다(§5.1).
- 수학 테스트 크기 63은 논문 표 3과 같습니다. 코딩 테스트 127은 표 2의 코딩 열과 맞고, 표 3의 147과 다릅니다.
- 실행 스크립트: `analysis/data_release_stats.py`, `analysis/data_release_steps.py`, `analysis/data_label_consistency.py`, `analysis/data_overlap_check.py`.

## 5. 한계와 확인되지 않은 것

- 표 셀의 분모를 확정하지 못했습니다. 논문 표 작성자가 어떤 N을 썼는지 모릅니다.
- Who&When의 두 부분집합 크기(수작업, 자동)는 논문에 없습니다. arXiv 초록은 전체 127편만 말합니다. 그래서 검정은 추정 N을 씁니다.
- 학습 실행 반복이 없어서 분산을 알 수 없습니다.
- 재현(학습, 모델 실행)은 하지 않았습니다. 가중치가 공개되지 않아 재현은 불가능하고, 데이터로 할 수 있는 것은 위 계산까지입니다.
