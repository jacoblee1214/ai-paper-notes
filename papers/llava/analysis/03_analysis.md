# 03. 분석: 식·산술 검산, 최소 구현, 공식 코드 대조, LLaVA-Bench 통계

구현 모드입니다. 학습·평가를 재현하지 않았고(8×A100과 GPT-4 판정이 필요), 대신 (1) 식과 산술 검산(`analysis/derivation_checks.py`), (2) 직접 짠 PyTorch 최소 구현과 pytest(`analysis/minimal_impl.py`, `analysis/test_minimal_impl.py`), (3) 합성 장면 토이 실험(`analysis/run_experiments.py`), (4) 공식 코드 `haotian-liu/LLaVA`(커밋 `c121f04`)의 정적 대조, (5) 공개된 평가 자료(문항 수, 판정 코드, Vicuna-80 판정 4세트)로 한 통계 점검(`analysis/bench_stats.py`)을 했습니다. **토이는 논문 재현이 아닙니다.** 코드 실행, 설치, 가중치·데이터셋 다운로드(질문 파일 8 KB 두 개 제외), API 호출은 하지 않았습니다.

## 1. 시각 토큰, 투영기, 비전 타워의 크기 (식 1)

식 1의 H_v = W · Z_v에서 Z_v는 ViT-L/14의 격자 특징입니다. 모든 값은 `derivation_results.json`입니다.

| 항목 | 값 | 계산 |
|---|---|---|
| 시각 토큰 수, 224px | **256** (CLS를 세면 257) | (224/14)² . 공식 코드는 `image_features[:, 1:]`로 CLS를 뗍니다 |
| 시각 토큰 수, 336px (LLaVA-1.5) | **576** | (336/14)² |
| AnyRes 최대(LLaVA-NeXT 기준 5타일) | 2,880 | 5 × 576 |
| 선형 투영 W, Vicuna-7B (d=4096) | **4,198,400** | 1024 x 4096 + 4096 |
| 선형 투영 W, Vicuna-13B (d=5120) | 5,248,000 | 1024 x 5120 + 5120 |
| 2층 MLP, 7B | **20,979,712** | + 4096 x 4096 + 4096 |
| 2층 MLP, 13B | 31,467,520 | |
| Vicuna(Llama) 7B / 13B 파라미터 | 6,738,415,616 / 13,015,864,320 | 4h² + 3h·ffn + 2h를 층 수만큼, 임베딩과 lm_head 비공유 |
| 투영기 / LM 파라미터 비 | 선형 7B 0.062%, MLP 7B 0.311%, 선형 13B 0.040%, MLP 13B 0.242% | |

| 비전 타워 / 7B LM 비 | 4.5% | |

- 1단계에서 학습되는 것은 4.2M(선형) 또는 21.0M(MLP) 파라미터로 7B LM의 0.06–0.31%입니다. 논문이 "lightweight하다"(§4.1)고 한 말은 산술로 맞습니다. 이 작은 모듈이 시각 특징을 LM의 임베딩 공간으로 옮기는 전부를 맡습니다.
- 선형 → MLP는 파라미터가 5배(4.2M → 21.0M)이지만 LM 대비 여전히 0.3%라, LLaVA-1.5의 "MLP가 낫다"(표 2 행 3)는 용량보다 비선형성의 문제로 읽을 수 있습니다(추측, 시험하지 않음; 토이 §6.2가 이 질문의 축소판).
- 비전 타워 식은 HF `CLIPVisionModel`(합성곱 편향 없음, 사전 LN, 사후 LN, q·k·v·out 편향)을 따릅니다. 이 식이 맞다는 것은 구조 일치의 검증이고, CLIP 가중치의 총량(`clip/`)과의 대조는 하지 않았습니다.

## 3. 학습 계산량의 일관성 점검 (부록 C)

부록 C는 8×A100에서 1단계 4시간, 2단계 10시간이라고 씁니다. 가정이 많아 **검증이 아니라 일관성 점검**입니다.

- 1단계(13B, 595K쌍, 256 시각 토큰 + 캡션 20토큰이라고 가정 → 1.64억 토큰): LM이 동결이라 가중치 기울기가 없고 활성 기울기만 필요하므로 4N/토큰이면 **8.5e18 FLOPs**입니다. A100 bf16 피크 312 TFLOPs × 8 × 4시간 대비 **MFU 23.8%**(체크포인팅의 6N을 쓰면 35.7%). 둘 다 현실적인 범위입니다. 캡션 길이는 논문에 없어 가정입니다.
- 2단계(13B, 158K × 3에폭 = 47.4만 샘플, 전체 미세조정과 체크포인팅의 8N/토큰): 10시간이 MFU 25–45%에 해당하려면 샘플당 평균 **455–819토큰**이 필요합니다. 시각 256토큰을 빼면 텍스트 200–560토큰이라 GPT-4가 만든 긴 답(상세 설명·복잡 추론)이 있는 데이터로 그럴듯합니다(평균 길이는 데이터를 받지 않아 확인하지 않음).
- 결론: 보고된 학습 시간은 13B, 8×A100, 위 가정에서 계산량과 모순되지 않습니다. 반대로 LLaVA-1.5의 336px(576토큰)에서 보고된 "약 6시간 + 약 20시간"(LLaVA-1.5 §3.3)은 토큰이 2.25배인 것과 방향이 맞습니다(2배 정도라고 서술).

## 4. 층 선택: "끝에서 두 번째 층"이 정확히 무엇인가

- 논문 §4.1은 "마지막 Transformer 층의 앞과 뒤의 격자 특징을 실험했다"고 쓰고 §5.2는 앞의 것이 0.96점 낫다고 합니다. 가설은 "마지막 층은 전역·추상 속성, 앞 층은 국소 속성".
- 공식 코드(`clip_encoder.py`): `image_features = outputs.hidden_states[self.select_layer]`, `select_layer = -2`(모든 공식 스크립트의 `--mm_vision_select_layer -2`), `select_feature='patch'`면 `[:, 1:]`. HF `CLIPVisionModel`의 `hidden_states`는 (임베딩 + 사전 LN) 뒤 각 블록의 출력으로 **25개(24층)**이므로 **[-2]는 23번째 블록의 출력**이고 사후 LayerNorm(`post_layernorm`)은 풀링된 CLS에만 걸려서 **어느 쪽 특징에도 적용되지 않습니다**. 최소 구현이 같은 규약을 씁니다(`TinyViT.hidden_states`, 테스트 `test_select_layer_minus2_is_second_to_last_block_without_cls`).
- 기계적 이유(CLS 풀링 목적에서): CLIP의 학습 신호는 마지막 블록 뒤의 **CLS**에만 닿습니다. 마지막 블록의 CLS 출력은 마지막 블록의 **입력**(=블록 23의 출력) 패치들만 읽으므로, **마지막 블록의 패치 출력은 손실에 직접 닿지 않습니다**. 즉 hidden_states[-1]의 패치 토큰은 학습 목적이 직접 제약하지 않는 쪽이고 [-2]는 CLS가 읽는 쪽입니다. 이것은 논문이 든 이유(전역 대 국소)와 다른, 구조에서 오는 설명입니다. 토이에서 이 설명을 진단했습니다(§6.3).

### 5.1 최소 구현이 하는 것

| D10 | 시퀀스 길이 언급 없음 | 시각 토큰 병합 뒤 `tokenizer_model_max_length`(2048)로 **뒤를 자름**(`llava_arch.py` L273–L277) | 논문에 없음. 576토큰이면 텍스트 1,472토큰 한도(§2) |
| D11 | 투영은 선형 층 하나(식 1) | 설정 기본값 `mm_projector_type='linear'`. v1.5 스크립트는 `mlp2x_gelu`(`builder.py`의 `Linear, GELU, Linear`) | 일치. 선형 대 MLP는 옵션 이름 하나 차이 |
| D12 | GPT-4 판정, 1–10점, 상대 점수(§5) | `eval_gpt_review_bench.py`: 모델 `gpt-4-0314`, `temperature=0.2`, 시스템 "You are a helpful and precise assistant for checking the quality of the answer.", **참조 답이 항상 Assistant 1, 후보가 Assistant 2**(`llavabench.sh`의 인수 순서), 판정 호출은 문항당 1회. 프롬프트는 "순서가 판단에 영향을 주지 않게 하라"고 쓰지만 순서를 바꿔 다시 묻지 않음. **파싱 실패는 `[-1, -1]`로 두고 평균에 그대로 포함**(`summarize_gpt_review.py`는 필터 없음). 요약은 `mean(후보) / mean(참조)` | 판정자 구성이 논문 §5에 없는 세부(모델 스냅샷, 온도, 위치 고정, 실패 처리)를 담고 있음. `gpt-4-0314`는 단종된 스냅샷이라 그대로의 재현은 불가능 |

- **파싱 실패의 크기.** 같은 저장소의 Vicuna-80 판정 4세트(GPT-4, 같은 1–10점 프로토콜)에서 각 80개 중 **3개(3.75%)**의 첫 줄이 "두 점수" 형식이 아니었습니다(`bench_results.json`). LLaVA-Bench 판정의 실패율은 모르지만 같은 크기라면 60문항에서 약 2개입니다. `[-1, -1]`이 평균에 섞일 때 상대 점수의 이동은 실제 비 67.3%에서 2개 실패면 −0.14점, 85%에서 −0.06점으로 **작습니다**(산술). 결론에는 영향이 없지만 필터가 없다는 사실은 기록할 가치가 있습니다.
- **참조 위치 고정.** 판정자는 항상 참조를 첫 번째로 봅니다. MT-Bench에서 GPT-4가 순서에 따라 판정을 바꾸는 비율은 15.8%(공개 판정 2,400개, `llm_as_judge/`)이므로 위치 편향이 상대 점수를 한쪽으로 밀었을 수 있으나, LLaVA-Bench에서는 순서를 바꾼 판정이 없어 **방향도 크기도 알 수 없습니다.**
- 코드 쪽 가장 큰 발견은 D1(1단계가 질문 없는 캡션 복사)과 D4(논문 레시피의 스크립트 부재)입니다.

## 6. 합성 장면 토이 실험 (CPU·MPS, 논문 재현이 아님)

`analysis/run_experiments.py`. Apple MPS에서 시드당 7설정(약 17분), 5시드(0, 1, 2, 3, 4). 데이터·가중치는 받지 않고 모두 코드로 생성합니다. 평가는 **시드마다 같은 보류 장면 질문 2,000개**(유형당 500)이고 구간은 시드 5개 평균의 t 95% 구간이고 표에서는 0–1로 잘랐습니다(자유도 4라 넓습니다).

### 6.0 설정

- **파이프라인**: (1) 비전 인코더(4층 ViT)를 CLS 전역 목적(색 존재 + 물체 수)으로 400스텝 학습 후 동결, (2) LM(3층)을 텍스트만으로 1000스텝 사전학습(장면 설명 글 + 글 안의 질의응답), (3) 같은 시드의 (1)(2)에서 모든 설정이 출발(짝지은 비교), (4) 1단계(투영만, 1200스텝, lr 2e-3, 캡션) → 2단계(투영 + LM, 2000스텝, lr 1e-3, 질문 4종 균등). 배치 64, AdamW(wd 0), 코사인, 워밍업 3%. 모든 설정이 같은 데이터 순서에서 시작합니다.
- **장면**: 5x5 칸에 색 물체 1–4개(색은 모두 다르고 6색 중). 질문 4종: **개수**, **칸의 색**(행·열로 지정, 답 색 1토큰), **위치**(색으로 지정, 답은 행·열 2토큰), **색 유무**(예/아니오). 답이 맞으려면 답 토큰 전부와 `<eos>`가 맞아야 합니다. 우연 수준: 개수 약 25–35%, 색 유무 50%, 칸의 색은 "장면에 있는 색 중 하나를 고르는" 기준선이 평균 약 52%, 위치 1/25(4%).
- **설정(arm)**: base(선형, 끝에서 두 번째 층 -2, 두 단계), one_stage(2단계만, 같은 2단계 스텝), **one_stage_long(2단계만, 1단계 + 2단계와 같은 총 스텝 3200, 계산 통제)**, mlp(2층 MLP, -2, 두 단계), mlp_one_stage, last_layer(선형, -1), layer_m3(선형, -3).
- **예비 실험**(보고하지 않은 설정 선택, 시드 101–104, 보고 시드와 다름): 처음 설정(8x8 칸, 학습되는 LM 위치, 작은 초기화 ViT 위치)은 위치·칸의 색 질문이 3,000스텝까지도 우연 수준(위치 2–12%)이라 설정 간 차이를 볼 수 없었습니다. 그래서 (a) LM 위치를 고정 사인 인코딩(실물 LLM의 RoPE처럼 어떤 위치도 정의됨)으로, (b) ViT 위치 임베딩을 2D 사인 초기화(전역 목적은 위치를 안 쓰므로 작은 초기화는 끝까지 작게 남음)로, (c) 칸 수를 5x5로 줄였습니다. 이 선택은 **학습이 되는 영역으로 가려고 한 것이고 결과를 보고 설정을 고른 것**입니다(근거: 같은 기준 "위치 질문이 우연보다 확실히 위"). 다른 설정에서 같은 결과가 나온다는 뜻이 아닙니다.

- **결과 읽는 법.** 개수와 색 유무는 모든 설정에서 거의 100%라(전역 정보로 풀림) 설정 간 차이를 만들지 못합니다. **칸의 색**(행·열로 주소 지정)은 모든 설정에서 0.51–0.58로 "장면에 있는 색 중 하나 고르기" 기준선(약 52%)과 구분되지 않아 **이 학습량에서는 사실상 학습되지 않았습니다.** 그래서 "공간 질문 평균"(개수, 칸의 색, 위치의 평균)의 설정 간 차이는 사실상 **위치 질문**의 차이입니다(위치의 차이를 3으로 나눈 값).

### 6.1 1단계(특징 정렬)는 필요한가 — 논문 C7, Prismatic

| 설정 | 총 스텝 | 공간 질문 평균(개수, 칸의 색, 위치) | 위치 | 칸의 색 |
|---|---|---|---|---|
| base(두 단계) | 1200 + 2000 | 0.761 [0.717, 0.805] | 0.744 [0.619, 0.869] | 0.539 [0.490, 0.588] |
| one_stage(같은 2단계 스텝) | 2000 | 0.568 [0.553, 0.584] | 0.195 [0.153, 0.236] | 0.510 [0.486, 0.535] |
| one_stage_long(같은 총 스텝) | 3200 | 0.807 [0.723, 0.892] | 0.872 [0.662, 1.000] | 0.551 [0.487, 0.615] |

- base 대 one_stage(2단계 스텝 동일, 총 스텝은 base가 1200만큼 많음): 짝지은 차이 -0.193 [-0.250, -0.135] (양의 시드 0/5). **1단계를 뺀 모델이 크게 떨어집니다.** 논문의 표 8(−5.11)과 같은 방향입니다.
- base 대 one_stage_long(총 스텝을 같게): 짝지은 차이 +0.047 [+0.005, +0.088] (양의 시드 4/5). **스텝 수를 맞추면 단일 단계가 두 단계와 같거나 낫습니다.** 1단계 스텝은 LM 가중치 기울기가 없어 스텝당 더 싸므로(4N 대 6N 가정 시 두 단계는 전체 스텝 2800개 상당) one_stage_long의 계산량이 약 14% 더 큽니다. 스텝 수는 같고 계산량은 맞지 않은 비교입니다. 한편 Prismatic이 주장하는 것은 "계산을 20–25% 아끼고 성능은 같다"입니다. 이 토이는 "단일 단계가 모자라지 않다"는 부분과 방향이 같고, 그 앞의 큰 격차(one_stage)가 **1단계의 효과가 아니라 학습 스텝의 차이일 수 있음**을 보여 줍니다. 논문 표 8의 ScienceQA 절제도 스텝·데이터 통제가 설명되지 않은 비교입니다.
- 1단계 후 캡션 내용 토큰 정확도(교사 강제, 색·행·열 토큰) 0.468 [0.462, 0.474]: 동결된 LM은 이미지 토큰에서 캡션 내용을 완전히 읽어 내지 못하고(우연은 약 17–20%), 이 부분 정렬이 2단계의 출발점이 됩니다.
- 단서: 1단계 데이터는 캡션 복사이고 2단계는 질문이라 과제가 다릅니다. 토이 LM은 글 속 장면 설명을 읽고 답하는 능력을 먼저 갖췄습니다(텍스트 사전학습). 실물 LLM에서 같은 능력이 정렬 단계의 효과에 영향을 주는지는 알 수 없습니다.

|---|---|---|---|---|
| -4(블록 1 출력) | 1.000 | 0.962 | 0.510 | 14.5 |
| -3 | 1.000 | 0.930 | 0.712 | 20.6 |
| -2 | 1.000 | 0.916 | 0.796 | 26.1 |

  **깊은 층일수록 패치 토큰 하나에 전역 정보(물체 수)가 많이 섞이고 위치 정보는 줄어듭니다**(위치는 약간, 전역은 크게). 색은 모든 층에서 완벽하게 읽혀 국소 정보의 손실은 이 토이에서 보이지 않습니다. 이것은 논문의 설명("마지막 층은 전역·추상, 앞 층은 국소")과 **방향이 같은 현상**이지만 CLS-only 전역 목적으로 학습한 4층 ViT에서의 현상이고, 이 차이가 하류 정확도의 차이로 이어지지는 않았습니다(위 표). CLIP의 층별 탐침은 하지 않았습니다.
- 정리: "끝에서 두 번째 층이 마지막 층보다 낫다"(논문 −0.96)는 이 토이에서 **구분되지 않았습니다**(−0.025). 더 얕은 층이 낫다는 약한 경향과 층별 표현의 전역성 증가는 보였습니다. 이 토이의 인코더는 CLS 전역 목적이라 마지막 블록 패치 출력이 손실에 닿지 않는 구조(`03` §4)인데도 마지막 층이 크게 나쁘지 않았다는 점은, 그 구조적 설명이 하류 정확도 차이를 만들 만큼 강하지 않음을 시사합니다.

### 6.4 BLIP-2 토이와의 비교 가능성 (`blip2/`)

위치·개수 질문의 **종류**는 같게 했습니다(개수, 칸의 색, 위치, 존재). 그러나 장면 크기(5x5 대 8x8), 인코더(CLS 전역 목적으로 사전학습한 ViT 대 고정된 무작위 인코더), LM(작은 인과 디코더 대 텍스트 사전학습 고정 디코더), 학습량이 다르므로 **수치를 직접 비교하면 안 됩니다.** 비교는 질적으로만 가능합니다: 이 토이에서 **개수와 색 유무는 모든 설정에서 거의 완벽**(CLS 전역 목적이 이 정보를 패치 토큰에 퍼뜨림)했고 어려운 것은 **위치 지정 질문과 칸으로 주소를 지정하는 칸의 색 질문**이었습니다. 모든 패치를 넘기는 연결이 압축 연결에 비해 위치 질문에서 유리한지는 같은 조건의 두 토이가 있어야 답할 수 있습니다.

### 6.5 한계

- 시드 5개(자유도 4)라 구간이 넓고, 설정 간 대부분의 차이는 구간이 0을 덮습니다. 위에서 방향이 일관된 것은 one_stage 대 base(5시드 모두 낮음), one_stage_long 대 base(4/5 양), layer_m3 대 base(5/5 양, 하한 +0.003) 정도입니다. 6개 비교에 다중 비교 보정을 하지 않았습니다.
- 토이의 비전 인코더는 CLS 전역 목적 하나로만 사전학습했고, 위치·색이 쉽게 읽히는 단순한 이미지입니다. 층 선택과 정렬 효과는 이 선택에 크게 의존할 수 있습니다.
- 설정 선택에 예비 실험의 결과가 들어갔습니다(6.0). MPS 연산의 비결정성 때문에 같은 시드의 재실행이 비트 단위로 같지 않을 수 있습니다(pytest의 결정성 테스트는 CPU).
- 데이터는 매 스텝 새로 만들어 과적합이 없고, 실물의 "158K를 3에폭 반복"과 다릅니다.

## 7. LLaVA-Bench와 ScienceQA의 통계

`analysis/bench_stats.py`(numpy, 학습·API 없음), 결과는 `bench_results.json`입니다. 이 폴더의 `llm_as_judge/`(MT-Bench 판정자 편향), `eval_error_bars/`(짝지은·군집 표준오차), `little_power/`(짝지은 비교의 검출력)와 같은 틀입니다.

### 7.1 문항 수 (공개 자료에서 확인)

| 벤치마크 | 문항 | 이미지 | 범주별 | 출처 |
|---|---|---|---|---|
| LLaVA-Bench (COCO) | **90** | 30 | 대화 30, 상세 30, 추론 30 | 공식 저장소 `playground/data/coco2014_val_qa_eval/qa90_questions.jsonl`(90줄) |
| LLaVA-Bench (In-the-Wild) | **60** | 24 | 대화 **17**, 상세 **15**, 추론 **28** | HF `liuhaotian/llava-bench-in-the-wild`의 `questions.jsonl`(8,246 B, 60줄), `context.jsonl`(24줄). 이미지는 받지 않음 |

- 논문이 "90문항"과 "24장 60문항"이라 쓴 숫자와 일치합니다. 문항의 범주 구성은 In-the-Wild에서 균등하지 않습니다.
- **표 5의 "전체"는 범주 상대 점수의 문항 수 가중 평균과 맞습니다**: BLIP-2 38.10 대 보고 38.1, OpenFlamingo 19.13 대 19.1, LLaVA 67.49 대 67.3, LLaVA† 66.95 대 66.7. 가중하지 않은 평균(63.8, 38.9)은 맞지 않으므로 17/15/28 가중이 확인됩니다. 즉 상대 점수는 점수 합의 비(풀링)입니다.
- **표 4 괄호 차이 16칸 중 4칸이 뺄셈과 다릅니다**: Conv + 5% Detail + 10% Complex의 상세 −7.1(뺄셈 −6.9), 전체 −4.4(−4.6), Conversation의 상세 −16.2(−15.5), 추론 −12.4(−11.6). 차이는 0.2–0.8점이라 반올림으로는 설명되지 않으며(0.05 이내여야 함), 결론에는 영향이 없습니다. 괄호 값이 다른 실행의 기준선에서 계산됐을 가능성이 있습니다(추측).

### 7.2 상대 점수의 불확실성

문항별 판정 점수는 공개되어 있지 않습니다. LLaVA의 판정 결과를 직접 부트스트랩할 수 없어서 두 가지로 근사합니다.

1. **실측 앵커: Vicuna-80 판정 4세트**(저장소 `llava/eval/table/review/`, GPT-4가 같은 1–10점 프로토콜로 판정, 각 80개 중 파싱 가능 77개). 문항별 점수의 표준편차는 0.5–1.7, 두 점수의 상관은 0.31–0.51, 동점률은 0–29%, 점수는 거의 정수(88–100%)입니다. 문항 부트스트랩 95% 구간은 alpaca 상대 점수 118.6에서 [115.7, 121.8], bard 102.3에서 [98.9, 105.7], gpt35 94.6에서 [91.7, 97.2], llama 136.3에서 [129.6, 144.7]입니다(반폭 3–7점).
2. **델타 방법.** 비 r = Σ후보/Σ참조의 표준오차를 문항을 독립 표본으로 보고 계산합니다. 참조 점수 평균 8.5, SD 1.0, 후보 SD 2.0, 상관 0.3이라는 **가정**(위 앵커의 범위를 넘지 않게 잡음)에서 n = 60, r = 0.673에 표준오차 2.9점(정규 점수를 직접 뽑은 시뮬레이션 2.84)입니다. 후보 SD 1.5–2.5, 상관 0–0.5의 범위에서 반폭은 아래와 같습니다. **후보 SD는 LLaVA의 문항별 점수가 아니라 가정입니다.** 후보의 점수가 5점 안팎으로 퍼지는 모델이므로 앵커(0.7–1.3)보다 크게 잡았습니다.

| 설정 | 점 추정 | 95% 반폭 (SD 2.0, 상관 0.3) | 범위 (SD 1.5–2.5, 상관 0–0.5) |
|---|---|---|---|
| In-the-Wild 전체 (n=60) | 67.3 | **±5.7** | ±3.9 – ±7.7 |
| In-the-Wild 대화 (n=17) | 57.3 | ±10.7 | |
| In-the-Wild 상세 (n=15) | 52.5 | ±11.4 | |
| In-the-Wild 추론 (n=28) | 81.7 | ±8.4 | |
| COCO 전체 (n=90) | 85.1 | **±4.7** | ±3.2 – ±6.4 |
| COCO 범주별 (n=30) | 83.1 | ±8.1 | |

- **논문의 "±"는 문항 표본 오차가 아닙니다.** 표 5의 LLaVA 67.3 ± 2.0은 3번의 추론 실행의 표준편차이고, LLaVA†의 ± 0.3은 같은 디코딩 결과를 GPT-4가 세 번 채점한 표준편차입니다. 문항을 다시 뽑는 오차(±5.7)는 이보다 약 3배 큽니다. "GPT-4 gives a consistent evaluation"은 판정자의 반복 일관성이지 상대 점수의 정밀도가 아닙니다.
- **In-the-Wild의 큰 순위는 견고합니다.** LLaVA 67.3 대 BLIP-2 38.1(차이 29.2점)은 문항 오차로 z = 7.1(모델 간 상관 0) – 10.0(0.5), OpenFlamingo 19.1(48.2점)은 z = 11.6 – 16.4입니다(`itw_vs_baselines`). 순위가 문항 표본으로 뒤집힐 가능성은 낮습니다.
- **표 4의 학습 데이터 절제는 작은 차이에서 약합니다.** 같은 90문항에서 비교하므로 짝지은 오차가 쓰이고 두 설정의 문항 점수 상관 ρ에 달립니다(ρ 모름). 차이 +6.7(Conversation → Conv + 5% Detail + 10% Complex)은 ρ = 0이면 z = 2.0, 0.5면 2.8, 0.8이면 4.5입니다. +4.6(Conv + 5%... → Full)은 z = 1.4 / 1.9 / 3.1, +3.2(Detail + Complex → Full)는 z = 0.95 / 1.35 / 2.1입니다. **"Full이 가장 좋다"는 방향은 있으나 85.1 대 81.9의 구분은 ρ가 0.8에 이르지 않으면 지지되지 않습니다.** "미튜닝 21.5 대 튜닝 70–85"는 어느 가정에서도 견고합니다.
- **범주별 값은 더 불확실합니다.** 상세 설명 범주는 In-the-Wild에서 n = 15, 반폭 ±11.4이고 표 5의 LLaVA 상세 52.5 ± 6.3(3회 실행)은 실행 간 변동만으로 이미 큽니다.

### 7.3 판정자 편향 (측정할 수 없는 것과 근거)

LLaVA-Bench의 후보 답과 판정은 공개되지 않아 편향을 직접 재지 못합니다. 설계에서 보이는 위험만 적습니다.

- **참조와 판정자가 같은 계열.** 참조 답은 텍스트 전용 GPT-4가 정답 설명을 보고 쓰고, 판정도 GPT-4입니다. 분모(참조의 점수)는 판정자 자신의 답이므로 자기 선호가 분모와 분자에 다르게 작용할 수 있습니다. MT-Bench에서 자기 선호는 결론이 보류됐습니다(GPT-4 승률이 사람보다 +12.4%p 높지만 하위 모델을 낮추는 방향과 분리되지 않음, `llm_as_judge/`).
- **위치.** 참조는 항상 Assistant 1입니다(D12). 순서 교환 판정이 없습니다. MT-Bench 공개 판정에서 GPT-4의 순서 의존 불일치가 15.8%였습니다.
- **판정자는 이미지를 보지 않습니다.** 정답 설명(COCO는 캡션과 상자, In-the-Wild는 사람이 쓴 상세 설명)에 없는 시각 사실은 맞아도 감점될 수 있고, 설명에 없는 환각은 잡지 못합니다. LLaVA-Bench는 환각을 직접 재지 않으며 논문도 인정합니다(부록 A "환각 정도"는 후속 과제).
- **학습 데이터와 같은 생성 파이프라인.** COCO 벤치마크의 질문과 참조는 학습 데이터(158K)를 만든 것과 같은 "캡션 + 상자 → GPT-4" 파이프라인에서 나옵니다(§3, §5). 이미지는 val2014로 분리됐지만 응답 형식과 어조가 같아 분포 안 평가입니다. 초록의 85.1%가 In-the-Wild의 67.3%보다 높은 것과 방향이 맞지만 원인 분리는 못 합니다.
- **길이·장황함.** MT-Bench(`llm_as_judge/`)의 장황함 공격 실험이 같은 계열 판정자의 길이 민감성을 보였습니다. 상세 설명 범주(참조가 길다)에서 후보의 길이가 점수에 미치는 영향은 후보 출력이 없어 측정하지 못했습니다.

### 7.4 ScienceQA (표 7, 8)

시험 분할은 4,241문항(논문 L485)이라 이항 구간은 정확도 90.92에서 Wilson 95% [90.02, 91.75], 92.53에서 [91.70, 93.28], MM-CoT-Large 91.68에서 [90.81, 92.47]입니다. 아래는 **시험 문항을 다시 뽑는 오차만** 센 것이고, **학습 실행 간 변동은 단일 실행이라 알 수 없습니다.**

| 비교 | 차이 | z(독립) | z(짝지은, 불일치율 d = 3% / 6% / 10%) |
|---|---|---|---|
| 끝에서 두 번째 층 대 마지막 층 (표 8) | 0.96 | 1.5 | 3.6 / 2.6 / 2.0 |
| 13B 대 7B | 1.08 | 1.7 | 4.1 / 2.9 / 2.2 |
| 이유 먼저 대 답 먼저 | 1.15 | 1.8 | 4.3 / 3.1 / 2.4 |
| 1단계 있음 대 없음 | **5.11** | **7.4** | 19 / 14 / 11 |
| GPT-4 판정 앙상블(92.53) 대 MM-CoT-Large(91.68) | 0.85 | 1.45 | 3.2 / 2.3 / 1.75 (같은 문항 쌍 자료가 없어 독립이 안전) |
| GPT-4 판정 앙상블 대 LLaVA 단독(90.92) | 1.61 | 2.7 | 6.1 / 4.3 / 3.3 |

- 짝지은 비교의 80% 검출력 최소 효과는 두 모델이 서로 다르게 맞히는 문항 비율 d가 3%, 6%, 10%일 때 각각 0.74, 1.05, 1.36점입니다(`little_power/`의 식 MDE ≈ 2.80·√(d/n)). **층 선택의 0.96점은 d가 6% 이상이면 80% 검출력의 최소 효과(1.05) 아래**에 있습니다. d는 모델 예측이 공개되지 않아 알 수 없으므로 "견고하게 확인된 차이"로 쓰기 어렵습니다.
- **1단계 없음의 −5.11점은 어느 가정에서도 크고 견고합니다**(문항 표본 기준). 단 이 절제는 ScienceQA를 처음부터 학습한 경우(투영과 LM이 무작위/사전학습 초기값에서 ScienceQA만 학습)이므로 "정렬 사전학습이 중요하다"가 챗봇·일반 VQA에도 같은 크기로 성립한다는 뜻은 아닙니다(`04` C7).
- **"새 SOTA 92.53%"**는 MM-CoT-Large 91.68보다 0.85점 높고, 독립 비교로 z = 1.45(양측 p ≈ 0.15)입니다. 두 모델의 예측을 쌍으로 볼 수 없어서 짝지은 검정은 못 했습니다. SOTA 순위의 경계 사례입니다. 또한 이 앙상블은 **GPT-4가 최종 답을 정하는 판정 단계**를 쓰며, 같은 문항 4,241개를 보고 설계된 방식입니다(여러 방식을 시험해 가장 좋은 것을 보고했다는 뜻이 아니라, 선택 과정이 서술되지 않았다는 뜻).


## 8. 이 분석의 한계

- 논문의 학습·평가(8×A100, GPT-4 판정)를 재현하지 않았습니다. 수치는 논문의 표를 재계산한 것과 공개 자료(문항 수, 판정 코드, Vicuna-80 판정)에서 온 통계이고, LLaVA 모델의 출력과 문항별 판정 점수는 보지 못했습니다. 상대 점수의 구간(`03` §7.2)은 후보 점수의 산포를 **가정**한 값입니다.
- 공식 코드는 정적으로만 읽었고 실행하지 않았습니다. D1–D12는 코드의 현재 커밋(2024-05-12)에 대한 서술이고 논문 시점(2023-04)의 코드와 다를 수 있습니다(`docs/MODEL_ZOO.md`가 보여 주는 대로 레시피가 여러 번 바뀜).
- 토이는 이해용입니다(§6.5). 실물의 CLIP 특징, 코퍼스 사전학습된 LLM, 자연 이미지와는 다릅니다.
- 이후 문헌은 이 저장소의 분석과 arXiv 초록, LLaVA-1.5 본문에서만 읽었고, MM1·ShareGPT4V·InstructBLIP·POPE·MiniGPT-4·OneVision은 본문을 읽지 않았습니다. 웹 검색은 0회입니다.
