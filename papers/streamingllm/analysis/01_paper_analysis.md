# 01. 논문 분석: Efficient Streaming Language Models with Attention Sinks (StreamingLLM)

분석 판: arXiv v4(2024-04-07, ICLR 2024 camera-ready 형식). v1(2023-09-29)과 비교했습니다. 본문 표 2, 3, 6의 값은 v1에도 같은 값으로 있고, v1에는 부록 A–I(한계 논의, StreamEval 거리별 표 7, LongBench 표 8, BERT의 sink, sink 토큰 2개 실험 표 9–10)와 영향 진술이 없습니다. 분석일 2026-11-28. 구현 모드(분석 + 최소 구현).

- 저자: Guangxuan Xiao(MIT), Yuandong Tian(Meta AI), Beidi Chen(CMU), Song Han(MIT, NVIDIA), Mike Lewis(Meta AI). 공식 코드 `mit-han-lab/streaming-llm`(MIT 라이선스).
- 학회: ICLR 2024 포스터(Poster Session 1). 확인 기록은 README의 "학회 표기".

## 1. 문제

스트리밍 응용(끝없이 이어지는 대화)에는 두 걸림돌이 있습니다(1절).

1. 디코딩에서 모든 이전 토큰의 K, V를 저장하면 메모리와 지연이 늘어납니다.
2. 사전학습 길이보다 긴 텍스트로 일반화하지 못합니다(길이 외삽 실패).

단순한 해법은 최근 L개의 KV만 두는 **window attention**입니다. 그러나 텍스트 길이가 캐시 크기를 넘는 순간, 즉 첫 토큰의 KV가 빠지는 순간 perplexity가 폭발합니다(그림 3, 표 1). 정확한 기준선은 **슬라이딩 윈도 + 재계산**(토큰마다 최근 L개를 처음부터 다시 계산, O(TL²))인데 느립니다(그림 1c).

## 2. 방법

### 2.1 관찰: attention sink (3.1절, 그림 2)

- 몇 층 이후의 거의 모든 head가 의미와 상관없이 **초기 토큰**에 attention을 크게 줍니다(Llama-2-7B, 256문장 × 길이 16의 평균 attention logit. 부록 F의 그림 12: 길이 4096에서 4096번째 토큰이 첫 토큰에 주는 softmax 질량은 아래 두 층을 빼면 대체로 절반을 넘음).
- 설명은 softmax(식 1)입니다. 합이 1이어야 하므로, 쓸 곳이 없는 attention을 어딘가에 버려야 하고, 모든 이후 토큰에 보이는 초기 토큰이 그 자리가 되기 쉽다는 것입니다. 초기 토큰이 빠지면 분모의 큰 부분이 사라져 분포가 평소와 달라집니다.
- 의미가 아니라 **절대 위치**가 중요하다는 근거는 표 1: 처음 4토큰을 `"\n"`으로 바꿔도 4+1020에서 perplexity가 5.60(원래 5.40, 윈도만 5158.07, Llama-2-13B, PG19 첫 책 65K 토큰)로 회복됩니다.
- 초기 토큰이 하나가 아니라 여러 개 필요한 이유로, 모델이 일정한 시작 토큰 없이 학습됐기 때문이라는 가설을 세웁니다(Llama-2는 문단마다 `<s>`를 붙이지만 청크로 자르기 전이라 0번 위치에 무작위 토큰이 옴).

### 2.2 롤링 KV 캐시 (3.2절, 그림 4)

- 캐시 = **싱크 토큰 s개(처음 s개 토큰)** + **최근 토큰 윈도**. 기본 s = 4(4절 첫머리 "default to four initial tokens").
- **위치는 원문이 아니라 캐시 안 순번**으로 매깁니다. 예: 캐시에 [0, 1, 2, 3, 6, 7, 8]이 있고 9번째 토큰을 디코딩하면 위치는 [0,1,2,3,4,5,6,7]입니다(원래 [0,1,2,3,6,7,8,9] 아님).
- RoPE: **회전 전의 키**를 캐시에 저장하고, 디코딩 단계마다 캐시 안 위치로 회전합니다. ALiBi는 건너뛰는 편향 대신 연속된 선형 편향을 씁니다.
- 파인튜닝 없음. 연산은 O(TL), 재계산은 O(TL²)(그림 1).

### 2.3 사전학습 때 싱크 토큰 (3.3절, 식 2, 표 3, 4, 그림 6, 7)

- 모든 학습 샘플 앞에 **학습 가능한 placeholder 토큰** 하나를 붙입니다("Sink Token"). 비교로 SoftMax₁(식 2: 분모에 +1, 즉 K = V = 0인 토큰을 앞에 붙인 것과 같음)을 "Zero Sink"라 부릅니다.
- Pythia-160M 코드와 학습 설정으로 8×A6000, 배치 256, 143,000 스텝(4.2절)에서 세 모델을 학습합니다.
- 표 3(PG19 첫 표본 1개): vanilla 27.87 / 18.49 / 18.05 / 18.05(0+1024, 1+1023, 2+1022, 4+1020), Zero Sink 29214 / 19.90 / 18.27 / 18.01, Learnable Sink 1235 / 18.01 / 18.01 / 18.02. 즉 싱크 토큰이 있으면 그 토큰 하나만 남겨도 되고, 윈도만 쓰면(0+1024) 오히려 더 크게 망가집니다(1235 대 27.87).
- 표 4: 7개 제로샷 벤치마크 점수가 vanilla와 비슷(차이 +0.3~+1.0pt). 그림 6: 학습 곡선 비슷.

## 4. 한계 (논문이 인정한 것과 우리가 본 것)

논문이 인정한 것(부록 A, C, D): 컨텍스트 창을 넓히지 않고 장기 기억도 늘리지 않습니다. 캐시 밖 정보는 쓸 수 없어 긴 문서 QA·요약에는 맞지 않습니다. 표 7은 질의-정답 거리가 캐시 크기를 넘으면 정확도가 0이 됨을 보입니다.

우리가 본 것:

- 평가 지표는 거의 PG19 perplexity이고, 모델별 폭발의 크기가 크게 다릅니다(표 2: 윈도만 / 4싱크 = Falcon-7B 1.5배, Pythia-12B 1.8배, MPT-7B 31배, Llama-2-7B 350배). "윈도 attention이 무너진다"는 Llama 계열에서 극적이고 다른 계열에서는 훨씬 약합니다(`03` §2, §3).
- 표 2의 "4개면 충분"은 모델마다 값이 다릅니다. Llama-2-7B는 1→2→4→8개에서 11.88→10.51→9.59→9.54이지만 Falcon-7B는 1개에서 이미 같고(12.12), MPT-7B도 1개에서 14.99입니다.
- 표 3의 사전학습 비교는 평가가 PG19 **첫 표본 1개**이고 시드 1개라 신뢰구간이 없습니다. vanilla에서 1개(18.49)와 2개(18.05)의 차이(2.4%)는 이 구성만으로 유의한지 알 수 없습니다.
- 표 2의 Falcon-7B 4+2044(12.12)와 표 6의 같은 구성(12.84)이 다릅니다(v1에도 같음. `03` §6).
- 효율(그림 10)은 A6000 한 대, 일반 HF 구현입니다. 우리는 이 GPU 지연을 재현하지 않았고 막대 숫자로 계산만 했습니다.
- 표 4(제로샷 점수)는 표본 오차 안의 차이입니다(`03` §6).
- 비판적으로: "싱크 토큰을 사전학습에 넣으라"는 권고는 160M 모델 하나, 시드 1개에서 나왔습니다.
