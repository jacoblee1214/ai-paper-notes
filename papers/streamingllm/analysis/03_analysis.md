# 03. 분석: 롤링 KV 캐시를 직접 짜서 스트리밍 perplexity로 논문 주장을 확인

구현 모드. 논문 결과(Llama-2, PG19, A6000)를 재현한 것이 **아니라**, 같은 방법을 소형 공개 모델에서 직접 구현해 논문의 정성적 주장(싱크 4개, 윈도만 쓰면 폭발, 재계산과 같음, 위치는 캐시 안 순번)이 성립하는 조건을 본 것입니다. 로컬에 이미 캐시된 가중치(Pythia-14M/70M/160M, GPT-2 small)와 데이터(`NeelNanda/pile-10k`)만 썼고 새로 받은 것은 없습니다. GPU, 공식 코드 실행, API 호출은 없습니다.

## 0. 구현과 정합성

- `minimal_impl.py`: `MiniLM`(Pythia와 GPT-2를 한 코드로, HF 가중치 복사), `attend()`(병렬 스트리밍 attention), `RollingKVCache`(토큰 하나씩, 회전 전 키 저장, 캐시 안 순번으로 회전), `nll_recompute()`(슬라이딩 윈도 + 재계산). 캐시 크기 C = s + w는 **현재 토큰을 포함**해 셉니다(공식 코드는 현재 토큰을 하나 더 봄, `04` D1).
- **병렬 형태가 토큰별 형태와 같다는 것**이 실험의 핵심 전제입니다. 질의 t는 싱크 [0, s)와 윈도 [max(s, t−w+1), t]를 보고, 윈도 키는 원래 위치로 회전해도 상대 거리가 캐시 안 거리와 같으며(`test_window_only_equals_banded_attention_with_true_positions`, HF 4D 마스크와 독립 비교), 싱크 키는 위치 0..s−1, 질의는 캐시 안 위치 min(t, C−1)로 회전합니다. 그래서 4096 토큰 스트림 24개를 한 번에 계산할 수 있습니다.
- 테스트 pytest 22개(무작위 초기화한 작은 HF 모델, 2초 안팎): HF 로짓 일치(GPT-2 1e-9, NeoX 1e-5; HF의 RoPE 각도가 float32라 NeoX는 그 아래로 못 내려감), T ≤ C이면 dense와 같음, `RollingKVCache`가 `attend()`와 1e-9 이내로 같음(s, w 4가지, GPT-2는 두 위치 모드), 캐시가 항상 `[0..s) ∪ 최근 w`만 보유, RoPE 상대 위치 불변, 재계산이 정의대로 동작, GPT-2는 원래 위치를 표 크기 너머로 못 씀.
- 실제 가중치에서(`real_model_checks_results.json`, float32, CPU, 스트림 4개 × 512 토큰): Pythia-70M은 HF 로짓과 최대 0.41 차이(로짓 크기 최대 1087, 상대 4e-4. 평균 |nll 차이| 4e-4, perplexity 13.3574 대 13.3572), GPT-2는 0.011(크기 339), 평균 |nll 차이| 7e-6. `RollingKVCache` 대 `attend()`(4+124, 길이 512)는 Pythia-70M 0.077(크기 1087), GPT-2 0.018(원래 위치)·0.008(순번 위치)로 float32 누적 오차 수준입니다. float64 테스트에서는 1e-9 이내입니다.

## 1. 실험 설계

- **스트림**: pile-10k 문서를 시드 0 순서로 이어 붙임(문서 뒤 EOS), 각 스트림은 문서 첫머리에서 시작. n = 24 스트림. Pythia는 T = 4096(사전학습 문맥 2048의 2배), GPT-2는 T = 1024(문맥 한계)와 T = 2048(위치 순번 모드만).
- **측정**: 위치 t의 입력으로 토큰 t+1의 nll. 구간 `pre`: t < C(아직 아무것도 안 빠짐, 모든 방법이 dense와 같음), `post_all`: t ≥ C, `mid`: C ≤ t < 사전학습 문맥, `late`: t ≥ 사전학습 문맥. perplexity는 스트림 평균 nll의 exp.
- **방법**: dense, 윈도만(0+C), 싱크 s개 + 윈도(s = 1, 2, 4, 8), 슬라이딩 윈도 + 재계산(C개를 위치 0부터 다시 계산, 스트라이드 위치만), 표 1 변형(`s4nl`: 입력의 처음 4토큰을 줄바꿈 토큰으로 바꾸고 싱크 4개 유지, 대상은 그대로).
- **통계**: 신뢰구간은 스트림 단위 부트스트랩 2000회. 방법 간 비교는 스트림 짝지은 평균 nll 차이이고 부호 뒤집기 검정(20000회) 뒤 모델별 비교 목록 전체에 Holm 보정. 시드는 문서 순서 1개(0)이고 모델 가중치는 결정적이라 **분산의 원천은 스트림(문서) 표집뿐**입니다. 재계산은 비용 때문에 스트라이드 위치(Pythia-160M은 t ≡ 127 mod 128, 나머지는 t ≡ 63 mod 64)에서만 재서, 재계산과의 비교는 모든 방법을 같은 위치로 줄여 합니다.
- **장치**: Pythia-14M/70M, GPT-2(T=1024)는 MPS에서, Pythia-160M과 GPT-2(T=2048)는 CPU에서 float32로 돌렸습니다(실행 중 MPS가 멈춰 CPU로 옮김). 가중치는 같고 장치만 다릅니다. 총 연산은 이 맥에서 수십 분입니다.
- **한계**: 구간별 perplexity는 서로 다른 위치 범위라 비교할 수 없습니다(초반 위치는 문맥이 없어 perplexity가 높음. `pre`가 `post`보다 큰 이유). 비교는 항상 **같은 위치에서 방법 간**으로만 합니다. 데이터는 PG19가 아니라 Pile(웹, 코드, 논문 등 혼합)이고 문서 경계가 스트림 안에 평균 몇 개 있습니다.

- 재계산은 윈도 안의 모든 층 은닉 상태를 윈도 안 토큰만으로 다시 만든다는 점에서 StreamingLLM(과거 문맥이 반영된 캐시된 K/V)과 다릅니다. 그런데도 값이 같다는 것이 이 방법의 놀라운 점입니다.

논문 표 1(5.40 대 5.60, Llama-2-13B)처럼 **싱크의 내용이 아니라 위치가 중요**하다는 해석과 맞습니다. 우리 모든 설정(위 표와 GPT-2 순번 위치 3개 포함)에서 줄바꿈으로 바꾼 쪽이 원문 처음 토큰과 ±0.032 nat 안입니다. 단 이 실험은 "처음 토큰의 입력만" 바꾸고 이후 모든 토큰의 은닉 상태가 그에 영향을 받으므로, "싱크 키의 의미가 필요 없다"의 직접 증명은 아닙니다.

### 3.4 위치 처리: RoPE의 캐시 안 순번과 GPT-2의 절대 위치

**(a) RoPE에서 질의 위치를 캐시 안 순번 대신 원래 위치로 두면** (`ablate_sink_pos.py`, C=512, 싱크 키는 위치 0..s−1 그대로):

| 모델, s | 캐시 안 위치(논문) `mid`(t < 2048) / `late`(t ≥ 2048) | 질의를 원래 위치 t로 `mid` / `late` |
|---|---|---|
| Pythia-70M, 4 | 16.39 / 9.94 | 16.41 / **18.96** |
| Pythia-160M, 4 | 11.63 / 7.35 | 11.75 / **122.4** |
| Pythia-160M, 1 | 11.76 / 7.47 | 11.93 / 9.87 |

- 논문 3.2절의 "캐시 안 위치가 결정적"은 **사전학습 문맥(2048)을 넘는 구간에서만** 결정적입니다. t < 2048이면 질의-싱크 거리가 사전학습에서 본 범위 안이라 차이가 1% 안팎(11.63 대 11.75)입니다. t ≥ 2048이면 거리가 학습 범위를 넘어 Pythia-160M은 7.35 → 122로 무너집니다(17배). 즉 위치 재배정은 sink 메커니즘이라기보다 **길이 외삽 문제의 해결**입니다.
- 윈도 키의 상대 거리는 두 경우 모두 t−j로 같으므로(RoPE의 상대성, 테스트로 확인) 바뀌는 것은 질의-싱크 거리뿐입니다. 이 경우 싱크가 학습 때와 다른 거리(2048 초과)에 보입니다.

**(b) GPT-2(학습된 절대 위치)**: 위치 임베딩이 입력에 더해져 K와 V에 굳기 때문에 캐시 안 순번으로 "다시 매길" 수 없습니다. 가능한 것은 둘뿐입니다.

- `orig`: 각 토큰이 처음 들어갈 때의 원래 위치를 유지. 길이 1024(위치 표 크기)를 넘으면 불가능합니다(테스트로 확인).
- `slot`: 넣을 때의 순번 min(t, C−1)을 위치로 사용(우리 제안, 논문에 없음). 캐시가 찬 뒤 새 토큰은 모두 위치 C−1을 받습니다.

| GPT-2, C = 256 | 0+C | 1+(C−1) | 4+(C−4) | 재계산(스트라이드) |
|---|---|---|---|---|
| `orig`(T = 1024) | 805 | 20.1 | 19.5 | 12.7 |
| `slot`(T = 1024) | 835 | 138.7 | 139.2 | 12.7 |
| `slot`(T = 2048, `late` 구간) | 3316 | 610 | 597 | 15.4 |

- 원래 위치(≤ 1024)에서는 RoPE 모델과 같은 그림입니다(싱크 1개가 폭발을 막음). `slot`에서는 싱크가 폭발은 막지만(835 → 139) 정상 수준(12.7)에서 7–10배 멀고, T=2048에서는 더 나빠집니다. 새 토큰이 모두 같은 위치 임베딩을 받아 윈도 안의 순서 정보를 잃기 때문으로 보입니다(원인 실험은 하지 않음, 추측).
- 결론: **StreamingLLM은 위치를 attention 계산 시점에 붙이는 모델(RoPE, ALiBi)을 전제로 한다**는 것을 확인했습니다. 절대 위치 모델에서는 캐시 안 K/V를 재계산해야 하고, 그러면 이 방법의 이득이 사라집니다.

**(c) 사전학습 문맥을 넘는 dense**: Pythia의 dense perplexity는 t ≤ 2048에서 11.99(160M), 17.07(70M), 30.66(14M)이고 t > 2048에서 384, 83, 148입니다. 논문의 "dense는 사전학습 길이를 넘으면 실패한다"(그림 3)가 우리 모델에서도 성립합니다(`own_streaming_curves.png`).

### 3.5 윈도만 폭발의 크기와 sink 강도

이 저장소의 `attention_sink_emerges` 분석이 같은 모델·데이터로 잰 "처음 위치가 받는 head 평균 attention α₁"(T = 1024, 문서 200개; 균일 기준선 0.0073)은 Pythia-14M 0.017, 70M 0.029, 160M 0.073, GPT-2 0.355입니다. 윈도만/4싱크 perplexity 비는 1.33, 1.09, 1.34, 5.11배(C = 512)입니다.

- GPT-2가 sink가 가장 강하고(α₁ 0.355) 폭발도 가장 큰 것은 방향이 맞습니다. 그러나 Pythia 세 모델 사이에서는 α₁ 순서(14M < 70M < 160M)와 폭발 크기 순서(70M < 14M ≈ 160M)가 같지 않습니다. Spearman ρ = 0.8이지만 n = 4이고 모델군이 섞여(RoPE 대 절대 위치) 순서 확인 이상의 의미는 없습니다(`sink_alpha_link.py`).
- 설명하지 못한 것: Pythia-70M에서만 폭발이 유독 작음. 이 모델의 α₁(0.029)이 160M(0.073)보다 낮은 것과 방향은 같지만 14M(0.017)과는 맞지 않습니다.

## 4. 사전학습 싱크 토큰: 아주 작은 토이 (`sink_token_toy.py`)

3.3절의 주장(사전학습 때 모든 샘플 앞에 학습 가능한 싱크 토큰 하나를 붙이면 그 토큰 하나만 남겨도 스트리밍이 안정)을 **아주 작은 규모**에서 시험했습니다. 논문(Pythia-160M, 143K 스텝, 8×A6000)과는 비교할 수 없는 토이이며, 결과는 음성입니다.

- 설정: 바이트 수준(어휘 256 + 싱크 토큰 1개) 4층, d = 128, 4 head, RoPE 16차원, 약 0.8M 파라미터. pile-10k의 앞 9000문서(55.6M 바이트)로 1200스텝, 배치 32, 입력 길이 128, AdamW(학습률 2e-3, 코사인). vanilla는 무작위 바이트 조각을, sink는 그 조각 앞에 학습 가능한 싱크 토큰(id 256)을 붙인 입력(길이 128: 싱크 + 127바이트)을 학습합니다(예측 대상 128개로 같음). 시드 2개(0, 1), 두 변형은 같은 초기화·같은 배치 순서. CPU, 총 약 9분.
- 평가: 학습에 안 쓴 문서(인덱스 9000 이상)를 이은 길이 512 스트림 32개(문서 첫머리에서 시작). sink 모델의 스트림 앞에는 싱크 토큰을 붙입니다. 캐시 C = 64, 구성 x+(64−x), x = 0, 1, 2, 4, 8.

| 변형, 시드 | 학습 손실 | 0+64 | 1+63 | 4+60 | 8+56 | 첫 토큰이 받는 attention(층 0–3 평균, t ≥ 64) |
|---|---|---|---|---|---|---|
| vanilla, 0 | 1.727 | 6.373 | 6.368 | 6.363 | 6.360 | 0.0098, 0.0010, 0.0027, 0.0012 |
| vanilla, 1 | 1.844 | 6.246 | 6.245 | 6.250 | 6.256 | 0.0100, 0.0018, 0.0024, 0.0009 |
| sink, 0 | 1.728 | 6.336 | 6.333 | 6.331 | 6.329 | 0.0212, 0.0005, 0.0004, 0.0018 |
| sink, 1 | 1.845 | 6.286 | 6.282 | 6.288 | 6.293 | 0.0198, 0.0084, 0.0018, 0.0011 |

- **이 규모에서는 싱크가 아예 생기지 않았습니다.** 윈도만(0+64)과 싱크 8개의 perplexity 차이가 0.5% 이내이고(구간 [5.7, 7.1]은 스트림 부트스트랩, 변형 간 차이보다 훨씬 넓음), 첫 토큰이 받는 attention 질량은 균일 기준선(약 1/100)과 구분되지 않습니다. 두 변형이 같은 값이라 "싱크 토큰이 있으면 1개만 남겨도 된다"를 시험할 수 없었습니다(vanilla가 이미 윈도만으로 괜찮음).
- 이는 `attention_sink_emerges`의 토이(0.7M, softmax에서도 sink 없음)와 같은 결과입니다. 그쪽 분석은 데이터 양, 학습 시간이 sink 출현의 조건이라고 보고했으므로, 우리 토이는 **조건 미달**(1200스텝, 바이트 수준, 55M 바이트를 1회도 못 돎)로 읽어야 하고 논문 3.3절에 대한 증거도 반증도 아닙니다.
- 따라서 3.3절·표 3·표 4는 이 맥에서 확인하지 못했습니다(`04` C7). 가능한 다음 단계는 제안으로만: Pythia-160M급 사전학습은 GPU가 필요해 하지 않고, 이 토이를 더 크게(층·스텝) 키우는 것은 CPU·MPS로 가능합니다.

## 5. 요약

- 롤링 KV 캐시(싱크 + 윈도, 캐시 안 위치)는 소형 RoPE 모델에서 재계산 기준선과 2% 안으로 같고, 윈도만 쓰는 것보다 항상 낫습니다(24개 스트림 전부).
- 폭발의 크기는 모델이 정합니다(1.1배–2000배). "4개"는 Llama-2에서의 값이고 우리 모델에서는 1개로 대부분 충분합니다.
- 위치 재배정은 사전학습 문맥을 넘는 구간에서만 결정적이며, 절대 위치 모델(GPT-2)에서는 쓸 수 없어 방법이 성립하지 않습니다.
- 논문 표 2와 6의 Falcon-7B 값이 서로 다르고, 표 3은 표본 1개이며, 표 4는 표본 오차 안입니다.
