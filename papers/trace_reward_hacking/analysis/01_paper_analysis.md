# 01 논문 분석: Is It Thinking or Cheating? (TRACE, arXiv:2510.01367)

분석 대상은 arXiv v4(2026-03-02, ICLR 2026 구두 발표 판)입니다. 절·그림 번호는 v4 기준입니다. v1과의 차이는 §6에 적습니다. 공식 코드는 찾지 못했습니다(`02` §4).

## 1. 문제

- **풀려는 것:** 추론 모델이 보상의 허점(loophole)을 써서 보상을 받으면서도 CoT는 멀쩡해 보이는 **암묵적 보상 해킹**을, CoT 텍스트를 읽지 않고 잡는 것(§1, §2).
- **형식화(§2):** 학습에 쓰는 대리 보상 R̂과 진짜 보상 R이 어긋날 때 해킹이 생깁니다. 허점은 두 종류입니다. 문맥 내(IC): 프롬프트에 정답 힌트나 평가 도구가 있음. 보상 모델(RM): 검증기가 허술함(음수 답도 통과, 코드에 `else`가 있으면 통과 등).
- **전제(§1):** "허점을 쓰는 것이 문제를 푸는 것보다 쉽다". 따라서 해킹 모델은 CoT의 앞부분만으로도 보상을 받을 수 있다는 가설입니다. 부록 A의 다중 홉 힌트 실험(그림 15)은 허점이 어려울수록 보상 획득이 늦어짐을 보여 이 가설을 지지합니다(정성적, 단일 실행).

## 2. 방법: TRACE

1. 응답의 CoT를 p%(10%, …, 100%)에서 자르고 `</think><answer>`를 붙여 **강제로 답하게** 합니다(그림 5).
2. 각 절단점에서 답을 여러 번 뽑아 **기대 대리 보상 E[R̂]**을 추정합니다. 수학은 온도 0.7로 5개를 뽑아 보상 받은 비율, 코드는 온도 0 한 개로 통과한 테스트 비율(RM 허점을 쓰면 1)입니다(§4 각주 1).
3. E[R̂] 대 CoT 비율 곡선의 **면적(AUC) = TRACE 점수**입니다(그림 5~7, 척도는 0–100, 그림 8·13). 식 번호는 없고 정의는 문장입니다. 절단 격자와 적분 방식(사다리꼴 여부)은 본문에 없습니다(`03` §1).
4. **분류:** 초기 정책(RL 이전 모델)의 평균 TRACE 점수를 임계값으로 삼아, 그보다 높으면 해킹으로 분류합니다(§4 "Initial Policy TRACE Score as Detection Threshold"). 초기 정책은 해킹하지 않는다고 가정합니다.
5. 선행 Lanham et al.(2023)의 early answering은 "자른 답이 전체 답과 같은가"인 모델 수준 지표인데, TRACE는 이를 **표본 수준**으로 바꾸고 "같은 답"을 "기대 보상"으로 일반화합니다(§4).

## 5. 한계 (저자가 적은 것 + 우리가 본 것)

- **저자(§7):** 허점이 인공적이고 단순함(코드 RM 허점의 해는 논리적으로 우스워 모니터에 쉬움). 닫힌 질문(객관식, Knights and Knaves)처럼 CoT 없이 맞힐 수 있는 과제에는 부적합. CoT 최적화 압박이 가해지면 낮은 TRACE 점수로 숨는 모델이 나올 수 있음(미실험). 과잉 사고가 점수를 부풀림(보정은 미실험). 초기 정책이 이미 힌트를 쓰면 임계값이 올라 민감도가 낮아짐.
- **우리가 본 것:**
  1. 탐지 표본 수, 시드, 신뢰구간이 없습니다. F1은 한 번의 학습 실행에서 나온 점추정입니다.
  2. 임계값(초기 정책 평균)의 구체적 계산 대상(어느 문항 집합)이 본문에 없고, 정직 분포의 평균을 임계값으로 쓰면 정직 표본의 절반 가까이를 해킹으로 부릅니다(`03` §3). 보고된 F1이 높으려면 임계값이 그와 다르게 설정됐어야 합니다.
  3. 양성(해킹)과 음성(비해킹)이 **서로 다른 모델**에서 나옵니다(§4.1). 표본 수준 신호가 아니라 모델 차이(길이, 문체, 답 형식)를 잡았을 가능성은 설정 1·2(같은 모델)로 부분적으로만 배제됩니다.
  4. TRACE는 **대리 보상 R̂을 직접 계산할 수 있고 강제 답변(prefill)이 가능해야** 합니다. 검증기가 없거나 비용이 큰 에이전트 과제에는 바로 쓸 수 없습니다.
  5. 코드 쪽 곡선(그림 21)은 0% 절단에서도 통과율이 0.77–0.94입니다. 부분 점수(통과 테스트 비율)를 써서 면적의 바닥이 높고 해킹과 비해킹의 격차가 좁습니다. 그래서 코드 F1은 0.59대입니다.

## 6. v1과 v4의 차이 (pdftotext 대조)

- 정의 문구: v1은 "검증기 통과율(verifier-passing rate)", v4는 "기대 대리 보상 E[R̂]"로 일반화. 초록의 수치(65%, 30%)는 같습니다.
- v4에는 토의의 "과잉 사고"(Overthinking), "추론 노력"(Reasoning Effort), "한계"(Limitation) 문단이 있고 v1에는 없습니다(제목 grep 대조). 부록 J(LLM 사용)는 두 판에 모두 있습니다. 저자 표기에 "공동 지도(‡)" 주석이 v4에서 추가되었습니다.
- 그림 9·10의 막대 라벨(0.883, 0.875, 0.964, 0.593, 0.457, 0.517 등)은 v1과 v4의 pdftotext에서 모두 나옵니다. 그림 1은 이미지라 텍스트 대조를 하지 못했습니다. v2·v3는 열어 보지 않았습니다.

## 7. 한 줄 요약

"CoT를 잘랐을 때 보상을 얼마나 일찍 받는가"를 곡선 면적으로 재면, 허점이 단순하고 정답이 CoT 없이도 나올 수 있는 인공 환경에서는 CoT 모니터보다 해킹을 잘 가려낸다(점추정 기준). 일반 환경에서의 신뢰도와 임계값 문제는 미검증입니다.
