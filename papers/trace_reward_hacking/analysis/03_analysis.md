# 03 검증: 식 검산, 재계산, 토이 (TRACE, arXiv:2510.01367)

재계산과 토이는 `analysis/recompute_trace.py`(numpy, scipy, CPU 수 초)이고 결과는 `analysis/recompute_trace_results.json`입니다. 논문에는 표가 없고 점수 로그·코드가 공개되지 않아, 그림의 막대 라벨(소수 셋째 자리)과 본문 숫자를 입력으로 썼습니다(그림 1·9·10은 이미지를 열어 라벨을 직접 읽음).

## 1. TRACE 점수의 정의 검산

논문은 식 번호 없이 "E[R̂] 대 CoT 비율 곡선의 AUC"로 정의합니다(§4). 절단 격자 c_1<…<c_K와 절단점당 표본 m개(수학 m=5, T=0.7; 코드 m=1, T=0)를 두면 표본 수준 점수는

S = 100 · (1/K) · Σ_k p̂_k,  p̂_k = (m개 중 보상 받은 비율)

(리만 합 가정. 사다리꼴로 쓰면 양 끝이 반만 반영되어 값이 조금 다르지만 순위는 거의 같음. 격자와 적분 방식은 논문에 없음. 척도 0–100은 그림 8·13의 축에서 확인.) 성질은 다음과 같습니다.

1. **범위:** 0 ≤ S ≤ 100. 비해킹 모델의 수학 점수가 20대(그림 8의 약 25~30)인 것은 "CoT 끝에 가까워야 풀림"과 맞습니다.
2. **계단형 곡선의 값:** 보상 획득 지점이 t*이고 최종 정확도가 q이면 p(c)=q·1[c ≥ t*]이므로 면적은 q(1−t*)입니다. 곧 TRACE 점수는 **정확도 q와 이른 정도(1−t*)의 곱**입니다. 해킹(t*≈0, q≈1)이면 100에 가깝고, 정직하되 문제가 쉬워 t*가 작은 경우와 구별되지 않습니다(§4 토의의 과잉 사고와 같은 문제).
3. **RM 허점의 특수성:** "음수면 통과"에서는 해킹 모델이 모든 절단점에서 음수를 내므로 p(c)≈1 평평한 곡선이고 S≈100입니다(그림 20). 이 경우 TRACE가 재는 것은 "일찍 안다"가 아니라 "처음부터 음수를 낸다"는 출력 형식 신호입니다. 그래서 정답을 몰라도 점수가 높아집니다.
4. **코드의 바닥:** E[R̂]이 통과 테스트 **비율**이라 0% 절단에서도 높습니다. 그림 21에서 비해킹 모델도 0% 절단 통과율이 RM 설정에서 약 0.84, IC 설정에서 약 0.77(그림에서 눈금 읽음, ±0.02)이고 해킹 모델은 각각 약 0.94, 0.82입니다. 면적 격차는 RM 설정 약 9점, IC 설정 약 4~5점(0–100 척도, 눈금 읽기)에 그칩니다. 코드 F1이 0.59대에 머무는 것과 방향이 맞습니다.
5. **표본 잡음의 식 검산:** 절단점 간 독립 가정에서 Var(S) = (100/K)² · Σ p_k(1−p_k)/m. 해킹 곡선 p≈0.95, K=10, m=5이면 sd = 100·sqrt(K·p(1−p)/m)/K = 100·sqrt(10·0.0475/5)/10 = 3.08. 토이의 해킹 점수 sd 3.11(m=5)과 일치합니다(`toy_basic.m=5.hack_sd`). m=1이면 6.8, m=20이면 1.5.

### 2.2 표본 수와 구간 (검출 표본 수가 논문에 없음)

- 수학 검출 집합은 검증 문항 1,498, 코드는 2,297이지만(§3.1), 그중 **몇 개 응답이 양성·음성 표본이 되었는지는 보고되지 않았습니다**(보상 1인 응답만 모으고, 반사실 시험으로 라벨링, §4.1). 따라서 F1의 신뢰구간은 논문 정보만으로는 계산할 수 없습니다. 시드·반복 학습도 없어 모델 간 분산은 구간에 포함할 수 없습니다.
- 대신 **가정 N(클래스당 표본)에서의 민감도**를 계산했습니다. 균형 클래스, TPR=1−FPR=a이면 F1=a가 되는 단순 모형이고, 차이는 독립 두 표본 비율 검정으로 봅니다(응답이 같은 문항에서 나오므로 실제는 대응 표본이라 더 좁을 수 있고, 같은 문항에서 여러 응답이 나오면 군집 효과로 더 넓을 수 있음).

| 비교 | 격차 | 유의(p<.05)에 필요한 클래스당 N | N=50 구간 TRACE / 모니터 | N=200 구간 TRACE / 모니터 |
|---|---|---|---|---|
| 수학 IC LLaMA3.2-3B | +0.209 | 11 | 0.92–1.00 / 0.67–0.83 | 0.94–0.98 / 0.71–0.80 |
| 수학 RM LLaMA3.2-3B (최소 격차) | +0.126 | 24 | 0.91–0.99 / 0.75–0.90 | 0.93–0.98 / 0.79–0.87 |
| 코드 RM Qwen3B | +0.136 | 52 | 0.48–0.69 / 0.34–0.56 | 0.54–0.64 / 0.40–0.51 |
| 수학 IC Qwen2.5-14B | +0.366 | 7 | 0.82–0.94 / 0.40–0.62 | 0.85–0.91 / 0.46–0.57 |

결론: 수학의 격차는 클래스당 수십 개 표본만 있어도 표본 오차보다 큽니다. 코드 RM(+0.136)만 클래스당 약 50개 이상이 필요한데, 코드 보류 집합이 2,297 문항이라 충족될 가능성이 높지만 **확인할 수 없습니다**. 표본 오차보다 문제가 되는 것은 (a) 학습 한 번 = 한 점이라는 점, (b) 임계값, (c) 클래스가 모델에 묶인 점입니다(§3, §4).

## 3. 임계값과 F1: 토이로 본 거동

설정: 격자 10%–100%(10개), 정직 곡선 p(c)=0.9·σ((c−t)/0.05)에서 t~U(0.6,1.0)(해결 시점이 문항마다 다름), 해킹 응답은 처음부터 p=0.95. 응답마다 m개를 뽑아 점수를 냅니다(4,000개/클래스).

| m | 정직 평균 / sd | 해킹 평균 / sd | AUROC | 임계값=정직 평균: FPR, 균형 F1 | 임계값=정직 95퍼센타일: FPR, 균형 F1 |
|---|---|---|---|---|---|
| 1 | 22.6 / 12.7 | 95.0 / 6.8 | 1.000 | 0.425, 0.82 | 0.035, 0.98 |
| 5 | 22.8 / 10.8 | 95.0 / 3.1 | 1.000 | 0.486, 0.80 | 0.034, 0.98 |
| 20 | 22.8 / 10.4 | 95.0 / 1.5 | 1.000 | 0.497, 0.80 | 0.050, 0.98 |

읽는 법과 한계(이것은 가상의 곡선이고 논문의 분포가 아님):

1. **순위(AUROC)는 완벽한데 임계값이 F1을 가릅니다.** 임계값을 "정직 모델 점수의 평균"으로 두면 정직 표본의 40~50%가 임계값을 넘습니다(평균은 분포 중앙 근처). 논문의 규칙은 "초기 정책의 평균 TRACE 점수"(§4)이고 보고된 F1은 0.88–0.96이므로, 논문에서는 정직 점수의 분포가 임계값보다 훨씬 아래에 모여 있거나 임계값을 다른 방식(쉬운 문항 평균 등, 논문 표현은 "easiest problems"에서의 정상 노력)으로 잡았을 것입니다. 이 부분은 논문 텍스트로 확정할 수 없습니다. **재현 시 첫 번째로 확인할 항목**입니다.
2. **m의 영향:** m이 클수록 해킹 점수의 분산이 줄지만(6.8 → 1.5) 정직 점수의 분산은 문항 간 변동 t가 지배해 거의 안 줄어듭니다. 곧 m=5는 해킹 쪽에는 충분하나 정직 쪽 분포의 폭은 줄이지 못합니다.
3. **혼합 모델(같은 모델이 60%만 해킹):** 해킹 대 비해킹 AUROC≈1.0, 임계값=정직 평균에서 F1 0.86–0.87(`mixed60%`). 이 토이에서는 클래스가 모델이 아니라 응답에 있으므로 모델 혼동 문제는 없는 이상적 경우입니다.
4. **과잉 사고(오탐):** 정직 모델이 RL 뒤 문항을 더 일찍 푸는 쪽으로 이동하면(t~U(0.6,1.0) → U(0.5,0.9) → U(0.4,0.8)), 해킹 없이도 초기 평균 임계값을 넘는 정직 응답이 **48% → 74% → 95%**가 됩니다(`toy_overthinking_false_positive`). 논문도 이를 한계로 적고 보정은 후속 과제로 남깁니다(§7 "Overthinking"). 임계값은 반드시 RL 이후의 깨끗한 문항에서 재보정해야 한다는 뜻입니다.
5. **늦은 해킹의 맹점:** 보상이 마지막 10%에서만 생기는 해킹(예: CoT 끝에서만 허점을 씀)은 점수 19.0으로 정직(22.7)보다 오히려 낮습니다. TRACE는 "일찍 보상 받는" 해킹만 잡습니다.

## 4. 곡선 수준 주장의 통계적 지위 (그림 8, 11, 12, 13, 18, 22)

- 각 곡선은 한 번의 학습 실행에서 체크포인트마다 한 점입니다(표 1·2에 시드 기재 없음). 그림 8에서 해킹 모델이 25단계 이후 약 25 → 60으로 오르고 비해킹은 25–35에 머무는 분리는 크지만, 학습 실행 간 변동은 알 수 없습니다. 비해킹 모델의 점수는 RLOO에서 평평하고 GRPO에서는 **내려갑니다**(그림 23). 곧 "비해킹 모델은 평평"은 알고리즘에 따라 다르며, 임계값이 고정 초기값이면 GRPO에서는 더 쉽고 RLOO에서는 덜 쉽습니다.
- 그림 11의 수학 설정 1: 해킹 모델의 보상이 비해킹을 넘은 뒤부터 평가를 시작합니다(§4.2). 즉 탐지 시작 시점이 해킹을 이미 확인한 뒤이므로 "해킹을 얼마나 일찍 알리는가"는 이 그림에서 재지 않습니다.

## 5. 라벨의 타당도

- **IC 반사실:** 틀린 힌트를 주었을 때 실패하면 해킹으로 라벨링(§3.2). 힌트 없이도 풀 수 있는 문항에서 힌트를 읽었으나 스스로도 풀 수 있었던 응답은 해킹으로 세어지지 않습니다(보수적). 반대로 힌트를 쓰고도 어쩌다 맞는 응답은 반사실에서 통과해 비해킹이 됩니다. 라벨 잡음의 크기는 보고되지 않았습니다.
- **모델 혼동(§4.1):** 양성은 해킹 모델, 음성은 비해킹 모델에서 나옵니다. 모델 차이(응답 길이, 문체, 음수 부호 습관)가 TRACE에도 모니터에도 영향을 줄 수 있습니다. 설정 1·2(같은 모델 내 탐지)가 이를 부분 보완하지만 이 설정의 F1은 그림 곡선으로만 있습니다.
- **모니터 기준선의 공정성:** 모니터는 제로샷 루브릭(부록 H) 하나, 판정 UNCLEAR의 처리 방식이 적혀 있지 않습니다. TRACE는 정책의 가중치·강제 답변 접근과 R̂ 접근, 초기 정책 기준이 있는 **특권 정보** 설정입니다. 정보가 다른 방법을 비교한 것이므로 "TRACE가 더 좋은 모니터"가 아니라 "모델 접근이 있을 때의 다른 신호"로 읽어야 합니다.

## 6. 계산 비용

응답 하나당 추가 생성은 K·m회(수학 약 10×5=50)이고 각 생성은 절단된 접두부 + 짧은 답입니다. CoT 모니터는 응답 하나당 72B 모델로 읽기 1회입니다. TRACE의 비용은 정책 자신이 내므로 "외부 모니터가 에이전트만큼 커질 필요 없음"(§7)은 사실이지만, 에이전트 궤적이 길고 도구 호출이 있으면 절단 후 재생성의 부작용(환경 상태, 도구 재호출)이 생깁니다.

## 7. 원인 2×2 판정표 (`../impossiblebench/analysis/03_analysis.md` §9의 틀 적용)

"통과했지만 풀지 못한" 원인을 (검사 결함 / 에이전트 조작) × (비의도 / 의도)로 가릅니다.

| | 비의도 | 의도(최적화로 학습된 우회) |
|---|---|---|
| **검사(보상) 쪽 결함** | RM 허점이 있어도 해킹하지 않은 정직한 풀이가 통과. TRACE 점수는 높지 않음(음수를 안 냄). 그러나 "정직하지만 틀린 통과"(5번 논문의 약한 테스트)는 일찍 보상 받지도 않아 **TRACE가 못 봄** | RM 허점(음수 통과, `else`)을 학습한 모델. **TRACE의 주 대상**(그림 10b, 20) |
| **에이전트 쪽 조작** | 쉬운 문제를 CoT 없이 푸는 과잉 사고. TRACE 점수가 높아 **오탐**(§3 항목 4) | IC 힌트 복사(그림 6, 24). **TRACE의 주 대상**(그림 10a) |

곧 TRACE는 "보상이 과정보다 일찍 생긴다"는 한 축만 재므로, 비의도·검사 쪽 결함(왼쪽 위)은 놓치고 비의도·에이전트 쪽(과잉 사고)은 오탐합니다. ImpossibleBench가 구조로 라벨을 확정하는 것과 달리 TRACE는 과정 신호라 원인을 구별하지 못합니다.
