# 04. 주장 검증 (공식 코드 없음)

공식 코드, 캐시 예시, 문항별 결과, 변형 데이터가 공개되어 있지 않아(`02` §5) 코드 대조(D) 대신 **주장 검증(C)** 을 합니다. 검증 수단은 논문 표 2·부록 C의 재계산(`03`), 통계 검정, 논문 본문의 설계 서술 대조입니다. 코드나 모델은 실행하지 않았고 API 호출도 하지 않았습니다. 분석일 2026-11-26.

판정 표기: **재계산 일치**(표의 수치가 다시 나옴) / **지지**(증거가 주장을 뒷받침) / **부분 지지**(좁은 범위에서만) / **근거 부족**(증거가 없거나 약함) / **검증 불가**(공개 자료로 확인할 수 없음).

## 2. 가장 중요한 세 가지

1. **C Acc와 교란은 보지 않은 문항의 증거가 아닙니다 (C5, C7).** 구축이 평가 문항과 정답 라벨을 쓰고, 교란 정답은 원본 모델 계열이 만들었습니다. 이 논문에서 "새 입력에서 맞는가"를 직접 잰 값은 없습니다.
2. **조용한 오답과 적용률이 없습니다 (C12).** 그림 1의 폴백은 미적중·오류만 잡습니다. 캐시가 자신 있게 틀린 답을 내는 비율(우리 모형에서 감지기 없이 재등장 질의의 약 12%, `03` §6.2)과 감지기가 있을 때의 효과가 이 논문에서 가장 비어 있는 부분입니다.
3. **16–291배는 단가 비율입니다 (C1).** 캐시 호출이 더 많은 토큰을 씁니다. 이 숫자는 "비싼 원본 모델 대신 1B 모델의 토큰 값을 낸다"의 효과와 "코드 캐시 덕분에 작은 모델이 같은 정확도로 풀 수 있다"의 효과를 섞고 있고, 후자는 같은 1B 모델의 직접 풀이 정확도(기준선)가 없어 분리되지 않습니다.

## 3. 재현이 필요하다면 (제안만 함, 실행 안 함)

논문 규모 재현은 비용이 큽니다. 논문 표 2의 문항당 총비용(부록 C, 원본+빌더+캐시)에 알려진 문항 수를 곱하면 MATH-500 약 610달러, AIME 3개년 약 143달러, GPQA Diamond 약 366달러, GSM8K 테스트 1,319문항 약 1,133달러로 **알려진 칸만 약 2,250달러**입니다(MMLU-Pro, SciBench와 교란 생성·판정자 비용 제외). 공식 구축 코드가 없어 파이프라인(Sec 2.2.1의 5단계 프롬프트, `Context`와 프리미티브)을 직접 짜야 합니다.

**가장 값싸게 C5·C6·C12를 가르는 소규모 설계**(승인이 필요함, API 호출과 비용 발생):

- **P1 (라벨 누출 대조).** AIME 2025 30문항, 같은 빌더로 (a) 정답 라벨을 시험에 쓰는 구축과 (b) 전사만 쓰는 구축을 나눠 C Acc를 비교. 두 값 차이가 "라벨 접근"의 몫입니다. 문항당 약 1.5달러이므로 60구축 약 90달러(논문 단가 기준, 현재 모델과 단가는 다를 수 있음).
- **P2 (보류 문항 시험).** 구축 문항과 다른 문항(같은 대회 다른 문제)을 캐시에 넣어 오적중률과 조용한 오답률을 측정. 질의 수백 건에 CPU 호출은 거의 무료이지만 빌더 호출 비용이 듦.
- **P3 (기준선).** 같은 1B·Haiku급 모델이 원본 문항을 직접 푼 정확도와 비용을 측정해 "코드 캐시의 몫"과 "싼 모델의 몫"을 분리. 직접 푸는 호출은 저렴(문항당 센트 단위).

이 맥(CPU·MPS)에서 가능한 것은 캐시 실행기(의미 함수 런타임과 FAISS)의 토이 구현과 CPU 지연 측정이고, 가중치를 받아야 하는 1B 실행은 모델 다운로드(수 GB 미만이지만 사전학습 가중치이므로 승인)가 필요합니다.

## 4. 인용에 쓸 수 있는 것과 없는 것

- 쓸 수 있음: 설계 아이디어(전사 → 의미 함수 코드, 설명으로 검색하는 함수 호출), 구축비와 호출 단가를 분해해 보고한 방식, 표 2의 비용 수치(재계산 일치, 조건 표기).
- 단서가 필요함: 정확도 "대등"(구축 문항 위의 점추정, 문항 수가 작은 칸은 동등성 불가), 교란 견고성(분모·외부 정답 없음), 16–291배(호출 1회 단가 환산).
- 쓰면 안 됨: "새 문제에서 원본만큼 맞는다", "미적중 시 안전하다", "CPU에서 빠르다", "계속 학습해도 성능이 유지된다".
