# 02. 선행 연구와 관계

분석일 2026-11-26. 논문(arXiv:2611.09891 v1)이 인용한 것과 우리가 보태 읽은 것을 구분했습니다. 이 절의 선행 연구는 대부분 초록·README 수준으로 읽었고(웹 검색 0회, arXiv API와 `gh api`로 메타데이터만 확인), 본문을 정독한 것은 표시했습니다.

## 1. 한 줄 위치

"풀이를 찾는 모델과 풀이를 실행하는 모델을 분리하고, 풀이를 **실행 가능한 프로그램**으로 저장한다"는 점에서 프로그램 보조 추론(PAL, PoT) + 도구·기술 라이브러리(LATM, Voyager) + 재사용 가능한 사고·워크플로 저장(Buffer of Thoughts, AWM) + 의미 캐시(GPTCache)의 교차점에 있습니다. 새로운 것은 (a) **풀이 생성기(LLM)와 저장 형식(프로그램)을 문제 하나의 전사에서 자동으로 만드는 파이프라인**, (b) 변수 이름이 아니라 자연어 설명으로 함수를 찾는 의미 함수, (c) 원본 모델 대비 호출 비용 배수의 보고입니다. 새롭지 않은 것은 "풀이를 코드로 바꿔 쓰면 정확하고 싸다"는 관찰 자체입니다(PAL, 2022).

## 2. 계보

### 2.1 프로그램으로 추론하기

- **PAL** (Gao et al., arXiv:2211.10435): 추론 단계를 파이썬 코드로 쓰고 인터프리터가 계산하게 해 산술 실수를 없앱니다. ARC의 "캐시가 결정적 코드로 실행되어 원본의 계산 실수를 피한다"(3.6절 Correctness)는 설명은 PAL의 논지와 같습니다.
- **Program of Thoughts** (Chen et al., arXiv:2211.12588, TMLR 2023): 추론과 계산을 분리해 계산을 코드에 맡깁니다. ARC와의 차이: PAL·PoT는 **문제마다 코드를 새로 생성**하고, ARC는 **한 번 생성한 코드를 같은 종류의 새 입력에 재사용**합니다. 즉 재사용(amortization)이 새 점입니다.

### 2.2 풀이·기술·워크플로 재사용

- **Voyager** (Wang et al., arXiv:2305.16291): 실행 코드로 된 기술 라이브러리를 임베딩 검색으로 불러 쓰고 점진적으로 늘립니다. 의미 함수가 "설명으로 검색해 호출"하는 구조의 직접 선조입니다.
- **LLM as Tool Makers (LATM)** (Cai et al., arXiv:2305.17126): 강한 모델이 도구(파이썬 함수)를 만들고 약한 모델이 쓰는 비용 비대칭 구조가 ARC의 𝒮/ℬ 대 𝒯 분리와 같습니다. 논문은 이를 인용하지 않습니다. 참고문헌 18개에는 PAL, PoT, Voyager, LATM, Buffer of Thoughts, AWM, FrugalGPT가 모두 없습니다(우리가 참고문헌 목록을 확인).
- **Buffer of Thoughts** (Yang et al., arXiv:2406.04271, NeurIPS 2024 스포트라이트): 문제에서 "사고 템플릿"을 추출해 버퍼에 두고 유사 문제에 인스턴스화합니다. ARC는 템플릿 대신 **실행 코드**를 저장한다는 점이 다르고, 논문은 BoT 계열을 "모듈형 캐시"라 부르며 "적중해도 LM 생성이 다시 필요하다"고 평합니다(Sec 1).
- **Agent Workflow Memory** (Wang et al., arXiv:2409.07429): 에이전트가 반복되는 워크플로를 귀납해 이후 생성을 안내합니다(Mind2Web, WebArena). 실행이 아니라 안내라는 점에서 ARC보다 약한 결합이고, 대신 도구 사용 에이전트 환경에서 검증됐습니다.
- **ADAS** (Hu et al., arXiv:2408.08435): 코드로 에이전트 구조를 탐색해 저장. 인용되지 않았습니다.

### 2.3 의미 캐시와 서빙 캐시

- **vLLM / PagedAttention** (Kwon et al., SOSP 2023): 접두사 KV 캐시. ARC가 말하는 "단일체 캐시"의 한 갈래이고 정확도 손실이 없습니다(같은 접두사일 때만).
- **GPTCache** (Bang, NLP-OSS 2023; `zilliztech/GPTCache`, MIT): 임베딩 유사도로 이전 응답을 돌려줍니다. 임계값을 낮추면 오적중(다른 질문에 이전 답)이 늘어난다는 점이 의미 캐시의 기본 위험이고, ARC는 이 약점을 "코드 안에서 값을 다시 추출·계산"해 피한다고 말하지만 **오적중 비율을 측정하지 않았습니다**(`03` §5).
- **Singh, 의미 캐싱 + 의도 기반 컨텍스트 최적화** (arXiv:2601.11687, 논문 인용 [5]): 표 형식 분석 질의를 파이썬 코드로 번역하는 다중 에이전트 시스템. 초록에 **적중률 67%(실제 질의), 의미 정확도 94.3%, 10,000건 이상 처리**가 있습니다. 실제 서비스 트래픽의 적용률 숫자가 보고된 드문 예이고 ARC의 적용률 c = 1 가정(`03` §6)과 대비됩니다(초록 수준).
- **ReasonCACHE** (arXiv:2602.02366, 논문 인용 [6]): 초록상 prefix tuning으로 시연을 고정 KV로 증류해 가중치 갱신 없이 추론을 배우게 하는 방법입니다. 논문은 이를 "추론을 요약해 다시 LM에 공급하는 모듈형 캐시"로 묶는데, 초록만 보면 학습된 KV 접두사에 가까워 분류가 느슨해 보입니다(초록 수준 의견, 본문 미확인).
- **Crystal-KV** (arXiv:2601.16986, 인용 [7]): CoT LLM의 KV 캐시 관리. ARC와 직접 경쟁하지 않는 서빙 계층 기술.

### 2.4 비용 절감 계통: 증류, 라우팅, 캐스케이드

- **증류**: 큰 모델 추론을 작은 모델에 가르칩니다(예: Distilling Step-by-Step, arXiv:2305.02301). ARC의 𝒯 파인튜닝(부록 D)은 증류지만 대상이 "추출·분류" 같은 초등 역할로 제한됩니다. ARC 본체는 **증류하지 않고 코드로 컴파일**한다는 점이 구별점입니다.
- **FrugalGPT**(arXiv:2305.05176)와 **RouteLLM**(arXiv:2406.18665, `lm-sys/RouteLLM`, Apache-2.0): 질의마다 모델을 고르는 캐스케이드·라우터. ARC의 "먼저 캐시를 시도하고 실패하면 클라우드"(그림 1)는 캐시를 첫 단 모델로 둔 캐스케이드입니다. 캐스케이드 문헌의 핵심 문제는 **언제 싼 모델의 답을 믿을지**(신뢰 판정)이고, ARC는 이 판정을 적중 임계값과 실행 오류 둘로만 둡니다.
- **같은 그룹의 SLM 입장 논문**(*Small Language Models are the Future of Agentic AI*, arXiv:2506.02153): 에이전트 호출 대부분은 좁고 반복적이라 SLM이면 충분하다는 주장입니다. ARC는 이 주장의 한 실행 방안입니다(반복적인 부분은 코드로, 의미 판단만 SLM으로). 그 주장의 경험적 뒷받침을 이 논문이 제공했는지는 `04`에서 따집니다(수학·과학 벤치마크이고 에이전트 워크로드가 아니라서 직접 뒷받침은 아님).
- **같은 그룹의 다른 논문**: *You don't need long context*(arXiv:2611.05306)와 같은 저자가 있습니다. 그 분석에서 헤드라인 배수가 구조에 따라 1–15배로 흔들렸고 절감이 매개변수 하나에 달려 있었습니다. 이 논문에서 같은 유형의 문제가 있는지는 `03` §2, §6에서 봅니다.

## 3. 구성 요소별 출처

| 구성 요소 | 출처 | 새로움 |
|---|---|---|
| 풀이를 코드로 | PAL, PoT (2022) | 없음. 재사용이 새 점 |
| 설명으로 함수 검색과 호출 | Voyager의 기술 검색(2023) | 이름 대신 자연어 설명으로 다단 호출(`do`/`load`) |
| 강한 모델이 만들고 약한 모델이 실행 | LATM (2023) | 일반 문제 전사에서 자동 구축 |
| 전사 → 템플릿 + 매개변수 범위 | Buffer of Thoughts (2024) | 템플릿이 아니라 실행 코드와 타당 범위 |
| 유사도 진입점 + 임계값 | GPTCache (2023) | 진입점이 코드를 가리킴. 임계값 값은 미보고 |
| 캐스케이드 폴백 | FrugalGPT, RouteLLM | 첫 단이 코드 캐시. 오답 감지 없음 |
| 1B 실행기 | 증류 계열 | 20% 평가 로그를 시드로 사용(`03` §4) |

## 4. 이 저장소의 다른 분석과의 관계

| 분석 | 관계 |
|---|---|
| `lm_know_what_they_know/` (14번) | ARC의 핵심 빈칸은 "이 캐시가 이 입력에 맞는가"와 "캐시 답이 맞는가"를 스스로 판정하는 장치입니다. 그 논문의 P(True)·P(IK)는 **자기 평가의 구분력(AUROC)과 보정**을 분리해 재는 틀이고, 구분력이 학습 분포 밖에서 크게 떨어진다는 결과(TriviaQA에서 학습한 P(IK)의 다른 과제 AUROC 0.61–0.69)는 ARC의 임계값 기반 적중 판정이 분포가 바뀌면 약해질 수 있음을 시사합니다. ARC에는 구분력·보정 측정이 전혀 없습니다. |
| `self_debug/` | 실행 피드백(통과·실패)을 받는 재시도가 이득의 대부분을 낸다는 결과. ARC의 구축 단계 5가 같은 구조이고, 여기서 "통과 판정"의 기준이 **평가 정답 라벨**이면 그 논문이 지적한 TransCoder의 문제(피드백 테스트 = 채점 테스트)와 같은 모양의 누출이 됩니다(`03` §4). |
| `agents_that_matter/` | 비용 보고와 단순 기준선. 그 논문은 달러가 아니라 토큰을 쓰고, 같은 정확도에서 "같은 시도 수의 단순 기준선"과 비교하고, 손익분기를 구축비로 계산합니다. ARC는 단일 점 비교(원본 Opus 4.5 확장 사고)만 있고 더 싼 단일 모델 기준선(Haiku 4.5 직접 풀이 등)이 없습니다. 또 그 논문이 LDB 비용에서 시드 생성비가 섞인 것을 밝혔듯이, ARC의 Savings×는 원본 비용이 분모이고 구축비를 따로 둡니다(분해는 정직한 편). |
| `test_set_contamination/` | 평가 문항이 캐시 구축에 쓰였는지가 핵심 질문인데 ARC는 **구축에 평가 문항을 의도적으로 씁니다.** 그 논문의 검정(순서 교환성)은 모델의 암기 탐지이지 이 설계를 점검하지는 않으나, "평가 집합과 구축 집합을 분리하라"는 전제는 공통입니다. 𝒯의 학습에 평가 로그 20%가 쓰인 점은 그 논문의 문제의식과 직접 닿습니다. |
| `eval_error_bars/`, `little_power/` | 문항 수·구간·MDE. ARC의 표 2는 구간이 없고 AIME는 30문항입니다. MDE ≈ 2.80·√(d/n)를 그대로 써 `03` §3을 계산했습니다. |
| `agent_baton/` (244번) | 같은 LFI 그룹의 에이전트 협업 논문. 링크만 둡니다. |
| `edgewise/` (246번) | 같은 그룹의 엣지 논문입니다. 분석이 끝났습니다. |
| `cannot_self_correct/`, `self_correction_survey/` | ARC의 판정자(Opus 4.5 위원회)가 정답을 가진 상태에서 교정 피드백을 줍니다. 외부 정답이 없을 때의 자기 교정과는 다른 설정임을 구분해야 합니다. |
