# 01. 논문 분석: Where LLM Agents Fail and How They can Learn From Failures (AgentDebug)

arXiv:2509.25370v1 (2025-09-29, 유일한 판. 2026-11-23 기준 v2 없음, arXiv comment 없음). 저자: Kunlun Zhu, Zijia Liu, Bingxuan Li, Muxin Tian 외 (UIUC, Stanford, AMD, OpenManus 등). 학회: ICML 2026 워크숍 포스터(`icml.cc/virtual/2026/77923`, 워크숍 이름 "Failure Modes in Agentic AI: Reproducible Triggers, Trace Diagnostics, and Verified Fixes", 2026-11-23 확인). 위치는 절·표·그림 번호이고, `03`·`04`는 이 저장소의 검증 문서입니다.

## 1. 문제

LLM 에이전트는 한 번의 근본 원인 오류가 뒤 단계로 번져 실패합니다(그림 1, §1). 기존 실패 분석은 오류 유형을 나열하거나 사례를 서술하는 데 그쳐, 근본 원인을 추적하거나 에이전트가 스스로 고치게 하지 못한다고 저자들은 주장합니다(§1). 이를 위해 세 가지를 냅니다.

1. **AgentErrorTaxonomy**: 에이전트를 memory, reflection, planning, action 네 모듈과 system(외부 요인) 하나로 나눈 5모듈, 표 2 기준 17개 오류 유형(§2.1, 부록 A.2).
2. **AgentErrorBench**: ALFWorld 100, WebShop 50, GAIA 50, 모두 200개 실패 궤적에 근본 원인 단계·모듈·유형을 사람이 주석(§2.2).
3. **AgentDebug**: 실패 궤적을 분석해 근본 원인 단계를 찾고, 교정 피드백을 주어 그 단계부터 다시 실행시키는 프레임워크(§3, 알고리즘 1).

## 2. 방법

### 2.1 에이전트 모형과 주석 (§2.1, §3.1)

에이전트는 매 단계 Memory → Reflection → Planning → Action을 차례로 내놓는 "모듈형 롤아웃"을 씁니다(부록 A.5 프롬프트: `<memory>`, `<reflection>`, `<plan>`, `<action>` 태그). 분류 체계는 이 형식에 맞춰져 있어, 태그가 없는 일반 에이전트에는 그대로 적용되지 않습니다.

주석 절차(§2.2): 500개 이상의 실패 궤적을 모아 분석했고(§2.1), 그중 200개를 골라 대학원생 10명이 주석했습니다. 단계 수준에서 모든 행동·반성·계획을 검토하고 "근본 원인의 최소 집합"을 표시했습니다. 훈련, 이중 주석, 불일치 합의 조정을 거쳤고 Cohen's κ = 0.55(모듈 수준)를 보고합니다. 이를 "substantial"이라 부르지만 Landis–Koch 구간으로는 moderate(0.41–0.60)입니다.

### 2.2 AgentDebug (§3.2, 알고리즘 1, 그림 4)

- 입력: 궤적 τ, 오류 분류 E_AET, 임계 오류 기준 C_crit, 최대 반복 I.
- **1단계 (세부 분석):** 매 단계 t, 모듈 m ∈ {mem, plan, refl, act}마다 오류 유형 e_t^m을 LLM으로 판정.
- 성공이면(Eval(τ)=1) 종료. 실패에 대해서만 2단계로 갑니다.
- **2단계 (임계 오류 탐지):** "LLM (no rollout/counterfactuals)"으로 임계 단계 집합 T*, 모듈 M*, 유형 Z*, 피드백 φ(0)을 만들고, t* = min(T*)를 취합니다(알고리즘 1 주석).
- **3단계 (반복 디버깅):** k=1..I에 대해 t*에서 피드백 φ를 넣고 재롤아웃. Eval이 1이면 종료, 아니면 UpdateFeedback으로 피드백을 다듬어 반복.

본문 §3.2는 2단계 제목을 "Critical Error Detection **via Counterfactuals**"로 쓰고 "각 시점에 교정된 행동을 대입해 롤아웃이 성공하는지 시험한다"고 설명하지만, 알고리즘 1의 주석과 부록 A.5 프롬프트(그림 15), 공개 코드는 모두 단일 LLM 호출입니다(`04` D1). 반사실 탐색은 오히려 기준선 Brute Force·Binary Search의 방식입니다(§4.1).

## 3. 실험

### 3.1 임계 오류 탐지 (§4.1, 표 1)

GPT-4.1, temperature 0. 지표: Step(S, 첫 임계 단계 정확 일치), Step+Module(S+M), All(단계+모듈+오류 유형 모두 일치). 기준선: Direct Prompting, Brute Force, Binary Search.

| | ALFWorld(100) S / S+M / ALL | WebShop(50) | GAIA(50) | 평균 |
|---|---|---|---|---|
| Direct Prompting | 28 / 14 / 1 | 30 / 6 / 0 | 26 / 10 / 0 | 28.0 / 10.0 / 0.3 |
| Brute Force | 10 / 5 / 0 | 8 / 0 / 0 | 18 / 8 / 0 | 12.0 / 4.3 / 0.0 |
| Binary Search | 20 / 6 / 1 | 14 / 8 / 0 | 22 / 10 / 0 | 18.7 / 8.0 / 0.3 |
| AgentDebug | 35 / 28 / 21 | 42 / 22 / 14 | 58 / 44 / 38 | 45.0 / 31.3 / 24.3 |

초록·서론의 "24% 높은 all-correct(24.3 대 0.3)"는 퍼센트포인트 차이이고, "step accuracy 61% 향상(45.0 대 28.0)"(§4.1)은 상대 개선입니다. 초록의 "17% 높은 step accuracy"는 같은 값의 포인트 차이(45.0 − 28.0)입니다. 평균은 환경별 값의 단순 평균(매크로)이며 궤적 수 가중이 아닙니다(`03` §1).

### 3.2 하위 과제 성공률 (§4.2, 그림 5, 6)

ALFWorld에서 GPT-4o-mini, Qwen3-8B, Qwen3-Next-80B 세 백본으로 비교합니다. AgentDebug는 최대 N=5번 재롤아웃(임계 단계에서 시작). 기준선은 Self-Refine, Vanilla Debugger, ToT, Best-of-N이고 "최대 시도 횟수를 총 토큰 사용량으로 AgentDebug와 맞췄다"고 합니다(§4.2).

| 성공률(%) | First | ToT | Vanilla-Debug | Best-of-N(5) | Self-Refine | AgentDebug |
|---|---|---|---|---|---|---|
| GPT-4o-mini | 21 | 21 | 29 | 31 | 41 | 55 |
| Qwen3-8B | 48 | 48 | 65 | 68 | 74 | 74 |
| Qwen3-Next-80B | 60 | 60 | 76 | 78 | 78 | 84 |

(그림 5의 막대 라벨. 그림 7(a)의 누적 값과 일치합니다.) GAIA·WebShop은 Self-Refine과 Best-of-N만 비교합니다(그림 6: 향상폭 ALFWorld 26/20/26, GAIA 12/14/14, WebShop 4/10/16 = Self-Refine/Best-of-N/AgentDebug).

### 3.3 절제와 분석 (§5)

- 최대 시도 횟수(그림 7a): 시도가 늘수록 누적 성공률이 오릅니다.
- 탐지기 기반 모델(그림 7b): GPT-4.1이 step 42.0, all 32.0으로 나머지(Llama-3.3-70B, GPT-4o-mini, Qwen3-Next-80B는 all 2.0)를 크게 앞섭니다. 값이 모두 2의 배수라 n=50 부분집합으로 보이나, 어느 부분집합인지는 적혀 있지 않습니다.
- 롤아웃 전략(표 7c): Modular 0.38, Memory+ReAct 0.34, Reflection 0.32, ReAct 0.26, Act Only 0.10.
- 오류 전파(그림 8): 초기 오류가 뒤로 번지는 히트맵(수치 없는 도식).

## 5. 한계 (저자 서술 + 우리 관찰)

저자 서술(부록 A.1): 3개 환경, 소규모, 전용 디버거 학습은 비용 때문에 못 했고 프롬프트로 대체.

우리 관찰: ① 탐지기와 하위 에이전트의 모델이 다름(GPT-4.1 대 GPT-4o-mini 등). ② 디버거 입력에 실패 라벨이 들어감(`04` D2). ③ 같은 궤적의 사후 정보를 쓴 피드백이라 환경 정보 누출 가능성이 있음(`03` §6). ④ 수치는 모두 단일 실행, 시드·신뢰구간·하위 과제 표본 수 없음. ⑤ 벤치마크 궤적을 만든 에이전트 모델이 본문에 없음(공개 미러에는 GPT-4o 81, Qwen3-8B 62, Llama3.3-70B 57, `03` §3).
