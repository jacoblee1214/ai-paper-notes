# 03. 재계산, 통계 검정, 계산량 검산

모든 수치는 `analysis/recompute.py`(입력 `tables.json` = 논문 부록 표 2–4, 출력 `recompute_results.json`)에서 나옵니다. 표를 옮긴 `parse_tables.py`는 58행 × 3표를 파싱했고, 같은 모델이 여러 곳에 반복된 행(기본 설정 7곳, 13B 기본 2곳, Llama-2 7B 2곳, CLIP 336 naive 2곳, SigLIP 384 naive 2곳)이 전부 일치함을 확인했습니다(전사 오류 점검). 그림 6, 7 레이더 차트의 라벨 값도 표와 여러 곳 대조해 일치했습니다.

## 1. 벤치마크 표본 수, 구간, 최소 검출 효과

### 1.1 문항 수와 MDE

문항 수는 공식 평가 코드의 `expected_examples`입니다(RefCOCO 계열은 합 26,488만 코드에 있고, 개별 10,834 / 10,758 / 4,896은 표준 val 분할 크기이며 합이 일치합니다). MDE는 두 모델이 같은 문항을 푼다는 쌍체 가정에서 2.80·√(q/n), q는 불일치율입니다. q는 공개되지 않아 0.2를 대표값으로 씁니다(0.1이면 ×0.71, 0.3이면 ×1.22). 기준 모델은 CLIP 336 letterbox입니다.

|---|---|---|---|---|
| VQAv2 | 214,354 | 77.09 | 0.18 | 0.27 |
| GQA | 12,578 | 62.57 | 0.85 | 1.12 |
| VizWiz | 4,319 | 54.33 | 1.48 | 1.91 |

- VQAv2, VizWiz, TextVQA는 soft accuracy(0–1 값)라 이항 구간은 근사입니다. TallyQA는 코드에 전체(38,589)와 부분(16,384) 변형이 있어 논문이 어느 쪽인지 불명확합니다(전체로 계산, 부분이면 MDE가 1.5배). VQAv2, RefCOCO 계열, TallyQA는 같은 이미지에서 여러 문항을 만들므로 군집을 무시한 위 구간은 낙관적입니다(`eval_error_bars` 참고).
- 결론: 1점 안팎의 차이는 VQAv2, TallyQA, OCID-Ref, AI2D에서는 검출되고 VizWiz, TextVQA, RefCOCOg, VSR에서는 검출되지 않습니다. 논문 본문의 "naive resize가 낫다" 같은 1점 이내 차이는 벤치마크 하나로는 판단할 수 없습니다.

### 1.2 VSR는 퇴화한 벤치마크

VSR zero-shot test 1,222문항의 항상-True 정확도는 629/1,222 = 51.47%입니다. 표 4의 고유 모델 48개 중 **16개가 정확히 51.47%**(같은 답만 냄)이고 **24개가 55% 미만**입니다. 기준 모델의 Wilson 95%는 48.7–54.3%로 우연 수준과 구분되지 않습니다. 이 벤치마크가 12개 z 평균에서 같은 비중(1/12)을 갖고, z 점수의 표준편차는 소수의 비퇴화 모델(Llama-2 63.67, 13B Vicuna 70.05 등)이 키웁니다. 영향: Vicuna→Llama-2 7B에서 VSR +12.2점 하나가 평균 z 차이 +0.058을 만들고 VSR을 빼면 +0.013입니다(`recompute_results.json` axes).

## 2. 시드와 반복

- 모든 설정은 **학습 한 번**입니다(표의 모든 행이 단일 점수, 분산 없음). §2는 "초기화 난수와 배치 순서를 고정"했다고 씁니다. 코드는 투영기 초기화 시드를 `torch.manual_seed(vision_backbone.embed_dim)`으로 정해(`prismatic.py` 55–56행) 같은 백본끼리는 같은 초기화를 쓰고, 학습 시드는 기본 7입니다(`scripts/pretrain.py` 72행). 즉 비교는 "시드를 맞춘 단일 실행 쌍"이지 "여러 시드 평균"이 아닙니다.
- 따라서 이 논문의 p 값이 재는 것은 "벤치마크들 사이의 일관성"이며, **학습 실행 간 변동은 재지 않습니다**. 실행 간 변동의 간접 증거가 두 개 있습니다.
  1. **공식 대 재현 LLaVA-1.5 (표 2–4)**: 같은 레시피인데 7B는 RefCOCO +5.4, RefCOCO+ +4.9, RefCOCOg +5.4, OCID-Ref +6.7, VizWiz -3.0, TallyQA -1.2점이고(MDE 밖이 12칸 중 6칸), 13B는 반대 방향으로 RefCOCO류 -1.5 – -2.0, VSR -3.7점(6칸이 MDE 밖). 평균 z 차이는 7B +0.17, 13B -0.16, 벤치마크 z 차이의 표준편차는 0.34와 0.14입니다. 이 격차에는 시드뿐 아니라 구현(FSDP 대 DeepSpeed)과 평가 래퍼 차이가 섞여 있으므로 순수 시드 변동의 상한 쪽 추정입니다.
  2. **Prism-SigLIP 13B (Controlled)**: RefCOCO 59.21로 같은 레시피의 7B(64.74)보다 낮고, CLIP 13B(70.92)보다 11.7점 낮습니다(표 3). 7B에서는 SigLIP-CLIP RefCOCO가 -1.7인 것과 대비됩니다. 학습 실패 또는 큰 실행 간 변동으로 보이며 논문은 설명하지 않습니다(`04` D4에서 repo 설정 오류 의심과 함께).

## 3. 설계 축별 결론의 통계적 근거

### 3.1 방법

기준 행과 대안 행의 쌍을 축마다 정하고(표 2–4의 같은 줄 구성), 벤치마크 12개(TextVQA는 OCR 입력 없는 것, 부록 B.1 기준)의 점수 차이를 구합니다. z 점수는 표의 고유 48개 모델(`np.std`, 공식 `compute_z_scores.py`와 같은 모집단 표준편차)로 만듭니다. 열은 다음과 같습니다.

- **평균 z 차이**: 12개 벤치마크 평균(논문의 "전체 점수" 차이).
- **+/-**: 쌍×벤치마크 칸 중 대안이 높은/낮은 개수(동점 제외)와 양측 이항 부호 검정 p. 같은 쌍의 12칸이 독립이 아니므로 참고용입니다.
- **MDE 밖**: 차이의 절댓값이 q=0.2의 MDE를 넘는 칸 수 / 전체 칸 수.
- **논문 p**와 우리가 계산한 대안 p: 쌍×벤치마크 칸을 모두 독립 표본으로 보는 단측 쌍체 t(flat), 쌍별 평균 후 t(쌍이 3개 이상일 때), Wilcoxon, 비쌍체 Welch.

### 3.3 읽는 법과 교란

- **효과 크기로 나누면 세 층이 있습니다.** (a) 평균 z 차이 |0.4| 이상(미동결 -1.15, 인코더 +1.64, 해상도 +0.41, DINO+SigLIP 융합 +0.46)은 어떤 검정으로도 유의하고 재현 격차(±0.17)보다 큽니다. (b) |0.15–0.3|(단일 단계 +0.15, 더 좋은 LM +0.17, 데이터 +0.20, 1→2 epoch +0.29, 공동 학습 -0.15)는 재현 격차와 같은 크기라서 단일 실행으로는 설계 효과와 실행 간 변동을 구별할 수 없습니다(1→2 epoch은 12칸 전부 오르는 일관성 때문에 예외적으로 믿을 만합니다). (c) |0.1| 이하(naive 대 letterbox +0.06, base 대 instruct +0.06, DINO+CLIP -0.08)는 효과가 없다고도 있다고도 말할 수 없습니다. 그림 `own_axis_effects.png`.
- **letterbox→naive는 인코더에 따라 방향이 갈립니다.** CLIP: +9/-2(TextVQA +5.2점), SigLIP: +6/-5(TextVQA +2.2이나 RefCOCO류 -1.3 – -1.7, OCID-Ref -4.0점), DINO+CLIP +8/-3, DINO+SigLIP +11/-1. 논문이 PRISM에 naive를 채택한 근거는 융합 모델 쪽이 더 강하고, 검정한 두 쌍(CLIP, SigLIP)만으로는 약합니다.
- **인코더 비교는 대조 목적 하나만 바꾼 것이 아닙니다.** IN1K ViT-L은 패치 16(224px에서 196 토큰), DINOv2·CLIP은 패치 14(256 토큰), SigLIP은 SO400M(분석적 계산 4.1억 파라미터 대 ViT-L 3.0억, 논문은 4억 대 3.07억). 사전학습 데이터도 다릅니다. 논문도 이 교란을 "Remark"에서 인정하지만 결론 문장은 "대조 목적 백본이 유의하게 낫다"입니다. 또 DINOv2는 TextVQA 12.6, IN1K는 12.3으로 글자 읽기가 거의 안 되고(CLIP 36.6), 이것이 인코더 효과의 큰 부분입니다.
- **해상도 비교는 체크포인트도 바꿉니다.** CLIP 224와 336은 서로 다른 OpenAI 체크포인트(336px 미세조정 판), SigLIP 224와 384도 해상도별 체크포인트입니다(`04` D6). "해상도 효과"는 "해상도+체크포인트 효과"입니다. 224px 설정은 letterbox를 상속받아 같은 전처리로 비교됩니다(`models.py`).
- **벤치마크별로 보면** 해상도 효과는 VQAv2, TextVQA, RefCOCO 계열, OCID-Ref, TallyQA에서 MDE의 2.7–8.5배이고 VizWiz와 POPE에서는 MDE 안입니다. 융합 효과는 RefCOCO 계열과 OCID-Ref(MDE의 4.9–9배)에 몰려 있습니다. 그림 `own_delta_over_mde.png`.

### 3.4 논문의 p 값은 재현되지 않습니다

- 부록 B.2의 서술("각 쌍의 정규화 차이로 1-sided Fisher T-test")만으로는 검정 단위를 알 수 없고, 공개된 `compute_z_scores.py`에는 z 점수까지만 있고 검정은 없습니다(`04` D8). 단위와 풀(pool)을 여러 가지로 바꿔 보았지만(쌍×벤치마크 쌍체 t, Welch, Wilcoxon, 중복 행 포함·제외 풀) 12개 논문 p 중 어느 것도 일치시키지 못했습니다. 예: 학습 시간 1→2 epoch의 논문 p 0.00496에 대해 flat-t 2e-4, Welch 0.016. 단일 단계는 0.00558 대 flat-t 0.001, Welch 0.10.
- 재현이 안 되는 것보다 중요한 점은 **유의성 판정이 검정 선택에 의존하는 축이 있다**는 것입니다. 단일 단계(p<0.01 기준 flat-t는 유의, Welch는 비유의), 데이터 추가(flat-t 0.002, Welch 0.042), 4쌍 resize(flat-t 0.0016, 쌍 단위 t 0.11). 효과가 |0.4| 이상인 축은 어느 검정에서도 같은 결론입니다.
- **쌍×벤치마크 칸을 독립 표본으로 치는 검정은 학습 실행 노이즈가 있으면 거짓 양성을 크게 늘립니다.** 쌍 수 k=1, 2, 4에서 모델 쌍마다 공유되는 노이즈 τ(z 단위)와 벤치마크별 이항 노이즈(q=0.2)로 시뮬레이션한 귀무 하의 p<0.01 비율(20,000회, `own_false_positive.png`):

| τ (z) | k=1 | k=2 | k=4 |
|---|---|---|---|
| 0 | 0.003 | 0.006 | 0.007 |
| 0.05 | 0.088 | 0.080 | 0.074 |
| 0.10 | 0.206 | 0.186 | 0.166 |
| 0.20 | 0.333 | 0.265 | 0.238 |

  τ=0.16 정도가 공식 대 재현 격차에서 나온 값이므로 명목 1% 검정의 실제 거짓 양성률은 약 20%입니다(k=2). 이는 우리 시뮬레이션의 모형(공유 노이즈 정규, 벤치마크 독립)에 의존하며, 논문의 정확한 검정을 쓴 것이 아닙니다. 방향성만 믿어야 합니다.

| 융합이 "전반적으로(across the board)" 좋다 (§4.2, §1) | DINO+CLIP은 VQA 평균 -9.1점, TextVQA 49.66→15.67 (-34점) | 융합 전반이 아니라 SigLIP과의 조합에 한함. 본문이 DINO+CLIP 예외를 밝히긴 함 |
| 공동 학습 제거는 "약간 개선" (§4.3, p=0.13655) | 제거 시 평균 z -0.15, VizWiz -9.5/-12.4점, VSR +2.2/+3.5점, 나머지는 거의 같음 | 점수 방향과 반대(VizWiz 제외하면 거의 변화 없음). 안전성 논지는 별개이며 이 표로 검증 불가 |
| 단일 단계가 "계산 20–25% 절감" (§4.1) | §5 계산량 검산 | 산술은 가능하나 데이터 길이에 의존 |
| PRISM이 InstructBLIP과 LLaVA-1.5를 "모든 평가에서 앞선다" (§5, 초록) | §6 | **틀림.** 12개 중 9개가 공식 LLaVA-1.5에 지는 벤치마크가 있음 |

## 4. 평가 하네스 대조 요약 (자세히 `04`)

- 생성: `do_sample=False`, `max_new_tokens=max_length`(코드). 논문 "greedy decoding"과 일치.
- **닫힌 집합 벤치마크(VSR, POPE, TallyQA, AI2D)는 생성이 아니라 첫 토큰 확률의 argmax입니다.** "True/False", "Yes/No", 선택지 글자의 첫 토큰 확률을 후보끼리만 정규화해 가장 큰 것을 고릅니다(`generate_batch`, 각 harness의 scorer). 논문 부록 B.1은 "객관식으로 형식을 바꿔 정확도를 보고"한다고만 쓰고 이 우도 기반 선택을 적지 않았습니다. TallyQA는 16개 선택지(A–P)라서 정답이 16 이상이면 표현할 수 없습니다.
- 부분 평가 세트: 코드에는 slim/subsampled 변형이 있으나(VQAv2 16,384, TallyQA 16,384, 1,024 등), 점수 집계 스크립트의 작업 이름은 `vqa-v2-full`, `gqa-full`, `vizwiz-full` 등 full 변형입니다. 논문 수치가 full인지는 표에 적혀 있지 않지만 z 점수 스크립트와 `expected_examples` 단언이 full을 가정합니다. TallyQA만 불명확합니다.
- 점수 정규화: 공개 `compute_z_scores.py`는 논문 "12개 평균"과 다릅니다. TASK_LIST가 7개 작업(VQAv2, GQA, VizWiz, TextVQA, RefCOCO, OCID-Ref, POPE)이고 평균 대상 지표 7개에는 **TextVQA-OCR과 TextVQA-Pure가 둘 다**, RefCOCO+가 없고, VSR, TallyQA, AI2D가 없습니다(`04` D8). 논문 부록 B.2의 12개 평균을 낸 코드는 공개되어 있지 않습니다.

## 5. 계산량 검산

### 5.1 시각 토큰 수와 투영기 파라미터

토큰 수 = (해상도/패치)². CLIP-L/14 224 → 256, 336 → 576, SigLIP-SO/14 224 → 256, 384 → 729(27×27, 384/14의 몫 27, 남는 6픽셀은 합성곱이 버림), IN1K ViT-L/16 224 → 196. 융합은 두 백본의 패치 수가 같아야 하고(코드 단언) 채널만 이어 붙여 토큰 수가 늘지 않습니다.

| 투영기 | 입력 차원 | Llama-2 7B (d=4096) | 13B (d=5120) |
|---|---|---|---|
| CLIP-L 2층 MLP | 1,024 | 20.98M | 31.47M |
| SigLIP-SO 2층 MLP | 1,152 | 21.50M | 32.12M |
| DINOv2+SigLIP, 논문 서술(2층 MLP) | 2,176 | 25.70M | 37.37M |
| **DINOv2+SigLIP, 코드의 FusedMLPProjector(3층, 은닉 4×입력)** | 2,176 | **71.39M** | **89.74M** |
| DINOv2+CLIP, 코드 3층 | 2,048 | 67.13M | 84.95M |

- 논문의 "투영기 입력 차원만 키워 거의 비용이 없다"는 서술은 2층 MLP 기준으로는 +4.2M(+20%)이지만, **코드의 3층 투영기는 비융합 대비 3.3배**입니다. 전체 7B에 비하면 작지만(+0.7%) 융합 대 비융합 비교에서 투영기 용량이 통제되지 않았습니다 (`04` D1).
- 백본 파라미터(분석적 계산): ViT-L/14 약 3.03억, SO400M/14 약 4.12억(timm 체크포인트는 어텐션 풀링 헤드 포함 약 4.28억으로 알려져 있으나 확인하지 않음). 융합은 두 번째 백본의 가중치와 계산을 그대로 더합니다. "virtually no added parameters"는 투영기만 보면 맞고 백본까지 포함하면 틀립니다.

### 5.2 "해상도 2배면 시간 복잡도 16배" (§4.2 Remark)

이 문장은 어텐션 점수 항(토큰² 비례)에만 맞습니다. 7B LM에서 시퀀스가 수천 토큰일 때 선형 항(2N/토큰)이 지배합니다. 패치 수를 4배로 했을 때 LM 순전파 FLOPs 배율(텍스트 T 토큰, 시각 V0 토큰, d=4096, 32층):

| 텍스트 T | V0=256 | V0=576 | V0=729 |
|---|---|---|---|
| 100 | 3.25 | 3.79 | 3.94 |
| 300 | 2.45 | 3.17 | 3.38 |
| 600 | 1.95 | 2.63 | 2.86 |

즉 실제 LM 계산은 약 2–4배이고 16배가 아닙니다(상한 계산: 인과 마스크 절반을 안 셈). 메모리는 활성값이 시퀀스에 선형이라 역시 대략 선형입니다. 논문은 "with a comparable explosion in memory requirements"라고 쓰지만 FlashAttention류를 쓰면 어텐션 메모리도 선형입니다(이 논문의 코드가 쓰는지는 확인하지 않음).

### 5.3 학습 계산 보고값

- **Prism 7B (Controlled) "8×A100에서 9시간 미만"** (영향 진술): 665K 샘플, 샘플당 V+T 토큰(T는 미공개), 6N·토큰 + ViT 순전파로 계산하면 CLIP 336(576토큰), T=300, MFU 0.4에서 6.6시간(체크포인팅 재계산 포함 8.8시간), DINOSigLIP 384(729토큰)에서 7.9시간(10.5시간). MFU 0.3–0.5와 T=150–450 범위에서 5–14시간이라 "9시간 미만"은 그럴듯한 범위 안입니다. 확인은 되나 반증도 어렵습니다.
- **단일 단계의 20–25% 절감** (§4.1): 정렬 558K + 미세조정 665K 중 정렬을 빼면, 두 단계의 샘플당 비용이 같을 때 절감은 45.6%입니다. 보고값 20–25%가 나오려면 정렬 샘플 하나의 비용이 미세조정 샘플 하나의 0.30–0.40배여야 합니다. 정렬은 LM 가중치 기울기를 안 구하므로(4N 대 6N) 이 비율은 미세조정 샘플의 평균 길이가 약 1,000–1,330 토큰(시각 576 포함, 텍스트 약 420–750)일 때 맞습니다. 평균 텍스트 길이를 모르므로 검증은 못 했고, 20–25%는 시간 측정값으로 읽는 것이 안전합니다.
- **"30% 이상 계산 절약"** (그림 1): 단일 단계 20–25%에 FSDP 구현의 20% 빠른 스텝(§2)을 곱하면 1-(0.8×0.775 ≈ 0.62) = 약 38%로 설명됩니다(곱 가정, 확인된 분해는 아님).
- **학습 단계 수:** 665,298 샘플/128 = 5,197.6단계. 1.25와 1.5 epoch의 코드 `max_steps` 6,500과 7,800은 5,197.6×1.25 = 6,497, ×1.5 = 7,796과 일치합니다.

### 5.4 OpenVLA의 224px 선택

224px는 시각 토큰 256개, 384px는 729개입니다. 프롬프트 20토큰을 가정한 7B LM 순전파는 약 3.8 TFLOPs 대 10.4 TFLOPs로 2.76배입니다. OpenVLA가 "384가 학습 3배 걸려 224를 택했다"는 서술(§3.4)과 같은 크기입니다.

## 6. PRISM이 "모든 평가에서 앞선다"는 문장

공식 LLaVA-1.5(같은 규모)보다 낮은 벤치마크 목록(표 2–4, 12개 기준):

| 모델 | 공식 LLaVA-1.5보다 낮은 벤치마크 |
|---|---|
| CLIP 7B Controlled | TallyQA |
| CLIP 7B | VizWiz, AI2D (InstructBLIP 7B에는 VSR에서도 짐) |
| SigLIP 7B Controlled | 없음 |
| SigLIP 7B | VizWiz (InstructBLIP에는 VSR) |
| DINOSigLIP 7B Controlled | 없음 |
| DINOSigLIP 7B | VizWiz |
| CLIP 13B Controlled | VSR, POPE, AI2D |
| CLIP 13B | VizWiz, AI2D |
| SigLIP 13B Controlled | RefCOCO, RefCOCO+, RefCOCOg, OCID-Ref, VSR, POPE, TallyQA, AI2D (8개) |
| SigLIP 13B | OCID-Ref, VSR, AI2D |
| DINOSigLIP 13B Controlled | VizWiz |
| DINOSigLIP 13B | 없음 |

12개 중 9개가 하나 이상에서 집니다. 지는 폭은 대부분 1–3점이고 SigLIP 13B Controlled는 위치 지정에서 최대 7.5점(RefCOCO 59.2 대 66.8) 집니다. 논문 §5는 "uniformly outperform ... by large margins"라고 씁니다. 정정: "대부분의 벤치마크에서, 특히 위치 지정에서 크게 앞선다"가 표에 맞는 문장입니다. 이득의 상당 부분(DINOSigLIP)은 위치 지정에서 나옵니다(RefCOCO 7B: 공식 LLaVA 55.1 대 PRISM 77.8).
