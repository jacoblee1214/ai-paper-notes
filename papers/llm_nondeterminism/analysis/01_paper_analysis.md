# 01. 논문 분석

*Non-Determinism of "Deterministic" LLM Settings* (Atil, Aykent, Chittams, Fu, Passonneau, Radcliffe, Rajagopal, Sloan, Tudrej, Ture, Wu, Xu, Baldwin; Penn State와 Comcast AI Technologies). 분석 판은 arXiv v5(2025-04-02)이고, 공식 게재본(Eval4NLP 2025, 제목 *...LLM System Settings in Hosted Environments*)과의 차이는 §6에 적었습니다. 절 번호는 arXiv v5 기준입니다.

## 1. 문제

- temperature 0, top-p 1, 고정 시드로 설정한 "결정적" LLM이 같은 입력에서 같은 출력과 같은 정확도를 내는가를 측정합니다(초록, §1, §5). 이론상 T→0이면 logit의 argmax가 되므로 출력이 같아야 합니다(§3 식 1, §8).
- 벤치마크 점수를 실행 1회로 보고하는 관행이 타당한가를 묻습니다(§1).

## 2. 방법

| 항목 | 내용 | 위치 |
|---|---|---|
| 모델 | GPT-3.5 Turbo, GPT-4o(Azure OpenAI), Llama-3-70B, Llama-3-8B, Mixtral-8x7B(Together AI) | §5.1 (호스팅 정보는 공식 저장소 `models/*.py`에서 확인, `04` D5) |
| 과제 | BBH 4개(navigate, ruin names, geometric shapes, logical deduction 3 objects)와 MMLU 4개(고교 유럽사, 대학 수학, 전문 회계, 홍보). 문항 수 250/250/250/250, 165/100/282/110 | §4, 표 1 |
| 설정 | zero-shot과 few-shot(BBH 3, MMLU 5), CoT 없음, T=0, top-p=1, 시드 고정, 조건마다 10회 실행 → 80개 조건 | §5, §6 |
| 지표 | **TARr@N**(N회 모두 원출력 문자열이 같은 문항의 비율), **TARa@N**(N회 모두 추출한 답이 같은 문항의 비율), BestAcc, WorstAcc, 중앙값 정확도, 실행별 최대-최소 정확도 차 | §5.2 |
| 상관 분석 | TARa, TARr, 최대-최소 차, 중앙값 정확도, 입력·출력 길이의 Spearman 상관 | §7.2, 그림 5–10 |
| 보조 실험 | 20회 실행(GPT-4o, Llama-70B, 대학 수학 few-shot)의 정규성 KS 검정(그림 2), 로컬 GPU의 Llama3-8B, GPT-3.5 파인튜닝 2-fold | §5.2, §8 |

- 식 1은 소프트맥스 확률 `p_i = exp(y_i/T) / Σ_j exp(y_j/T)`입니다. T=0에서는 정의되지 않고 극한이 argmax라는 설명이 본문에 없습니다(`03` §1).
- BestAcc는 "N회 중 한 번이라도 맞힌 문항을 맞힌 것으로 센 정확도", WorstAcc는 "N회 중 한 번이라도 틀린 문항을 틀린 것으로 센 정확도"입니다(§5.2).

## 3. 주요 결과와 근거 위치

| 주장 | 근거 위치 | 우리 검증 |
|---|---|---|

| 어떤 LLM도 모든 과제에서 같은 정확도를 내지 못하고 같은 문자열은 더 드묾 | 표 2, 표 3, 그림 3, 4 | 맞음. 80개 조건 중 TARr@10이 99% 이상인 조건은 0개, 0%인 조건은 9개(`03` §2) |

| 출력이 길수록 불안정하다 | §7.2, 그림 5 | 우리는 검증하지 않음. 조건 80개의 Spearman이며 모델·과제가 섞여 있어 교란 가능(`03` §6) |
| 정확도 분포는 정규가 아니다(KS p<1e-9) | §5.2, 그림 2 | **재현 안 됨.** 표본으로 표준화한 정규성 검정에서 p=0.50, 0.92(`03` §7) |
| 로컬 GPU의 Llama3-8B는 최적화 없이 결정적이다 | §8.1 | 논문에 결과 표 없음. 저장소 노트북은 조건 1개(`04` D6) |
| 파인튜닝이 불안정을 줄인다 | §8.1 | 저장소 결과 2개 조건, 정확도도 크게 낮음(`04` D7) |
| 원인은 입력 버퍼 공유 등 호스팅 최적화일 것이다 | 초록, §8.1 | **추정.** 논문 스스로 "추측할 수밖에 없다"고 씀 |

## 4. 논문이 하지 않은 것 (한계)

- **원인 실험이 없습니다.** 초록의 "co-mingled data in input buffers"와 §8.1의 연속 배칭, 청크 프리필, 프리픽스 캐싱은 모두 추측입니다. 닫힌 모델은 확인할 수 없다고 직접 씁니다(§8.1).
- **통계 검정이 없습니다.** 정규성이 아니라서 표준편차를 보고하지 않는다고 하고(§5.2), 실행 간 차이가 문항 수만으로 예상되는 범위인지 보지 않습니다. 우리 검정은 `03` §3입니다.
- **재실행 간 차이를 보고하지 않습니다.** 같은 조건을 다시 돌린 결과가 공개 데이터에 있고(2024-12 배치는 top-p 0.0, 2025-02 이후 배치는 top-p 1.0, 날짜도 다름), TARr이 수십 %p 달라지는 쌍이 있지만 논문 본문에 없습니다(`03` §3 C).
- **모델 버전 기록이 없습니다.** GPT는 Azure 배포 이름, Llama·Mixtral은 Together AI의 서버리스 모델 이름만 코드에 있고 논문 본문에는 날짜와 버전이 없습니다.
- **CoT 없는 객관식·짧은 답입니다.** 출력이 짧은 설정이라 긴 추론이나 도구 호출 에이전트로 일반화되지 않습니다.
- **답 추출기가 규칙 기반입니다.** 논문도 인정하며(§8), 우리 재계산에서 파서가 TARa를 바꾸는 경로를 확인했습니다(`03` §5).
- **API 호스팅이라 시드가 실제로 지켜졌는지 모릅니다.** 코드는 `seed=12`를 보내지만 제공자가 지키는지는 논문이 검증하지 않습니다.
