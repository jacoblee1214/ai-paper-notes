# 04. 주장 검증과 공식 코드 대조

구현 모드: 이후 문헌이 이 검정을 확인·수정·반박한 것을 C1–C9로, 공식 코드 정적 대조를 D1–D10으로 적습니다. 판정은 "확인(우리 유도·재계산 포함) / 부분 확인 / 반박 / 미검증"으로 씁니다. 이후 문헌은 초록과 본문 해당 대목을 직접 읽은 것만 인용했고, 재현하지 않았습니다.

### 요약해서 인용에 쓸 때

- C1, C5는 확실히 인용할 수 있습니다(검정이 증명하는 범위의 정의).
- C3, C4의 수치는 논문 자체 실험의 값이고 설정이 다른 외부 결과(미세조정, 작은 샤드)와는 바로 일치하지 않습니다.
- C6의 "이 비판이 이 검정에는 적용되지 않는다"는 우리의 논리적 해석이며 어떤 외부 연구가 이 검정으로 그것을 실험으로 보인 것은 아닙니다.

## 2. 공식 코드 대조 D1–D10

대상: `tatsu-lab/test_set_contamination`, 커밋 `56e2257e87dfebc3ac786ab982bbb681c53846ab`(2023-11-07, 마지막 push 2023-11-07), 작업 트리 31 MB(`repo/`, 얕은 clone, gitignore). 라이선스 파일이 없음(GitHub API license: null). 정적으로 읽었고 실행하지 않았습니다. 코드는 `compute_sharded_comparison_test.py` 한 파일(231줄)과 `benchmarks/`·`detection_challenge_benchmarks/`의 zip입니다. 논문의 Table 2에 쓰인 시험 파일은 있으나 **감사 결과(p값 로그)는 저장소에 없습니다**.

| # | 항목 | 논문 / 우리 구현 | 공식 코드 | 영향 |
|---|---|---|---|---|
| D1 | 구현된 검정 | 순열 검정(§3.1)과 분할 검정(§3.2), 표 1에 두 p값 | **분할 검정만**. 순열 검정 코드가 없음 | 표 1의 순열 p 열은 저장소로 재현 불가 |
| D2 | 샤드 나누기 | 인접 문항 샤드, 앞 n mod r개 샤드에 1개 더 (Alg. 1) | `shard_counts = [n//r + (1 if i < n % r else 0)]` 후 누적합으로 연속 구간 | **같음.** `shard_sizes`와 동일 (`test_shard_sizes_follow_algorithm_1`) |
| D3 | 통계량 | 단측 t 검정(df = r−1) | `z = mean(diffs) / np.std(diffs) * sqrt(r)`, `np.std` 기본 **ddof=0**, p는 `1 - tdist.cdf(z, df=r-1)` | 통계량이 표준 t보다 √(r/(r−1))배 큼: r=50에서 1.0102배, 명목 5%가 실제 0.0517, r=10이면 1.054배, 0.058. 비보수적 방향이지만 r=50에서는 작음. 우리 구현은 `ddof`를 인자로 두고 기본 1 |
| D4 | p값 계산 정밀도 | 표 1의 최소 p가 "1e-38(수치적 0)" | `1 - cdf`는 ~1e-16에서 0이 됨(z ≥ 12에서 df=49) | 코드가 낼 수 있는 가장 작은 양수 p는 ~1e-16, 표의 1e-38은 코드 출력이 아니라 후처리(우리 추정). 1.96e-11, 3.43e-13은 정밀도 안. `scipy.stats.t.sf`를 쓰면 안전 |
| D5 | 문항 구분자와 토큰화 | 문항을 이어 붙임(seq), 구분자 미정의 | 각 문항을 **따로** `t.encode(ex)`해 토큰 리스트를 이어 붙임. 구분자는 문항 문자열 끝의 개행(`readlines`, JSON 리스트 원소도 `\n`으로 끝남, 우리 `repo_checks.py`로 확인). `add_special_tokens` 미지정이라 HF 토크나이저 기본 동작(LLaMA 계열은 문항마다 BOS가 붙는 것으로 알고 있으나 실행해 확인하지 않음) | 정준과 순열이 **같은 토큰 리스트를 재배열**하므로 토크나이저 효과는 상쇄(우리 토이도 같은 구조). 구분자 설계에 따라 문항 경계 신호가 달라질 수 있음 |

| D7 | 순열 수·샤드 수 기본값 | §4.1: 50 샤드, 51(또는 50) 순열 (표기가 뒤섞임), §4.3: 50 샤드, 250 순열 | 기본값 50 샤드, 250 순열, `max_examples=5000`(앞 5,000개만), 시드 0. README 예시는 GPT-2 XL, 1024/512, 100 순열 | 논문 표기 혼선(m/r, 51/50)은 코드가 아니라 서술 문제. 5,000문항 절단은 파일의 **앞** 5,000개 (LAMBADA는 이 구간에 중복 줄 2개) |

### 우리 구현과 공식 코드의 같고 다른 점 (요약)

- **같음**: 샤드 나누기 규칙(D2), 샤드 안에서만 섞기, 정준 한 번 + m개 순열 평균, 단측 t(df = r−1), 같은 토큰을 재배열하는 구조(D5).
- **다름**: 통계량 분모(ddof 1 대 0, D3), 시퀀스 앞 처리(D6), 순열 검정을 구현함(D1), 동점 처리(`03` §1), `permutation_z_test`는 우리가 추가.
- **다름, 규모**: 문항 200개 / r=10 / m=25(토이, 논문은 1,000–5,000문항 / 50 샤드 / 51–250 순열), 우리 LM은 n-gram.
