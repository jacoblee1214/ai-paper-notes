# 01. 논문 분석: EdgeWise (arXiv:2610.17560 v2)

*EdgeWise: Bringing Long-Horizon Agents to the Edge via Selective Cloud Delegation* (Shi, Jiang, Hachiuma, Fu, Lee, Belcak, Muralidharan, Agarwal, Tang, Dantrey, Molchanov, Patney, Radhakrishnan; NVIDIA, Rutgers 인턴십). 분석 판은 **v2(2026-10-15)**이고 v1(2026-10-13)과의 차이는 §6에 적었습니다. 쪽·절·표·그림 번호는 v2 PDF 기준입니다. 분석일 2026-11-26.

## 1. 문제

긴 에이전트 과제(코딩)에서 매 단계 클라우드 LLM을 쓰면 비싸고, 단계마다 필요한 능력이 다르다는 전제에서 시작합니다(§1). 기존 라우팅은 질의 단위이고(RouteLLM 등), 다단계 라우터(Router-R1, MERA)는 다중 홉 QA 위주이며 별도의 결정 모델이 모델 풀에 묶여 있다고 봅니다(§1, §5). 그래서 **로컬 SLM이 주 풀이자이고 필요한 단계만 클라우드 LLM에 넘기는** 구조를 제안합니다. 위임한 단계는 LLM이 한 단계만 실행하고 제어가 SLM으로 돌아옵니다(§2, 그림 2).

## 2. 관찰: 일부 단계만 LLM이어도 비슷하다 (§2, 그림 3)

- 설정: SLM = Qwen3.5-9B, LLM = GPT-5.5(xhigh), 최대 80턴, Terminal-Bench 2.1과 SWE-ReBench, 하네스 Terminus2와 OpenHands(§2).
- **무작위 위임**: 단계마다 정해진 확률로 LLM이 실행합니다. 클라우드 비율 약 40%에서 배치마다 성능 편차가 크고 "일부 배치는 전부 클라우드와 비견되며 비용은 25% 이상 줄어든다"고 합니다(§2, 그림 3: 점은 3회 평균, 띠는 표준편차). 그림 3에는 −25.2%, −29.8%, −57.0%가 적혀 있습니다.
- 결론: "LLM을 얼마나 쓰느냐보다 어디에 쓰느냐가 중요하다"(§2 끝).

## 3. 핵심 단계는 어떻게 골랐나 (§3.1, 그림 4)

- 코딩 에이전트 궤적 2.4k개의 각 단계를 여섯 유형으로 분류합니다: Write/Edit, Read/Search, Diagnose/Reproduce, Test/Validate, Discover/Navigate, Wait/Poll(§3.1).
- 유형별 **클라우드 커버리지**(그 유형 단계 중 클라우드가 한 비율)와 이진 보상을, (벤치마크, 과제, 무작위 선택 예산) 군집 안에서 중심화해 합친 피어슨 상관을 계산합니다(식은 §3.1 본문, r_a = Σ C̃·R̃ / (√ΣC̃² √ΣR̃²)). 신뢰구간은 군집 부트스트랩입니다.
- 결과(그림 4 왼쪽): Write/Edit r = 0.200 [0.099, 0.297], Read/Search 0.040, Diagnose/Reproduce 0.018, Test/Validate −0.111 [−0.231, 0.008], Discover/Navigate −0.066, Wait/Poll −0.004. 오른쪽: 성공 궤적이 실패 궤적보다 Write/Edit 커버리지가 TB 9.4%p, SWE 5.6%p 높고 다른 단계는 +0.3, +0.9, −0.2(차이의 차이 Δ: 결합 +7.1 [2.9, 11.3], TB +8.5, SWE +5.8).
- 이 결과로 **"Write/Edit과 복잡한 Read/Search"를 핵심 단계 기준**으로 정합니다(§3.2.1). 단 "복잡한" Read/Search를 따로 잰 통계는 없습니다(그림 4의 Read/Search는 단순·복잡을 합친 값, 구간이 0을 포함).

## 4. 위임을 누가 결정하나 (§3.2)

### 4.1 외부 판정자(이진 위임, 훈련 없음) (§3.2.1, 식 없음)

판정자 J(GPT-5.4-mini)가 이력 h_t를 보고 a_t = J(h_t) ∈ {Local, Cloud}를 매 단계 내립니다. 판정 기준에 그림 4의 패턴(Write/Edit, 복잡한 Read/Search)을 넣었습니다. 임계값 버전(§3.4, §4.4)은 연속 점수 s_t = J(h_t)와 임계값 τ로 a_t = Cloud(s_t > τ)를 냅니다.

### 4.2 자기 위임(SFT 다음 RL) (§3.2.2)

- **SFT**: SWE-Smith에서 GPT-5.5가 푼 궤적과 "이 단계를 작은 모델이 하면 위임이 필요한가"라는 라벨 2K개로 L_SFT = −Σ log p_θ(y|x)를 학습합니다. 이 라벨은 형식 학습용이라고 밝힙니다.
- **RL**(40×A100, 175 스텝, 배치 8, 예제당 롤아웃 16, §4.1). 위임 토큰은 LLM이 쓴 부분이 정책 손실에서 빠집니다.
  - **식 (1)** 궤적 보상 R_i = V_i + 1[V_i = 1] · 1/(1 + λ C_i), V_i는 정답 여부, C_i는 클라우드 호출 수, λ = 0.1.
  - **식 (2)** 위임 토큰의 이점 A_t = A_traj + β (N_trajectory / N_route) A_i^del. A_traj는 GRPO 이점, N_trajectory는 궤적의 학습 토큰 수, N_route는 위임 토큰 수.
  - **식 (3)** (부록 G.1) A_i^del = +1(SLM 결정 d_i = 비평가 결정 d̂_i), −1(다름). 비평가는 GPT-5.4-mini이고 §3.1의 핵심 단계 기준으로 각 위임 결정을 판정합니다. 본문은 "로컬 실행이 충분하면 이점을 더하지 않는다"고 하지만 식 (3)은 그 경우를 따로 두지 않습니다(`03` §6.3, `04` C12).
- 훈련은 SWE-Smith + Kimi-K3(클라우드 LLM)입니다. 평가는 GPT-5.5·Opus 4.8입니다(§4.1, §4.2).

### 4.3 문맥과 빈도 (§3.3, §3.4, §4.3)

LLM에 넘기는 문맥 다섯 가지(전체 이력, 직전 단계, 최근 k=3, SLM 추론 제거, 관련 단계)와 판정자 문맥 세 가지(전체 이력, 전체+현재 분석, 현재 분석만)를 비교합니다. 결과(그림 6): 전체 문맥이 최고(71.91, $59.16)이고 SLM 추론만 뺀 것이 64.42/$45.60, 최근 3단계 58.80, 직전 단계 43.07. 판정자는 현재 분석을 더하면 60.67, 현재 분석만이면 50.56으로 떨어집니다. 빈도(§4.4, 그림 7, 12): 임계값 0.2–0.4가 검증 세트(SWE-Smith)에서 좋았고 TB·SWE-ReBench에서도 비슷하다고 합니다.

## 6. v1과 v2의 차이

PDF 텍스트를 단어 단위로 비교했습니다. 표 값과 본문 수치는 같고 바뀐 것은 다음입니다.
- 첫 쪽에 NVIDIA 소속 줄과 프로젝트 페이지 링크(`research.nvidia.com/labs/lpr/edge-wise/`)가 생겼습니다. 날짜 2026-10-14 대 2026-10-19(arXiv 개정일은 10-15).
- **그림 7의 캡션**이 v1에서는 그림 6과 같은 문장("세 가지 문맥 설정에서의 정확도와 비용")으로 잘못 들어 있었고, v2에서 "임계값별 성능과 비용"으로 고쳐졌습니다.
- 표 7의 하네스 행 순서, 부록 E(LLM이 처리한 단계 분포)의 쪽 위치, 그림 위의 100%/90% 축 라벨 위치가 달라졌습니다.
