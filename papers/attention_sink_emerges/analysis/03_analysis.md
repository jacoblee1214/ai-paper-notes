# 03. 식 검산, 표 재계산, 시드 변동 점검, CPU·MPS 토이

원본 로그나 결과 표가 공개되지 않아(`04` 머리말) **논문 표에 인쇄된 값만** 다시 계산했다. 계산은 `analysis/metric_check.py`(식), `analysis/tables_recompute.py`(표), `analysis/sink_toy.py`(토이)가 하고 결과는 같은 이름의 `*_results.json`에 있다. 검사 라벨은 V1–V12.

## 1. Sink_k^ε 지표의 식 검산 (V1–V4)

`metric_check.py` → `metric_check_results.json`

- **V1 범위.** A_{1,1}=1, 나머지는 [0,1]이므로 1/T ≤ α_1 ≤ 1이다. T=64에서 1/64 = 0.0156(첫 토큰 질량이 0일 때)과 1(모든 질의가 첫 토큰만 볼 때)을 직접 만든 행렬로 확인했다. 논문 텍스트 추출은 하한을 "T"로 깨뜨리는데 원문 기호는 1/T다.
- **V2 균일 attention의 기준선은 H_T/T이다.** 식 α_1 = (1/T)Σ_i 1/i = H_T/T. T=64에서 0.0741, T=1024에서 0.0073, T=2048에서 0.0040. 그림 3의 "T가 클수록 지표가 줄어든다"는 **sink가 약해져서가 아니라 기준선이 H_T/T로 내려가기 때문에** 생기는 성분이 포함된다. 균일 헤드가 ε=0.3을 넘는 가장 큰 T는 9다(T=9에서 0.3143, T=10에서 0.2929). 그러므로 T<10에서는 sink 없는 헤드도 sink로 센다.
- **V3 임계값의 의미.** "i≥2에서 첫 토큰에 일정한 질량 w를 주고 나머지는 균일"인 헤드의 α_1 = (1+(T−1)w)/T이므로 α_1=ε에 해당하는 질량은 w* = (εT−1)/(T−1)이다. T=64, ε=0.3이면 **w* = 0.289**(ε=0.1, 0.2, 0.4, 0.5이면 0.098, 0.194, 0.384, 0.492). 큰 T에서는 w*→ε. 즉 ε=0.3은 "질의의 약 29%를 첫 토큰이 가져간다"에 해당한다. 직접 구성한 행렬로 5개 ε와 5개 T에서 정확히 일치했다.
- **V4 명제 1(NoPE 반복 토큰은 균일)은 정확히 맞고, 명제 4(Rotary 상한)는 맞지만 느슨하다.** 명제 1: q, k가 모든 위치에서 같으면 점수가 모두 같아 A=1/t. 수치 오차 0. 명제 4: ‖q‖‖k‖=ξ일 때 A ≤ e^{2ξ}/(e^{2ξ}+t−1). ξ=0.5–8에서 5개 모두 상한이 성립했다. 그러나 상한으로 α_1 < 0.3(T=64)을 보증할 수 있는 최대 ξ는 **1.09**뿐이다. ξ=2에서는 상한 α_1 ≤ 0.666, ξ=4에서 0.990이라 sink가 없음을 보장하지 못한다. 실제 α_1은 모든 ξ에서 0.074–0.078이었다(Rotary는 오프셋별 각도만 달라 균일에 가까움). 표 1의 0.00은 명제가 보증하는 것이 아니라 **명제보다 강한 경험적 관찰**이다.

**판정:** 지표의 정의와 이론 부분은 맞다. 다만 ε와 T는 "sink 정도"를 재는 눈금이 아니라 T에 의존하는 기준선 위에 놓인 임계값이다. T=64, ε=0.3은 "평균 29% 이상"을 뜻하고, 서로 다른 T의 값은 직접 비교되지 않는다.

### 임계값 민감도 (V5)

공개 모델의 α_1 분포(부록 그림 19–24)는 숫자로 주어지지 않아 ε를 바꿔 재계산할 수 없다. 대신 토이(§6)에서 ε=0.1–0.5를 모두 잰다. 논문 그림 3은 ε와 T의 의존만 보이고, 결론(어떤 변형이 sink를 늘리나)이 ε에 얼마나 민감한지는 60M 학습 표에서 보고하지 않는다. 표 2·9·14의 모든 값은 ε=0.3 하나이므로, **결론의 ε 민감도는 검증할 수 없다**.

## 3. 나머지 표의 산술과 일관성 (V9–V12)

- **V9 표 5(v* 크기).** K bias에 고정 v*를 더할 때 Sink_*(bias 위치)와 Sink_1(첫 토큰)의 합은 73.34, 70.09, 48.14, 27.39, 71.89, 33.92, 11.21이다. 즉 "sink가 bias에서 첫 토큰으로 이동한다"고 쓰지만 **총량은 보존되지 않고** 큰 v*일수록 줄어든다(20v″에서 11.21). 같은 검증 손실(3.71–3.73)이라 모델 능력의 차이는 아니다. "첫 토큰으로 돌아온다"기보다 "sink가 약해지며 일부가 첫 토큰으로 남는다"에 가깝다.
- **V10 표 13(학습 가능한 key bias 차원 수).** Sink_*는 d_a=1,2,4,8,16,32,64에서 32.18, 30.88, 30.94, 31.39, 23.30, 51.23, 69.19이다. 본문의 "차원이 많을수록 sink가 더 뚜렷하다"는 큰 방향은 맞지만 8 → 16에서 −8.09로 단조가 아니다(낮은 척도로 5.3 SD).
- **V11 표 1과 표 7.** chat − base: Mistral −9.15 pp, LLaMA2-7B +0.41, LLaMA2-13B −0.75, LLaMA3-8B −0.17. 논문의 "비슷하다"는 3개에는 맞고 Mistral은 9 pp 차이다. natural → random 하락은 GPT2-XL 6.7, Mistral 22.3, LLaMA2 2.3, LLaMA3 7.8 pp이고, 첫 위치 임베딩을 다른 위치로 바꾸면 62.28 → 0.20–10.97(표 7)로 본문 서술과 일치. 표 7의 "교체 위치 5"의 0.20은 10(2.36), 25(10.97)보다 낮아 위치 의존이 단조가 아니다.
- **V12 손실 "비슷함"의 범위(표 6).** 검증 손실은 softmax 3.73에 대해 sigmoid(정규화 없음) 3.70, elu 3.69로 **같거나 더 낮다**. 반면 identity 커널(정규화 없음) 3.99, MLP 커널 3.85/3.91, elu 커널 4.19는 +0.12–0.46 나쁘다. 논문의 "MLP 커널은 정규화와 무관하게 sink가 없다"는 같은 비교 척도에서 모델이 더 나쁜 경우이므로 sigmoid와 같은 증거로 쓰기 어렵다. 또 "정규화 없는 sigmoid 1B의 SFT 안정성"은 절 E와 그림 30에서 한 실행의 손실·기울기 곡선만 있다.

## 4. 같은 종류의 다른 사례와의 비교 (로봇 attention 분석)

이 논문의 정의로 보면 sink는 (i) 작은 value norm, (ii) 큰 은닉 norm(massive activation), (iii) 데이터가 정하는 위치의 묶음이다. 다른 분석이 "끝점 질량"을 sink로 해석할지는 이 세 조건으로 가릴 수 있다. 예를 들어 어떤 VLA 분석은 행동 청크 양 끝 토큰의 attention 질량을 RoPE가 만든 위치 효과로 설명하고, 끝점 value의 norm 비가 약 1.0이며 출력 기여가 평균 이상이라 sink 조건이 아니라고 결론 내렸다. 이는 이 논문의 "key bias처럼 작동하되 값 계산에는 기여하지 않는다"(절 7.3) 기준에 비춰 일관된 판정이다.

## 5. 규모와 예산 산술 (`tables_recompute_results.json`)

- 60M 모델: 층당 4·768² + 3·768·1536 = 5,898,240, 10층 **58.98M(비임베딩)**, 임베딩+언임베딩 77.46M. 논문의 "약 60M, 임베딩 제외"가 맞다.
- 헤드 수 L×H = 80, 즉 지표 1칸 = 1.25 pp. 18.18%는 평균 14.5개, 15.20%는 12.2개, 41.08%는 32.9개 헤드. 1B 설정은 22층 × 16헤드 = 352(비임베딩 1.13B).
- 토큰 예산: 배치 1,048,576토큰(512 × 2048) × 20,000스텝 = **20.97B 토큰** = 5B 토큰의 **4.19회**. 데이터 양 실험의 같은 스텝에서의 반복 횟수는 5B 4.2, 2.5B 8.4, 500M 41.9, 200M 105, 100M 210, 50M 419회. 그림 28(50M, 100M 과적합이 1k–2k 스텝에 시작하고 Sink<1%)은 이 반복의 극단이다. 따라서 "데이터가 적으면 sink가 생기지 않는다"는 **다양성의 부족과 반복 횟수의 증가가 섞인 결과**다. 논문은 이를 과적합과 분리하려 했으나(그림 28), 같은 스텝에서 데이터만 줄였기 때문에 다양성이 아니라 반복 때문인지는 가려지지 않는다.

## 6. CPU·MPS 토이: 학습 중 첫 토큰 sink의 출현

`analysis/sink_toy.py` → `sink_toy_results.json`. 직접 짠 4층, d=128, 4헤드, SwiGLU, RoPE, RMSNorm 모델(약 0.7M 파라미터)을 파이썬 표준 라이브러리 소스를 바이트로 읽은 약 40 MB 코퍼스(설치된 파일, 다운로드 없음, 바이트 어휘 256)에서 T=64 조각으로 AdamW 2,000스텝(lr 2e-3, weight decay 0.1, 배치 64) 학습한다. attention 변형 3종(softmax, sigmoid 정규화 없음, sigmoid 정규화 있음)을 각 시드 3개로 돌렸다. 지표는 논문 식 그대로(sigmoid 정규화 없음은 proxy) ε=0.1–0.5. 논문 수치와 직접 비교하지 않는다.

- **토이에서는 softmax에서도 첫 토큰 sink가 생기지 않았다.** 모든 헤드의 α₁이 균일 기준선 H_64/64 = 0.074보다도 낮다(최대 0.07). 학습 곡선(그림)에서도 α₁은 처음 0.074에서 내려가 0.04에서 평탄하다. 즉 attention이 오히려 첫 토큰을 피하고(국소·자기 위치로) 몰리는 모델이 되었다.
- 따라서 **softmax 대 sigmoid의 방향 비교(논문 표 6의 18.18 대 0.44)는 이 토이로 확인할 수 없다.** 세 변형의 차이는 ε=0.1에서의 작은 값(0.8–4.6%)뿐이며 방향 해석을 할 수 없다.
- 해석(가설, 이 실험으로 검증하지 않음): 논문은 sink가 "충분한 데이터와 효과적 최적화 뒤"에 생긴다고 하고, 60M 모델·5B 토큰·2048 문맥에서 1k–2k 스텝 뒤에 나타난다(그림 4). 이 토이는 0.7M 파라미터, 문맥 64, 바이트 단위 코드 코퍼스, 2k 스텝이라 첫 토큰을 "아무것도 안 하기" 자리로 쓸 필요가 약했을 수 있다. 탐색 중 다른 설정도 시험했으나(실행 기록은 저장하지 않음): 합성 마르코프 사슬(V=128–512, 복사 구간 포함, 3,000스텝, lr 1e-3–2e-3, weight decay 0.1 또는 1.0)에서도 softmax의 Sink₁(ε=0.3)이 0%였고 sigmoid 정규화 없음은 0.2–1.5%였다. 토이 설계를 키워 다시 보는 것이 다음 단계다.
- 의미: 논문의 sink 출현은 **소규모에서 쉽게 재현되는 현상이 아니다**(논문은 Pythia-14M에서도 있다고 하나 사전학습 규모와 문맥 길이가 이 토이와 다르다). 이 토이는 지표 구현이 균일 기준선(0.074)에서 시작해 내려가는 것을 보였으며(식 검산 V2와 일치), 논문의 결론을 지지하지도 반박하지도 않는다.
