## 1. 마스크와 손실 식 검산 (`mask_loss_toy.py` → `mask_loss_results.json`)

### 1.1 마스크 규칙 (논문 §3, 그림 4)

규칙: 모든 위치 $i$는 $j\le i$를 보고, 같은 이미지에 속한 패치 둘은 서로 봅니다. 식으로는 $M_{ij}=[j\le i]\ \lor\ [b(i)=b(j)\ge 0]$, $b$는 이미지 번호(텍스트는 −1)입니다. BOI와 EOI는 텍스트처럼 인과이고 이미지 블록에 속하지 않습니다.

- **구현 둘이 같다:** (a) 블록 id 방식(위 식), (b) big_vision `make_attn_mask`식 `cumsum(ar)[j] <= cumsum(ar)[i]`에서 텍스트는 ar=1, 이미지 첫 패치 ar=1, 나머지 패치 ar=0. 세 배치 `[BOS cap BOI p×8 EOI END]`, `[BOS BOI p×8 EOI cap END]`, 이미지 둘(3패치씩)에서 모두 같은 행렬입니다(T1).
- **정보 흐름 점검(T2, 이미지 둘 배치):** 같은 이미지 안 양방향 ✓, 첫 이미지는 둘째 이미지를 못 봄 ✓, 둘째 이미지는 첫 이미지를 전부 봄 ✓, BOI는 자기 뒤 패치를 못 봄 ✓, EOI와 이후 텍스트는 이미지 전부를 봄 ✓. 인과 대비 추가 허용 쌍은 6개(블록당 3패치의 위 삼각 3쌍 × 2)로 기대와 같습니다.
- **PaliGemma와의 관계:** `paligemma/`의 prefix-LM 마스크는 이미지·접두를 한 양방향 블록으로 두고 접미를 인과로 둡니다. 같은 `cumsum` 함수에서 ar 배열을 `[0…0 | 1 1 1]`로 주면 prefix-LM, `[1 1 1 | 1 0 0 0 | 1 1 …]`로 주면 Transfusion입니다. 즉 한 일반 규칙("ar=1이면 새 인과 단계")의 두 사례이고, π0의 3블록 마스크도 같은 함수입니다(`paligemma/analysis/03` §7). 차이는 Transfusion이 이미지 블록이 시퀀스 중간에 여러 번 나오고 블록이 생성 대상(출력)이라는 점입니다.

작은 배열(캡션 먼저 `[BOS cap BOI p×8 EOI END]`의 마지막 몇 행, `#` = 볼 수 있음):

```
  p   # # # # # # # # # # # . .     (이미지 패치: 자기 이미지 전부, 앞 텍스트, EOI와 END는 못 봄)
EOI   # # # # # # # # # # # # .
END   # # # # # # # # # # # # #
```

### 1.2 손실 식 (식 4)과 한 순전파 계산 (T3)

$L=L_{LM}+\lambda L_{DDPM}$, λ=5. 토이는 위치마다 어떤 손실이 걸리는지 논문 서술대로 구현했습니다: 위치 $i$의 출력은 입력이 텍스트이고 다음 토큰이 텍스트이며 입력이 BOI가 아닐 때만 LM 손실(각주 8), 이미지 위치의 출력은 ε 예측이고 이미지별로 평균. 이미지의 노이즈는 패치화 전에 더하고 timestep 임베딩을 모든 패치 벡터에 더합니다(각주 6, 9).

- 초기화 직후: $L_{LM}=2.02$(균등 분포 기대 ln 8 = 2.08), $L_{DDPM}=1.74$. 기울기 노름은 LM 2.76, DDPM 5.64로 DDPM이 2.0배이고 λ=5를 곱하면 약 10배입니다.
- **λ의 의미는 정규화 선택에 묶여 있습니다.** 논문은 LM 손실이 토큰별, 확산 손실이 이미지별이라고만 적고(§3), ε 오차를 이미지 원소에 대해 합하는지 평균하는지(1024개 패치 원소 대 8개 등), 배치 가중을 어떻게 하는지는 적지 않았습니다. 같은 λ=5라도 패치 수가 다른 설정(표 6의 16–1024 패치)에서 LM과 DDPM의 상대 크기가 달라질 수 있습니다. §4.1은 λ를 5로 두었다고만 적고 패치 크기를 바꾼 표 6에서 λ를 다시 점검했다는 서술은 없습니다.
- **LM 손실의 하한:** 토이에서 학습이 끝난 $L_{LM}$은 0.56(시드 0의 마지막 스텝 기록, 0.55–0.57)에서 멈춥니다. 모델 실패가 아니라 "BOS 다음이 캡션(80%)인지 BOI(20%)인지"가 정해져 있지 않아서 생기는 엔트로피 때문입니다. 하한은 $(1.609+0.2\,CE_B)/3\approx0.54$ + 이미지 먼저 배치의 캡션 항(여기서는 약 0.02). 캡션 먼저 80%와 이미지 먼저 20% 섞기(§4.1) 자체가 첫 위치에 고정 엔트로피를 남깁니다. 실제 모델에서는 BOS 다음 텍스트 분포에 흡수되어 작습니다.

### 1.3 LM → diffusion 전환 규칙과 EOI (T4)

- 캡션 위치의 출력이 BOI를 내는지(전환 신호): 9개 모델 전부 100%.
- 전환 뒤 diffusion(DDIM 50 스텝, ε 예측)으로 8패치를 생성하고 분류: **정확도 100%**(3시드 × 3변형), 진짜 패턴과의 MSE 0.0113–0.0118. 논문은 250 스텝 DDPM이고 토이는 50 스텝 DDIM입니다. 토이에서 x0 추정을 $[-3,3]$로 자르는 것은 DDPM 구현의 `clip_denoised`와 같은 관행입니다. 자르지 않으면 t≈T에서 $1/\sqrt{\bar\alpha_t}\approx 300$배 오차 증폭으로 MSE가 3.7로 커졌습니다(디버그 실행, 코사인 일정에서 $\bar\alpha_T$ 하한 1e-5).
- **EOI:** 논문은 학습에서 EOI를 LM 손실로 예측하는지 적지 않고, 추론에서는 "확산이 끝나면 알고리즘이 EOI를 붙인다"고 합니다(§3 Inference). 토이는 마지막 패치 위치에 LM 손실이 없으므로 EOI를 예측하지 않고 같은 방식으로 붙입니다.
- **BOI:** BOI는 앞 위치의 LM 출력으로 예측하고(입력이 BOI일 때만 손실 없음, 각주 8), 이미지 크기는 `modality_default_shape`처럼 추론 때 사용자가 정합니다(논문: "원하는 이미지 크기에 따라 n 패치").

## 2. 계산량·파라미터·토큰 산술 (`compute_check.py` → `compute_results.json`)

### 2.1 파라미터와 6ND
- Llama형 구성 파라미터(어휘 32,000, 입출력 임베딩 분리, ffn = 8d/3을 256 배수로): 0.162B, 0.374B, 0.778B, 1.364B, **6.738B**. 표 2의 0.16/0.37/0.76/1.4/7B와 맞습니다(7B는 6.74B). 임베딩이 7B에서 0.262B입니다.
- 그림 5의 모든 점의 x좌표(log10 FLOPs)가 $6\,N\,D$, D = 0.1, 0.2, …, 0.5T(체크포인트)와 일치합니다. 최대 로그 오차 0.8%(0.16B), 7B에서 0.3%. 7B 마지막 점은 $2.02\times10^{22}$입니다. 즉 **그림 5의 25점은 모델 5개 × 체크포인트 5개이고 독립된 실행은 크기마다 하나**입니다. Transfusion과 Chameleon의 x좌표가 같으므로(C4·Wiki·Llama 패널 확인) 두 방법에 같은 N을 썼습니다.
- Chameleon은 이미지 토큰 16,384개의 임베딩·출력 행이 늘어 N이 커집니다(0.16B에서 $2\times16384\times768$ = 0.025B, 15%). 그림 5는 같은 N을 썼으므로, 표 2의 N이 어느 쪽 파라미터인지(임베딩 포함 여부) 논문에서 확인되지 않습니다. 이 차이는 0.16B에서 15%이고 7B에서는 약 2%입니다.
- 6ND는 어텐션 제곱항을 뺀 값입니다(각주 15: 일부러 이론 FLOPs를 씀). 7B, 길이 4,096에서 어텐션 항은 6N 대비 약 7%입니다(근사, `compute_check.py`).

### 2.2 U-Net 추가 파라미터와 표 9의 7.3B
- 표 7의 ΔEnc/Dec(%) × 크기로 역산한 U-Net 파라미터: 0.17B(0.16B 행), 0.264B, 0.270B, 0.270B, 0.266B(7B 행). §4.1의 "모든 구성에서 0.27B"는 0.37B 이상에서만 맞고 0.16B 행은 0.27B라면 166%여야 하는데 표는 106.1%입니다. 가장 작은 행에서 U-Net이 작았을 가능성(트랜스포머 폭 768과의 연결층 크기 차이)이 있으나 논문에 설명이 없습니다.
- 표 9의 "Transfusion (Ours) 7.3B"는 6.74B + 0.27B = 7.01B와 **약 0.29B** 다릅니다. 표 7은 같은 7B U-Net을 3.8% 증가로 적고 있어서 표 9의 7.3B 출처(예: 임베딩 이중 계산)는 논문으로 확인되지 않습니다. 영향은 파라미터 비교(표 9의 "Model Params" 열)뿐이고 학습 FLOPs는 6N·D에서 약 4% 변합니다.

### 2.3 같은 FLOPs에서 본 이미지 수 (각주 13)

| Transfusion 1×1 잠재 패치(표 6 "None") | 1,024 | 0.244B | 0.64 |

| Transfusion 8×8 | 16 | 15.6B | **41.1** |

- 본 비교(§4.2)에서 **Transfusion은 같은 FLOPs로 약 4.0배 많은 이미지를 학습**합니다(2×2 대 VQ). 그림 5의 이득 일부는 이 효과일 수 있고, 논문의 "데이터를 통제했다"는 표현은 토큰 수·FLOPs 통제이고 이미지 수 통제가 아닙니다. 이미지당 1,024 요소인 Transfusion 1×1(표 6 "None")과 Chameleon의 비교는 이 논문에 없습니다. 이 분리가 가장 필요한 빠진 실험입니다.
- **표 6의 패치 크기 절제도 같은 이유로 혼재됩니다:** 8×8은 380M 이미지를 41번 도는 셈이어서(과적합 가능) "U-Net이 큰 패치를 견딘다"는 결과(표 6)에는 "더 많은 이미지·노이즈를 봤다"가 섞여 있습니다. 논문도 "더 많은 이미지와 확산 노이즈를 봤기 때문일 수 있다"고 적습니다(§4.3.2).
- §4.4: 692M × 5 에폭 × 256 패치 = 0.886T, 본문 "3.5B 쌍 × 256" = 0.896T로 이미지 쪽 약 1T와 맞습니다(캡션 토큰 제외).

### 2.4 학습 FLOPs 동등과 서비스 비용
이미지 한 장 생성 FLOPs(7B, KV 캐시 가정, 어텐션 제곱항 제외, $2N$/토큰): Transfusion은 250 스텝 × 256 패치 = 64,000 위치를 계산하고 Chameleon은 1,024 토큰을 계산합니다. 비율 **62.5배**(CFG는 양쪽에 2배라 상쇄). 논문 서두의 "서빙 비용을 최대 64× 줄일 수 있다"는 1×1(1,024 패치)에서 8×8(16 패치)로 줄인 Transfusion 안의 비율(1024/16)이고 Chameleon 대비가 아닙니다. 따라서 §4.2의 "34× 적은 계산"은 학습 FLOPs의 이야기입니다.

### 3.3 외삽과 방법상 주의
- **외삽 여부:** 목표 FLOPs(A: 8e20–1.3e22)가 모두 Transfusion 점의 FLOPs 범위(1e20–2.0e22) 안이라 내삽입니다. Chameleon 7B는 자기 점 범위의 오른쪽 끝입니다. 변형 A는 Chameleon 맞춤선을 쓰지 않으므로 Chameleon의 하한 필터(FID 5점, CLIP 9점 제거)가 A에는 영향이 없습니다(B에는 있음).
- **비율은 상수가 아닙니다:** 두 선이 평행하지 않아서 Chameleon FLOPs에 따라 비율이 변합니다(변형 B 기준. FID: 2e20에서 0.009, 2.1e21에서 0.019, 2e22에서 0.041. CLIP 0.29 → 0.50. PPL은 0.42 → 0.65). 논문 서술 "선이 거의 평행"과 달리 **7B(가장 큰 값)에서 비율이 가장 큽니다**(격차가 줄어듦). 선을 그대로 늘리면 FID에서 약 3e26 FLOPs, C4 PPL에서 약 4e24 FLOPs에서 교차합니다(7B 0.5T의 1.4만 배와 200배, 외삽이므로 예측으로 읽지 않음). 반대로 CIDEr(0.29 → 0.22)과 Llama 정확도(0.77 → 0.50)는 규모가 클수록 격차가 커집니다.
- **체크포인트는 같은 학습의 중간 시점:** 학습률은 4,000 스텝 워밍업 후 코사인으로 1.5e-5까지 감쇠하며 250k 스텝에 걸쳐 감쇠합니다(§4.1). 0.1–0.4T 체크포인트는 감쇠가 끝나지 않은 상태입니다. 두 방법이 같은 일정이라면 비율에 일차로는 영향이 작지만 Chameleon은 최대 학습률이 1e-4(Transfusion 3e-4)라서 중간 체크포인트의 불이익이 다를 수 있습니다(가설, 검증 못함). "동등 FLOPs의 최적 곡선"과는 다른 곡선입니다.

- CIDEr에서 Chameleon의 이상점 두 개(1.6–1.9e21에서 약 4.7)를 빼고 다시 맞추면 비율(B 변형) 0.211로 변화가 작습니다.

- **표 4:** 괄호 차이는 재계산해서 모두 맞습니다(+0.3/+0.2/−2.0, +0.9/+0.5/−1.8, +0.8/+0.5/−3.0). Chameleon의 C4 PPL 열화가 Transfusion의 5.7배(+1.7 대 +0.3)이고 단일 실행입니다.
- **표 9:** COCO FID 6.78은 Parti 7.23, Imagen 7.27, DeepFloyd 6.66과 1 이내이고 서로 다른 평가 프로토콜의 보고값(CFG를 벤치마크마다 조정, §4.1)이라 순위를 정할 수 없습니다. GenEval 0.63 대 DeepFloyd 0.61, SDXL 0.55: 프롬프트 수가 약 553이면 이항 SE ≈ 0.02(미확인 값 사용)이므로 0.63 대 0.61은 구별되지 않고 0.55와의 차이(0.08)가 약 4 SE입니다. 이 문장은 프롬프트 수 확인 전에는 조건부입니다.
- **표 간 일관성:** 같은 설정이 나오는 칸은 정확히 일치합니다. 표 5 선형 양방향 = 표 6 선형 2×2 = 표 7 0.76B 선형, 표 5 U-Net 양방향 = 표 6 U-Net 2×2 = 표 7 0.76B U-Net = 표 8 0.76B 제한 없음, 표 7 7B U-Net = 표 8 7B 제한 없음, 표 4의 Transfusion 텍스트 3칸 = 표 5의 선형 텍스트 3칸. 표 5·6의 열 머리 "Acc (↓)"는 오타입니다.
