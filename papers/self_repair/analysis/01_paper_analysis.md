# 01. 논문 분석

**Is Self-Repair a Silver Bullet for Code Generation?** Theo X. Olausson, Jeevana Priya Inala, Chenglong Wang, Jianfeng Gao, Armando Solar-Lezama (MIT CSAIL, Microsoft Research). arXiv:2306.09896, 판본 v5 (2024-02-02). ICLR 2024 포스터.

- 분석 판본: v5 (PDF `paper/paper.pdf`, 49쪽, 본문 9쪽 + 참고문헌 + 부록 A–H).
- 이전 판과의 차이: arXiv 주석에 따르면 v5는 Code Llama 실험을 추가하고, Code Llama의 HumanEval 자기 수리 수치를 망친 데이터 처리 오류를 고쳤습니다. v1 수치는 쓰지 않았습니다.
- 라이선스: CC BY 4.0 (arXiv abs 페이지 확인).

## 1. 문제

LLM이 어려운 코드 과제(APPS 경쟁 문제, HumanEval)에서 틀릴 때, 같은 모델에게 자기 코드를 고치게 하면(self-repair) 성능이 오르는가. 기존 연구는 샘플 예산을 따지지 않거나 한 가지 설정만 봤습니다. 저자들은 "같은 예산의 i.i.d. 샘플링과 비교하면 어떤가"를 묻습니다. 그리고 수리 성능이 "진단"(모델이 자기 코드의 어디가 왜 틀렸는지 말하는 능력)에 달려 있다고 가설을 세웁니다.

## 2. 방법

**4단계 파이프라인** (Section 3.1, Figure 1)
1. 코드 생성: n_p개 i.i.d. 샘플 p_i ∼ M_P(ψ)
2. 실행: 테스트 실행 → 오류 메시지 e_i
3. 피드백 생성: n_f개 피드백 f_ij ∼ M_F(ψ; p_i; e_i)
4. 수리: n_r개 후보 r_ijk ∼ M_P(ψ; p_i; e_i; f_ij)

M_P와 M_F를 같은 모델로 두면 피드백과 수리를 한 번에 샘플할 수 있습니다(joint sampling, Section 3.1, Appendix G). 저자들은 이를 "진짜 자기 수리"라 부릅니다.

**수리 트리와 pass@k** (Section 3.2)
- 수리 트리 T 하나를 샘플 한 덩어리로 보고, 예산은 |programs(T)| = n_p + n_p·n_fr 입니다.
- 비교 기준은 같은 예산 k의 i.i.d. pass@k입니다.
- 계산을 줄이려고 Np=50, Nf=25, Nt=1000 크기의 큰 트리를 한 번 만들고 부분 표본을 복원추출합니다(bootstrap).
- 부록 A는 예산을 토큰 수로 잰 pass@t도 보입니다. 피드백 토큰도 비용이므로, 예산을 샘플 수로 보면 자기 수리가 과대평가될 수 있다는 문제를 다룹니다.

**모델과 데이터** (Section 4)
- CodeLlama-13b-instruct, GPT-3.5 (gpt-3.5-turbo-0301), GPT-4 (gpt-4-0314). 온도 0.8.
- HumanEval (164개) 과 APPS에서 무작위 300과제 (입문 60, interview 180, competition 60).
- 메인 설정: HumanEval은 약한 모델 CodeLlama와 강한 모델 GPT-3.5, APPS는 강한 GPT-4와 약한 GPT-3.5.

## 3. 주요 결과

| 질문 | 결과 (논문 위치) |
|---|---|
| 같은 예산에서 자기 수리가 낫나 (RQ a) | 흔히 조금 낫거나 차이가 없고, 작은 예산에서는 오히려 낮습니다. APPS GPT-4는 np 증가와 함께 최대 8% 우위 (Fig. 3b). |
| 어떤 설정이 낫나 | 초기 샘플 수 n_p를 늘리는 것이 수리 횟수 n_fr을 늘리는 것보다 낫습니다 (Sec 4.1, Fig. 3–4 히트맵). |
| 더 강한 피드백 모델이 도움이 되나 (RQ b) | 그렇습니다. CodeLlama의 피드백을 GPT-4로 바꾸면 HumanEval과 APPS 모두에서 자기 수리보다, 그리고 기준선보다 낫습니다 (Sec 4.2, Fig. 5). |
| 사람이 피드백을 주면? (RQ c) | 40개 실패 프로그램에 대해 사람 피드백은 GPT-4 수리 통과율을 33.3%에서 52.6%로 1.58배 올립니다 (Table 1, 16명 참가). |

**Table 2 (수리 성공률, APPS):** 입문 → 경쟁으로 갈수록 떨어집니다. GPT-4 전체 10.8%.

**결론 (Sec 6):** 자기 수리는 "은탄환"이 아니고, 현재 모델은 "무엇이 왜 틀렸는지"를 믿을 만하게 말하지 못하는 것이 병목입니다.

## 5. 한계 (저자 서술 기준)

- 자기 완결형 Python 과제와 실행 가능한 단위 테스트만 다룹니다. 실제 소프트웨어 개발과는 다릅니다 (Sec 5).
- 과제 수가 적습니다 (APPS 300, 인간 실험 20과제 40프로그램).
- 수리 실험은 한 고정 데이터에서 부트스트랩하므로 과제 표본의 분산을 반영하지 않습니다 (Sec 5). 우리 재계산에서 이 차이가 중요하다는 것을 확인했습니다 (`03` V5).
- 인간 실험은 수리 시간을 재지 않았습니다 (Sec 5).

## 6. 이 논문에서 가져갈 것

- **진단 품질이 병목이라는 가설과 증거.** 피드백 출처를 바꾸는 실험(Sec 4.2)이 가장 깨끗한 대비입니다. 같은 수리 모델에 피드백만 바꿉니다.
- **예산 기준.** 샘플 수로 예산을 재면 피드백 비용이 빠집니다. 우리 연구에서도 같은 함정이 있는지 확인해야 합니다.
- **통계 보고.** 이 논문은 과제 단위 불확실성을 보고하지 않습니다. 우리가 비교 연구를 쓴다면 과제 단위 부트스트랩 구간을 같이 보고해야 합니다.
