# 03. 분석과 재계산

논문: Olausson et al., *Is Self-Repair a Silver Bullet for Code Generation?* (arXiv:2306.09896v5, ICLR 2024)
검증 모드. 재계산 스크립트는 `analysis/`에 있고, 결과는 `*_results.json`에 있습니다. 모든 수치는 우리가 다시 계산한 값입니다. 논문 값과 다르면 따로 적습니다.

## 0. 데이터와 방법

| 자료 | 출처 | 쓴 곳 |
|---|---|---|
| 인간 피드백 실험 표(Appendix E, 20과제 x 2 프로그램 x 4 피드백 x 25 수리) | 논문 부록 E 표를 옮겨 적음 | V1–V3 (`recompute_human_study.py`) |

| APPS GPT-3.5 원자료 `all-chatgpt-…` 와 `mp-chatgpt-mf-gpt4-nf-10-…` | 같은 tarball | V10–V11 (`apps_feedback_check.py`) |
| processed JSON (GPT-4 APPS full-kn, GPT-4 HumanEval) | 저장소 `paper/data/*/processed/` (git-lfs) | V4 교차 검산 |

**정확 기댓값 모델.** 저자 코드 `paper/analysis/sample-and-estimate.py`는 복원추출 Monte Carlo(1000회)로 pass rate를 냅니다. 우리는 같은 식을 닫힌 형태로 풀었습니다. 과제 t의 기본 프로그램 통과 비율을 p_t, 실패한 기본 프로그램 b의 수리 통과 비율을 q_b라 하면 다음과 같습니다.

- 기준선 pass@k: S_base(t,k) = 1 − (1 − p_t)^k
- 자기 수리 (np, nfr): a_t = (1/50) Σ_{b 실패} (1 − q_b)^nfr, S_sr(t) = 1 − a_t^np
- 정규화 값 = 과제 평균 S_sr / 과제 평균 S_base(t, k), k = np(1 + nfr). 논문 히트맵의 정의와 같습니다.

**검산.** 기준선 (1,0)의 평균은 우리 0.39513이고, 저자 processed JSON의 (1,0) 값은 0.39502입니다. 차이는 저자 Monte Carlo 잡음(0.0001) 수준입니다.

**불확실성.** 논문의 오차막대는 한 번 뽑은 고정 데이터에서 수리 트리를 다시 뽑는 분산만 반영합니다. 과제 300개를 뽑은 표본 분산은 반영하지 않습니다. 그래서 과제 단위 부트스트랩(10,000회, 복원추출)을 따로 냈습니다. 인간 실험은 과제가 20개뿐이라 과제 단위로 부트스트랩했습니다.

## 1. 인간 피드백 실험 (Table 1, Appendix E)

| 구분 | GPT-4 피드백 | 사람 피드백 | 비율 (사람/GPT-4) |
|---|---|---|---|
| 전체 (40 프로그램) | 666/2000 = 33.30% | 1052/2000 = 52.60% | 1.580 |
| 입문 (28 프로그램) | 597/1400 = 42.64% | 871/1400 = 62.21% | 1.459 |
| interview (6 프로그램) | 58/300 = 19.33% | 137/300 = 45.67% | 2.362 |
| competition (6 프로그램) | 11/300 = 3.67% | 44/300 = 14.67% | 4.000 |

- **V1 (재현됨).** 전체 33.30%, 52.60%, 비율 1.58, 난이도별 값 여섯 개가 논문 Table 1과 모두 일치합니다.
- **V2 (재현됨, 표본은 작음).** 프로그램 단위로 사람 피드백 통과율이 높은 쪽은 20개, GPT-4 쪽은 5개, 같음은 15개입니다. 동점을 뺀 양측 부호 검정 p = 0.0041입니다. 프로그램 평균 차이를 부호 뒤집기 순열로 본 p는 0.00025입니다. 과제 단위 부트스트랩 비율의 95% 구간은 1.24–2.33입니다. 과제가 20개뿐이라 구간이 넓습니다.
- **V3 (주의).** 논문은 "난이도가 높을수록 상대 차이가 커진다"고 씁니다. 상대 비율은 1.46 → 2.36 → 4.00으로 실제로 커집니다. 그러나 절대 차이는 19.6 → 26.3 → 11.0 pp로 단조롭지 않습니다. competition은 프로그램 6개(수리 300개)뿐이라 신뢰하기 어렵습니다. 인용할 때는 "상대 비율은 커지지만 절대 차이는 interview에서 가장 크다"고 적어야 합니다.

## 4. 피드백 품질이 병목인가 (Section 4.2, Figure 5의 APPS 부분)

GPT-3.5 기본 프로그램은 같고(두 파일의 mean pass 0.23067이 같음), 수리 모델은 GPT-3.5로 같습니다. 바뀌는 것은 피드백 출처뿐입니다. 정규화는 각 파일 자체의 pass@k 기준선으로 합니다. A는 GPT-3.5 자기 피드백(수리 25개), B는 GPT-4 피드백(수리 10개)입니다.

| np (k=2np) | A: GPT-3.5 자기 수리 | B: GPT-4 피드백 | B − A (과제 부트스트랩 95% 구간) |
|---|---|---|---|
| 1 (2) | 0.914 [0.894, 0.934] | 1.092 [1.055, 1.138] | +0.135 ~ +0.229 |
| 2 (4) | 0.952 [0.933, 0.971] | 1.111 [1.074, 1.155] | +0.117 ~ +0.209 |
| 5 (10) | 0.977 [0.958, 0.996] | 1.117 [1.081, 1.161] | +0.100 ~ +0.189 |
| 10 (20) | 0.997 [0.978, 1.017] | 1.120 [1.083, 1.166] | +0.080 ~ +0.174 |
| 25 (50) | 1.040 [1.015, 1.070] | 1.140 [1.094, 1.197] | +0.046 ~ +0.161 |

(B − A 구간은 `apps_feedback_results.json`의 `B_minus_A_ci95`입니다. 각 값은 과제 부트스트랩 95% 구간입니다.)

- ****V10 (재현됨, 강하게 지지됨).** 피드백만 바꾸면 모든 np에서 B가 A보다 높고, B의 구간이 1 위에 있습니다. 논문의 "약한 모델의 피드백을 강한 모델 것으로 바꾸면 자기 수리 이득이 나타난다"는 주장과 맞습니다.
- ****V11 (보충).** A(GPT-3.5 자기 수리)는 np ≤ 10에서 1 아래입니다. np=25에서만 1.04로 구간이 1 위입니다. 논문의 "자기 수리는 작은 예산에서 손해"라는 서술과 맞습니다.
- **한계.** 피드백 출처는 GPT-4 하나만 봤습니다. 수리 모델이 같아도 B는 피드백을 10개만 쓰고 A는 25개를 씁니다. 두 설정의 피드백 개수 차이는 통제되지 않았습니다. HumanEval에서는 확인하지 않았습니다.

## 5. 인간 피드백 실험의 독립성 (확인 필요)

부록 D는 참가자에게 "오류 메시지와 GPT-4 피드백 두 개를 함께 준다"고 씁니다. 이 문장을 그대로 읽으면, 참가자가 GPT-4 피드백을 본 상태에서 자기 설명을 썼을 가능성이 있습니다. 그렇다면 사람 피드백이 GPT-4 피드백에 기대고 있을 수 있습니다. 슬라이드 지시문(이미지)은 텍스트로 확인하지 못했습니다. 이 점은 저자 확인이 필요합니다.
