# 03. 분석: BLIP-2 (arXiv:2301.12597)

식과 마스크 검산, 파라미터 산술, 논문 표 재계산, 직접 짠 최소 구현과 공식 코드의 정적 대조, 합성 데이터 토이 실험을 모았습니다. **토이는 논문 재현이 아닙니다.** 논문 수치는 하나도 재측정하지 않았고(가중치와 데이터를 받지 않음), 토이는 구조 수준의 성질(마스크, 고정 개수 압축, 2단계)이 작은 규모에서 어떻게 보이는지 이해하려는 것입니다. 모든 수치는 `derivation_results.json`, `toy_results.json`에서 옵니다.

## 1. 마스크, 식, 파라미터 검산 (`derivation_checks.py`, pytest)

### 1.1 세 마스크와 정보 흐름

질의 K = 3, 텍스트 T = 4의 마스크 행렬입니다(행이 보는 쪽, 열이 보이는 쪽, x = 볼 수 있음. `derivation_results.json` `masks_K3_T4`).

```
ITC (단일 모달)        ITG (다중 모달 인과)    ITM (양방향)
    Q0 Q1 Q2 T0 T1 T2 T3     Q0 Q1 Q2 T0 T1 T2 T3     Q0 Q1 Q2 T0 T1 T2 T3
Q0   x  x  x  .  .  .  .  Q0  x  x  x  .  .  .  .  Q0  x  x  x  x  x  x  x
Q1   x  x  x  .  .  .  .  Q1  x  x  x  .  .  .  .  Q1  x  x  x  x  x  x  x
Q2   x  x  x  .  .  .  .  Q2  x  x  x  .  .  .  .  Q2  x  x  x  x  x  x  x
T0   .  .  .  x  x  x  x  T0  x  x  x  x  .  .  .  T0  x  x  x  x  x  x  x
T1   .  .  .  x  x  x  x  T1  x  x  x  x  x  .  .  T1  x  x  x  x  x  x  x
T2   .  .  .  x  x  x  x  T2  x  x  x  x  x  x  .  T2  x  x  x  x  x  x  x
T3   .  .  .  x  x  x  x  T3  x  x  x  x  x  x  x  T3  x  x  x  x  x  x  x
```

- **ITC:** 질의 블록과 텍스트 블록이 완전히 분리됩니다. 텍스트 표현은 이미지에 의존하지 않고 질의 표현은 텍스트에 의존하지 않습니다. 이는 대조 학습의 전제(두 인코더의 출력을 따로 계산)와 같습니다. 텍스트 블록 안은 양방향입니다(텍스트 인코더).
- **ITG:** 질의 → 텍스트 열이 모두 막혀서 **질의 출력은 텍스트가 무엇이든 같습니다.** 텍스트 행 T0이 질의 3개와 자기 자신까지 볼 수 있고, 아래 행으로 갈수록 앞쪽 텍스트가 늘어나는 하삼각입니다.
- **이미지가 텍스트에 닿는 경로.** 이미지 특징은 **교차 attention을 통해 질의 위치에만** 들어갑니다(텍스트 위치에는 교차 attention이 없음). 그러므로 ITG에서 텍스트가 이미지를 알려면 반드시 [이미지 → 질의(교차 attention) → 텍스트(self-attention)] 경로를 거쳐야 하고, 텍스트 생성에 필요한 시각 정보는 **질의 32개가 전부 담아야** 합니다(§3.2의 설명). 질의가 텍스트를 못 보므로 "무엇을 묻는지" 모른 채 압축합니다.
- **12층, 교차 attention이 층 0, 2, ..., 10에 있는 모델에서 층별로 측정**(`image_reach_12_layers`): 이미지를 바꿨을 때 질의 표현은 층 0부터, **텍스트 표현은 ITG, ITM에서 층 1부터** 달라지고 ITC에서는 끝까지 달라지지 않습니다. 즉 텍스트가 이미지 정보를 받을 수 있는 층은 12층 중 11층입니다. pytest `test_image_info_reaches_text_only_after_first_cross_layer`가 4층 모델에서 같은 사실을 확인합니다.
- ITM은 질의와 텍스트가 서로 보므로 질의 출력이 "이 쌍이 맞는가"를 담습니다. 논문이 ITM 점수를 **질의별 2-클래스 로짓의 평균**으로 정의하는 것(§3.2)도 질의 출력이 모두 멀티모달이기 때문에 가능합니다(우리 구현·시험 `test_stage1_loss_shapes_and_itm_layout`).

### 1.2 ITC 유사도와 손실

- 유사도 정의(§3.2): sim(i, j) = max_k ⟨z_ik, t_j⟩ (정규화된 투영 뒤). K = 1이면 일반 코사인 유사도로 환원됩니다(`test_itc_score_is_max_over_queries`가 K = 1 환원과 수동 최댓값 루프 일치를 확인).
- 텍스트→이미지 방향 유사도 max_k⟨t_i, z_jk⟩는 **같은 점곱의 최댓값이라 이미지→텍스트 행렬의 전치**입니다. 그래서 대칭 손실은 한 행렬만으로 계산됩니다(우리 구현). 공식 코드는 두 방향을 따로 계산하지만 결과는 같습니다(`04` D3).
- **라벨 평활화(코드 ε = 0.1)의 바닥값.** 배치 B에서 ITC 손실은 0이 될 수 없고 평활화된 목표의 엔트로피 H = −(1−ε+ε/B) ln(1−ε+ε/B) − (B−1)(ε/B) ln(ε/B)가 하한입니다. B = 2320(논문 ViT-L 1단계 배치)에서 **1.0995**, B = 1680에서 1.0671입니다(식과 PyTorch가 5자리까지 일치, `itc_label_smoothing_floor`). 우리 토이(B = 64)의 하한은 **0.729**입니다(진행 중 관찰한 ITC 손실 0.80은 이 하한 위). 따라서 공식 학습 로그에서 ITC 손실이 1.1 근처에서 멈추는 것은 정상입니다.
- **어려운 음성의 유효 후보 수.** ITM의 어려운 음성은 softmax(sim/τ)에서 표본추출하며 τ = 0.07입니다. 무작위 유사도(평균 0.2, 표준편차 σ)에서 B = 2320일 때 유효 후보 수 exp(H)(softmax 엔트로피의 지수)는 σ = 0.05, 0.10, 0.20에서 각각 **1,797, 842, 69**이고, B = 64에서는 49, 27, 6.3입니다(`hard_negative_effective_candidates_tau0.07`). 유사도가 흩어질수록 후보가 줄어들고 σ가 0.2쯤 되어야 소수에 쏠립니다. 학습 초기에는 사실상 무작위 음성에 가깝고, 정렬이 좋아진 뒤에야 "어려운" 음성이 됩니다(추정).

### 1.3 파라미터 수와 출력 토큰 수

논문 §3.1: Q-Former 188M, 출력 32 x 768, 이미지 특징 예 257 x 1024. LAVIS 구조(BERT-base + 층마다 질의용 FFN + 격층 교차 attention)로 편향과 LayerNorm까지 센 닫힌 식(`minimal_impl.qformer_param_count`)의 결과입니다. 이 식은 같은 구조를 직접 짠 토이 모듈의 실제 파라미터 수와 정확히 일치함을 시험으로 확인했습니다(`test_toy_param_formula_matches_module`).

| 항목 | 우리 산술 | 논문 |
|---|---|---|
| 1단계 Q-Former 전체 (BERT-base, ViT-g 폭 1408, 질의 32) | **186.7M** (임베딩 23.8 + 층 141.7 + 교차 attention 20.1 + LM 헤드·투영 약 1.0) | 188M (§3.1, 표 1). 차이 −0.7% |
| 같은 구조에서 질의용 FFN을 뺄 때 | **130.0M** | (188M과 맞지 않음) |
| 2단계 학습 파라미터 ViT-L OPT-2.7B | 103.6M | 104M (표 2) |
| ViT-g OPT-2.7B | 107.1M | 107M |
| ViT-g OPT-6.7B | 108.3M | 108M |
| ViT-L FlanT5-XL | 103.2M | 103M |
| ViT-g FlanT5-XL | 106.7M | 107M |
| ViT-g FlanT5-XXL | 108.3M | 108M |

- 188M은 **질의용 FFN이 층마다 따로 있어야만** 맞습니다(없으면 130M). 논문은 "같은 self-attention 층을 공유"만 적고 이 사실을 적지 않았습니다(`04` D2). 남는 1.3M(0.7%)은 설명하지 못했습니다(토큰 유형 임베딩, 묶이지 않은 헤드 가정 등 후보가 있으나 가중치를 받지 않아 확인 불가).
- **표 2의 104–108M은 2단계에서 텍스트 쪽(어휘·위치 임베딩, 텍스트 FFN, LM 헤드)을 떼어 낸 질의 경로**입니다(코드가 그것들을 `None`으로 설정, `blip2_opt.py` L78–L83). 이미지 인코더 폭(ViT-L 1024 대 ViT-g 1408)이 교차 attention의 키·값 투영 크기를 바꿔 약 3.5M 차이를 만들고, LLM 은닉 차원이 선형 투영 크기를 바꿉니다. 6개 표 값이 모두 0.3M 안에서 일치합니다.
- **"54배"**: 10.2B / 188M = 54.3. 표 2의 108M으로 나누면 **94.4배**(`flamingo_ratio_54x`). 8.7점 차는 65.0 − 56.3 = 8.7로 맞습니다.
- 출력 토큰: 32 x 768 = 24,576개 값. ViT-L/14 224px의 특징 257 x 1024 = 263,168개(10.7배), ViT-g/14의 257 x 1408 = 361,856개(14.7배). 토큰 수로는 257 → 32(8배)이고, LLaVA-1.5의 336px 576토큰과 비교하면 **18배** 적습니다. 257 = (224/14)² + 1(CLS)입니다(`token_counts`). 이 압축이 LLM 입력 길이와 지연에는 직접 이득이지만 위 값 수의 압축은 정보 병목이기도 합니다(§4).

## 2. 논문 표 재계산

(데이터셋 크기는 논문에 없는 일반 지식으로 가정했습니다: VQAv2 test-dev 약 107,394문항, GQA test-dev 12,578, OK-VQA test 5,046, COCO 검색 5K 이미지 / 25,000 캡션. 같은 문항에 대한 두 모델 비교라 짝지은 오차는 더 작으므로, 아래 SE는 비짝 이항 근사의 **보수적 상한**입니다. 모델 시드 분산과 평가 프롬프트·빔 설정 분산은 포함되지 않아 실제 불확실성은 더 큽니다. `derivation_results.json` `table_recompute`.)

### 2.1 표 사이 일치

표 1의 BLIP-2 VQAv2 65.0 = 표 2의 ViT-g FlanT5-XXL test-dev 65.0, 표 1의 NoCaps CIDEr 121.6 = 표 3의 FlanT5-XL overall 121.6, 표 1의 Flickr TR@1 97.6와 IR@1 89.7 = 표 5의 ViT-g 행, 표 6의 ITG 포함 행(85.4/97.0, 68.3/87.7) = 표 5의 COCO 미세조정 ViT-g 행으로 모두 맞습니다. 그림 5의 80k 스텝 값(OPT 약 54, FlanT5-XL 약 63)도 표 2의 val 54.3과 63.1에 맞습니다(그림에서 읽은 근사값).

### 2.2 표 2: "더 강한 인코더나 더 큰 LLM이 낫다" (§4.1)

| 비교 (VQAv2 test-dev) | 차이 | SE(상한) | z |
|---|---|---|---|
| ViT-g − ViT-L (OPT-2.7B) | +2.6 | 0.22 | 12.1 |
| ViT-g − ViT-L (FlanT5-XL) | +0.7 | 0.21 | 3.4 |
| OPT-6.7B − OPT-2.7B (ViT-g) | **+0.3** | 0.22 | **1.4** |
| FlanT5-XXL − FlanT5-XL (ViT-g) | +2.0 | 0.21 | 9.7 |
| FlanT5-XL − OPT-2.7B (ViT-g) | +10.7 | 0.21 | 50 |

- 인코더 이득은 OPT에서 크고(+2.6) FlanT5에서 작습니다(+0.7). **LLM 쪽에서는 OPT 크기 2.7B → 6.7B가 +0.3(1.4 SE, 표본 오차 안)**인데, 같은 격차가 OK-VQA(31.7 → 36.4)와 GQA(34.6 → 36.4)에서는 큽니다. "큰 LLM이 낫다"는 VQAv2 test-dev의 OPT 쌍에서는 구분되지 않습니다. 가장 큰 효과는 **OPT 대 FlanT5(+10.7)**로, 크기가 아니라 지시 튜닝 계열과 평가 프롬프트(`01` §5-7)입니다.
- GQA에서 ViT-L FlanT5-XL(44.4)이 ViT-g(44.2)보다 높습니다(−0.2, SE 0.63으로 구분 불가). OK-VQA에서 ViT-g의 +1.3은 SE 0.98로 1.3σ입니다. 즉 "ViT-g가 모든 벤치마크에서 낫다"는 성립하지 않고, 인코더 효과는 VQAv2의 OPT에서만 뚜렷합니다. 논문은 세 사실 (1) ViT-g > ViT-L, (2) 같은 계열 안에서 큰 모델이 낫다, (3) FlanT5 > OPT로 요약합니다(§4.1). 이 중 (1)은 부분적, (2)는 VQAv2에서 FlanT5에는 성립(+2.0)하나 OPT에는 표본 오차 안, (3)은 확인됩니다.
- OK-VQA에서 BLIP-2 XXL(45.9)이 Flamingo80B(50.6)에 −4.7(z −4.7)로 집니다. 논문의 설명("OK-VQA는 개방 세계 지식, Chinchilla 70B가 더 많이 안다", §4.1)은 가설이며 통제 실험은 없습니다.

### 2.3 표 4와 표 6

- 표 4(VQAv2 미세조정, 개방형 생성 모델 중 최고): OPT-6.7B test-std 82.30 대 Flamingo80B 82.10(+0.2, z 1.2), 대 OFA 82.00(+0.3, z 1.8). **세 모델의 차이가 테스트 표본 오차 수준**입니다. "최고 성능"은 점 추정 순위이며 통계적 우위가 아닙니다. 또한 이 설정은 이미지 인코더를 미세조정하고(1.2B 학습) 질문을 Q-Former에 넣어 제로샷 구조와 다릅니다(`01` §5-8).
- 표 6(ITG가 검색을 돕는다): +0.9, +0.8, +1.1, +0.6. 비짝 SE로 보면 z는 1.3, 2.2, 2.6, 2.0입니다. 네 지표가 모두 같은 방향이고 두 개는 z 2 이상이나, 같은 이미지에 대한 한 번의 학습 쌍이라 **시드 분산이 빠져 있습니다.** 방향은 일관하고 크기는 확정할 수 없습니다(`04` C7).

## 3. 최소 구현 (`minimal_impl.py`)

논문 구조를 그대로 줄인 PyTorch 코드(약 630줄)입니다. 논문 ↔ 구현 대응은 다음과 같습니다.

| 논문 | 구현 |
|---|---|
| Q-Former: 질의 K개 + 공유 self-attention + 질의 위치 교차 attention(격층) + 질의용·텍스트용 FFN | `QFormer`, `QFormerBlock`(d = 64, 4층, 층 0과 2에 교차 attention, 헤드 4) |
| 마스크 세 가지 (그림 2) | `build_mask("itc" / "itg" / "itm")`, 패딩 열 가림 |
| ITC: 질의별 유사도 최댓값, 배치 내 음성 | `itc_similarity`, `itc_loss`(대칭, 라벨 평활화 0.1) |
| ITM: 질의 로짓 평균, 유사도 기반 어려운 음성 | `sample_hard_negatives`(softmax 표본추출), `stage1_losses`(배치 [양성 B, 음성 2B]) |
| ITG: 인과 마스크, [DEC] 첫 토큰 | `stage1_losses` |
| 2단계: 선형 투영 → LLM 입력 앞에 소프트 프롬프트 | `QFormerConnector`, `TinyDecoder(prefix=...)` |
| 고정된 이미지 인코더, 고정된 LLM | `FrozenImageEncoder`(무작위 초기화 후 `requires_grad=False`), `TinyDecoder`를 텍스트로 사전학습한 뒤 `freeze` |
| 대비 연결기 | `MLPConnector`(모든 패치, LLaVA-1.5식), 2x2 풀링 변형 |

**pytest 21개**(CPU 약 6초): 세 마스크 행렬이 그림 2와 같음, 패딩 열 가림, ITC에서 텍스트가 이미지에 의존하지 않고 질의가 텍스트에 의존하지 않음, **ITC 마스크 한 번의 순전파 = 공식 코드처럼 질의와 텍스트를 따로 돌린 결과**, ITG에서 질의가 텍스트를 바꿔도 같고(텍스트 없이 돌린 것과도 같음) 텍스트는 이미지에 의존함, ITG 인과성, ITM 양방향, 이미지 정보가 텍스트에 닿는 첫 층이 1, 이미지 패치 수(9, 36, 64, 257)와 무관하게 출력이 K개, MLP 연결기의 토큰 수는 패치 수에 따라 늚, ITC 점수 = 질의별 유사도 최댓값, 어려운 음성이 양성을 안 뽑고 유사도를 따름, ITM 배치 배치, 1단계가 작은 배치를 과적합함, **고정 모듈(인코더, 디코더)에 기울기가 없고 최적화 한 스텝 뒤에도 값이 그대로**이며 Q-Former와 투영에는 기울기가 있음, 소프트 프롬프트가 입력 앞에 붙고 인과적임, 합성 장면과 문답 일관성, 토이 파라미터 닫힌 식 = 실제 개수, 교차 attention 층 위치와 188M·104/107/108M 산술.

## 4. 합성 장면 토이 (`run_experiments.py`, 5시드)

**토이는 논문 재현이 아닙니다.** 질문은 "고정 개수 압축이 어떤 과제에서 손해를 보는가, MLP 투영기와 비교하면 어떤가, 1단계는 무엇을 하는가"를 구조 수준에서 보는 것입니다. 모든 수치는 `toy_results.json`(시드별 값은 `toy_seed*.json`)입니다.

### 4.1 설정

- **장면:** 8 x 8 칸에 색 물체 1–4개(색 6종, 서로 다른 색, 서로 다른 칸). 가능한 장면은 약 27.8비트(`toy_scene_bits`).
- **고정된 이미지 인코더:** 칸마다 (rgb x 점유, 점유)를 무작위 MLP에 통과시키고 칸 위치 임베딩을 더한 32차원 패치 특징 64개. 무작위 초기화 후 고정(`requires_grad=False`). 정보는 보존하지만 의미 있게 정렬되어 있지 않습니다.
- **고정된 디코더("LLM"):** 3층, 96차원, RoPE, 23.4만 파라미터. **텍스트만으로** 사전학습한 뒤 고정합니다. 학습 입력은 [캡션(물체를 "색 at 행 열 and ..."로 적은 글) + 질문 3개 + 답]이고 이미지는 보지 않습니다. 사전학습 뒤 **정답 캡션을 글자로 주었을 때의 정확도(오라클, 연결기의 상한 어림)**: 개수 100%, 색 존재 100%, 행 판별 95.8%, **위치(행과 열 모두) 78.0%**(물체 1개 100%, 2개 81.9%, 3개 70.5%, 4개 59.8%)입니다(`decoder_check.json`). 디코더가 위치 질문에서 완벽하지 않아 위치 정확도는 이 상한 아래로 봐야 합니다.
- **네 질문 유형**(소프트 프롬프트 뒤에 질문, 답 토큰을 탐욕 디코딩, 정확 일치): 개수(우연 25%), 색 존재(**"예"가 70.8%라 다수 답 기준선이 70.8%**), 위치(행과 열 두 토큰, 우연 1.6%), 행 판별("is the red at r3 ?", 우연 50%).
- **Q-Former:** d = 64, 헤드 4, 4층(교차 attention 층 0과 2), 질의용·텍스트용 FFN 분리, 24.4–24.6만 학습 파라미터. 2단계에서는 질의 출력을 선형 투영해 디코더 앞에 소프트 프롬프트로 붙입니다. Q-Former는 질문을 보지 않습니다(논문 제로샷 설정과 같음). **MLP 연결기:** 패치 64개를 각각 2층 MLP로 투영해 64토큰을 그대로 넘깁니다(LLaVA-1.5식). 풀링 변형은 2 x 2 평균 풀링으로 16토큰.
- **학습:** 2단계는 배치 128, AdamW 1e-3(워밍업 100, 코사인 감쇠), **2,000스텝**. 1단계는 배치 64, 2e-3, 2,500스텝(ITC + ITM + ITG, 1:1:1). 평가는 유형당 500장면, 5시드(시드마다 연결기 초기화, 데이터 스트림이 다름. 고정 인코더와 디코더는 모든 시드가 공유). 구간은 시드 평균의 t 95%(자유도 4)입니다.

- **조건 없이 비교하면 오해합니다.** 파라미터가 12K인 MLP는 같은 스텝에서 K = 16 Q-Former에 졌습니다(−10.0 [−16.6, −3.4], 위치 −10.8). 그러나 MLP를 파라미터가 비슷한(239K) 크기로 키우면 평균 74.0%로 **K = 16(67.7%)을 +6.3%p [+1.7, +10.9] 앞서고 K = 32(71.7%)와는 +2.4 [−0.7, +5.5]로 구분되지 않으며**, 위치에서는 K = 32보다도 +16.9%p [+6.5, +27.2] 높습니다. 즉 "Q-Former 대 MLP"는 파라미터 수와 수렴 정도에 따라 부호가 바뀌었고, 두 번째 통제(12K MLP를 4,500스텝까지 학습, 66.7%)도 같은 방향(+8.9 [+2.7, +15.1])으로 MLP의 점수를 올렸습니다.
- **과제별 패턴(파라미터 맞춤 MLP 대비).** 개수와 행 판별은 비슷하고, **색 존재는 Q-Former가 +7.3(K=4)에서 +12.4(K=16)%p 높으며**(구간이 0 밖), **위치는 Q-Former가 K = 4에서 −39.1, 16에서 −33.3, 32에서 −16.9%p로 크게 낮습니다**(모두 구간이 0 밖). 압축이 **칸 단위 위치 조회에서 손해를 보고 전역 존재 질문에서는 이득**이라는 방향이며, K가 커질수록 손해가 줄어듭니다.
- **MLP 풀링(16토큰, 2 x 2 평균)은 MLP 전체보다 평균 2.8%p [−2.0, +7.5] 낮고 위치만 구분됩니다(+6.6 [+1.6, +11.7])**. 풀링은 칸을 합쳐 위치 정보를 잃습니다. 같은 16토큰의 Q-Former(67.7%)가 이 풀링(55.0%)보다 높은 것은 12K 대 245K 파라미터 차이와 섞여 있어 구조 효과로 해석하지 않습니다.

- **같은 2단계 스텝 수에서는 1단계가 크게 도움**이지만(+9–10%p), 그 비교는 1단계에서 이미 2,500스텝을 더 학습한 쪽입니다. **총 스텝을 4,500으로 맞춘 대조군은 오히려 1단계 + 2단계보다 높았습니다**(−7.1%p, 모든 유형에서 같은 부호, 개수 제외). 따라서 이 토이에서 1단계의 이득은 (a) 연결기가 더 오래 학습되었기 때문이고 (b) 1단계가 2단계의 질문-답 목적에 비해 그 과제에 직접 쓸모 있는 표현을 더 빨리 주지도 않았다는 뜻입니다. **논문 그림 5의 주장은 이 토이로 재현되지도 반박되지도 않았습니다.** 논문 그림 5와 우리 토이의 차이점: 논문은 대조군에 총 학습량(250k + 80k 대 80k)이 달랐고, 우리는 이를 맞춰 보았고, 토이의 2단계 과제는 1단계 캡션 형식과 비슷한 질문-답 문장이며 디코더가 캡션을 읽도록 사전학습되어 있어 1단계가 줄 것이 적었을 수 있습니다(추측).

## 5. 한계와 해석 주의

- **수렴 전입니다.** 2단계 2,000스텝에서 모든 연결기가 아직 오르는 중이었고(같은 Q-Former가 4,500스텝에서 85.2%) K 효과와 MLP 대비는 수렴 속도 차이를 포함합니다. 포화 상태의 K 효과는 측정하지 못했습니다.
- **"총 스텝을 맞춘" 대조군은 스텝 수만 맞춘 것**입니다. 1단계는 배치 64, 세 목적이라 스텝당 계산량이 더 크고 2단계는 배치 128입니다. 계산량이나 본 샘플 수로 맞추면 결과가 달라질 수 있습니다.
- **디코더의 위치 오라클이 78%.** 위치 과제는 디코더가 캡션 글자로 읽어도 틀리는 경우가 많아, 위치 수치의 해석 폭이 좁습니다. 물체가 많을수록 오라클이 낮아집니다(1개 100%, 4개 59.8%).
- **디코더가 "caption을 읽는" 모델이라** 소프트 프롬프트가 캡션 같은 토큰열일 때 유리할 수 있습니다. 실제 LLM은 이런 구조가 아니고 이는 Q-Former(특히 1단계의 ITG가 캡션 생성을 학습)에 유리한 편향일 수 있습니다(추측).
- **Q-Former가 질문을 보지 않는 설정만** 했습니다. InstructBLIP이나 BLIP-2의 VQA 미세조정(질문 조건화)은 시험하지 않았습니다.
- **고정 이미지 인코더가 무작위 MLP + 위치 임베딩**이라 CLIP 같은 의미 정렬이 없습니다. 패치 사이의 문맥 혼합이 없어(칸이 독립) 국소성은 모든 연결기에 열려 있습니다. 실제 ViT 특징에서는 칸 정보가 퍼져 있어 압축의 손해가 다르게 나타날 수 있습니다.
- **시드 5개, 시드마다 같은 고정 디코더·인코더.** 구간은 연결기 초기화와 데이터 스트림의 분산만 반영하고 디코더·인코더 선택의 분산은 포함하지 않습니다. 비교가 많아(짝지은 쌍 20여 개) 구간을 보정하지 않았습니다.
- **설계 반복의 기록.** 처음에는 "칸 (행, 열)의 색을 묻는" 유형(color_at)이 있었으나, 디코더가 캡션 글자로 읽는 오라클에서도 3,000스텝까지 물체 수만큼 후보 중 우연 수준(2개 약 50%, 3개 약 30%)에 머물러 **유형을 행 판별로 바꿨습니다.** 키(행, 열)가 값(색)보다 뒤에 오는 역방향 조회를 작은 디코더가 학습하지 못한 것으로 추정합니다. 디코더 사전학습은 8,000스텝까지 돌려 위치 오라클 78%에서 멈췄습니다(조기 종료 기준 97%에 도달 못 함).
