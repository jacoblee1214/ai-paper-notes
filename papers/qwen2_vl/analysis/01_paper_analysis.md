# 01. 논문 분석: Qwen2-VL

*Qwen2-VL: Enhancing Vision-Language Model's Perception of the World at Any Resolution* (Peng Wang 외, Qwen Team, Alibaba Group). arXiv:2409.12191. 분석 대상은 **v2 (2024-10-03, 최신)**입니다. 학회 채택 기록은 없고 기술 보고서입니다(README의 학회 표기 절).

## 1. 문제

LVLM의 입력이 고정 해상도(예: 224×224)로 다듬어지면 큰 그림의 세부가 사라지고(§1), 위치 정보를 1차원 RoPE로 넣으면 이미지의 2차원 구조와 영상의 시간 축을 표현하기 어렵다는 문제입니다(§1). 두 가지를 구조로 해결하려 합니다. (1) 이미지를 원래 해상도대로 가변 개수 토큰으로 바꿉니다. (2) 위치를 시간·높이·너비로 나눠 넣습니다. 그 위에 이미지와 영상을 한 방식으로 다룹니다.

## 2. 방법 (§2)

### 2.1 구조 (§2.1, 표 1, 그림 2)

- 틀은 Qwen-VL의 "비전 인코더 → 연결기 → LLM"을 그대로 둡니다. 비전 인코더는 약 675M ViT이고 모든 LLM 크기에서 같습니다(표 1). LLM은 Qwen2 1.5B, 7.6B, 72B입니다(표 1).
- ViT는 DFN의 ViT로 초기화하고 고정 절대 위치 임베딩을 2D-RoPE로 바꿉니다(§2.2). 깊이·폭 같은 세부는 논문에 없고 공개 config로 확인했습니다(`04`).
- **naive dynamic resolution** (§2.1): 이미지를 어떤 해상도든 가변 개수의 시각 토큰으로 바꿉니다. 해상도가 다른 이미지는 한 시퀀스로 이어 붙여(패킹) 처리하고, 길이는 GPU 메모리에 맞춰 제한합니다. ViT 뒤의 MLP가 인접한 2×2 토큰을 한 토큰으로 합칩니다. 앞뒤에 `<|vision_start|>`, `<|vision_end|>`를 붙입니다. 예: 224×224, patch 14이면 LLM 앞에서 66토큰입니다(§2.1). 이 수에는 시작·끝 토큰 2개가 들어 있습니다(`03` §2).
- **M-RoPE** (§2.1, 그림 3): 회전 임베딩을 시간·높이·너비 세 성분으로 나눕니다. 텍스트는 세 성분이 같은 위치 번호를 써서 1D-RoPE와 같아집니다. 이미지는 시간 번호가 같고 높이·너비 번호가 토큰 위치를 따릅니다. 영상은 프레임마다 시간 번호가 늘고 높이·너비는 이미지와 같습니다. 여러 모달리티가 섞이면 다음 모달리티는 앞 모달리티의 최대 번호 + 1에서 시작합니다. 논문은 이것이 위치 번호의 값을 줄여 더 긴 시퀀스로 외삽하게 해 준다고 주장합니다. **세 성분에 채널을 어떤 비율로 나누는지는 논문에 없습니다**(코드에서 [16, 24, 24], `04`).
- **이미지·영상 통합** (§2.1): 영상은 초당 2프레임으로 뽑고, 깊이 2인 3D 합성곱으로 두 프레임을 한 토큰 묶음으로 만들어 시퀀스 길이를 늘리지 않고 프레임을 더 넣습니다. 이미지는 같은 프레임 두 장으로 취급합니다. 영상당 총 토큰은 학습 때 16,384로 제한하고 프레임 해상도를 동적으로 조절합니다.

### 2.2 학습 (§2.2)

- 3단계입니다. 1단계는 ViT만 학습(이미지-텍스트 쌍, 약 600B 토큰), 2단계는 모든 파라미터를 풀고 추가 800B 토큰의 이미지 관련 데이터, 3단계는 ViT를 고정하고 LLM만 지시 데이터로 미세조정합니다. 사전학습 누적 1.4T 토큰이며 텍스트 토큰에만 감독을 줍니다. 지식 기준일은 2023년 6월입니다.
- 데이터 형식은 ChatML이고, 위치 지정은 좌표를 [0, 1000)로 정규화해 `<|box_start|>…`로 감쌉니다. 에이전트 데이터는 함수 호출 형식(UI 조작, 로봇 제어, 게임, 내비게이션)입니다.
- 인프라(§2.3): PAI-Lingjun, 3D 병렬(DP·TP·PP)에 ZeRO-1, 72B는 1F1B 파이프라인. 학습 규모(GPU 수·시간)와 학습률 같은 하이퍼파라미터는 적혀 있지 않습니다.

## 3. 실험 (§3)

| 표·그림 | 내용 | 비고 |
|---|---|---|
| 표 2 | 21개 일반 벤치마크, 72B·7B·2B 대 Previous SoTA·Claude 3.5·GPT-4o | 문항 수·생성 설정·판정자 서술 없음. 비교 대상 수치의 출처가 혼재(`03` §4) |
| 표 3 | 사내 다국어 OCR, GPT-4o와 8개 언어 | 사내 벤치마크, 규모 불명 |
| 표 4 | 영상: MVBench, PerceptionTest, EgoSchema, Video-MME | Video-MME는 최대 768프레임 제한 |
| 표 5 | 에이전트: 함수 호출(사내), AITZ, 카드 게임 4종, ALFRED, R2R, REVERIE | 함수 호출 평가셋은 Qwen 모델로 만든 사내 데이터 |
| 표 6 | 위치 지정(RefCOCO 계열) | 일반 모델 중 최상위 |
| 표 7, 그림 4 | 고정 토큰 수 대 동적 해상도, `min_pixels` | 7B, 단일 실행 |
| 표 8 | 1D-RoPE 대 M-RoPE | Qwen2-1.5B + ViT-L, 사전학습 모델 |
| 그림 5 | 72B의 영상 길이 외삽 (Video-MME 중간 길이) | 1D-RoPE 기준선 없음 |
| 그림 6 | 모델 크기·학습 토큰 대 성능 | "스케일링 법칙"이라 하지만 적합 곡선 없음 |

논문의 결론: 72B가 GPT-4o·Claude 3.5와 비슷한 수준이며(MMMU는 뒤짐, §3.1), 문서 이해에서 우위, 영상 20분 이상 이해, 다국어 OCR 우위(§1, §3.2). VLN(R2R, REVERIE)은 특화 모델에 크게 못 미치고 그 이유를 3D 지도 모델링의 어려움으로 돌립니다(§3.2.7).

## 4. 한계 (논문이 쓴 것과 우리가 본 것)

논문이 쓴 것: MMMU에서 GPT-4o에 뒤짐(§3.1), VLN에서 특화 모델에 크게 뒤짐(§3.2.7), Video-MME는 768프레임 제한이 긴 영상 성능을 깎을 수 있음(§3.2.6).

우리가 본 것 (자세한 근거는 `03`, `04`):
- 평가 설정(생성 방식, 프롬프트, 판정자)이 거의 서술되지 않았고, 표 2의 비교 대상 수치 출처가 서로 다릅니다.
- 모든 비교가 단일 실행이며 분산이 없습니다. M-RoPE 절제(표 8)는 사전학습 1.5B 모델이고 위치 번호 값 압축과 축 분리가 섞여 있습니다.
- 영상 외삽(그림 5)은 반사실이 없습니다.
- 채널 분할 비율, ViT 깊이·폭, 영상 총 토큰 제한 구현이 논문에 없습니다.

## 5. v1(2024-09-18)과 v2(2024-10-03)의 차이

`pdftotext` 결과를 줄 단위로 대조했습니다.
1. 각주 1 추가: "naive dynamic resolution은 사내 이전 버전 Qwen-VL Plus와 Qwen-VL Max에서 구현했고 Qwen2-VL에서 더 개선했다". 본문 문장도 "Unlike its predecessor"에서 "Unlike Qwen-VL"로 바뀜.
2. 표 2에 MMMU-Pro 행 추가(Previous SoTA 46.9, Claude 51.5, GPT-4o 51.9, 72B 46.2, 7B 43.5, 2B 37.6)와 참고문헌 추가(Yue 외 2024).
3. 내비게이션 벤치마크(R2R, REVERIE)의 인용이 빈 괄호에서 실제 인용으로 수정.
4. 그 밖의 차이는 쪽 번호와 각주 번호, 쪽 나눔뿐입니다. 수치 표(표 2의 기존 행, 표 3–8)와 방법 서술은 같습니다.

## 6. 같은 방법 이름의 다른 판본 (혼동 주의)

공식 저장소 `QwenLM/Qwen2-VL`은 현재 `QwenLM/Qwen3-VL`로 바뀌어 있어(`04` §1) 이 논문의 M-RoPE 코드가 아니라 후속 모델의 것을 읽게 될 수 있습니다. Qwen2.5-VL은 시간 번호를 절대 시간(초)으로 바꾸고 ViT에 창 attention을 넣었으며, Qwen3-VL은 M-RoPE 채널을 인터리브로 바꿨습니다(`02`, `04`). 이 논문의 식과 수치를 후속 모델에 그대로 옮기면 안 됩니다.
