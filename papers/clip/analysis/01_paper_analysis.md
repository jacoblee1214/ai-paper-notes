# 01. 논문 분석: Learning Transferable Visual Models From Natural Language Supervision (CLIP, arXiv:2103.00020)

분석 판은 arXiv v1(2021-02-26)이며 이 판 하나뿐입니다(arXiv API, 2026-11-26). 위치 표기 `Ln`은 `paper/paper.txt`(`pdftotext -layout`, 두 단 조판이라 줄이 섞이므로 근처 줄 범위로 읽을 것)의 줄 번호이고, 절·그림·표 번호는 논문의 것입니다.

## 1. 문제

- 당시 비전 시스템은 정해진 범주 집합(ImageNet 1,000개 등)의 정답 라벨로 학습합니다. 새 개념을 가리키려면 라벨 데이터를 더 모아야 합니다(초록, §1 L60–L100).
- 인터넷의 (이미지, 텍스트) 쌍에서 직접 배우면 지도의 폭이 자연어만큼 넓어지고, 학습한 표현을 문장으로 가리킬 수 있어 데이터셋별 학습 없이 "제로샷 전이"가 됩니다(§2.1).
- 앞선 시도(Visual N-Grams, VirTex, ICMLM, ConVIRT)는 규모가 가속기 "일" 단위에 10만–20만 장이라 벤치마크 성능이 낮았습니다. 논문의 기여는 새 아이디어가 아니라 **규모와 효율**입니다(§1 L100–L130, "ConVIRT의 단순화판").

## 2. 방법

### 2.1 데이터 (§2.2)

- WIT(WebImageText): 4억 (이미지, 텍스트) 쌍. 영어 Wikipedia에서 100회 이상 나온 단어, 고PMI 이중어, 일정 검색량 이상의 Wikipedia 문서 제목, WordNet synset을 합친 50만 개 질의로 검색하고 질의당 최대 2만 쌍으로 대략 균형을 맞춥니다. 총 단어 수는 WebText(GPT-2 학습 데이터)와 비슷합니다. **데이터셋은 공개되지 않았습니다.**

### 2.2 학습 목적 (§2.3, 그림 2, 그림 3)

- 처음에는 VirTex식으로 이미지 CNN + 텍스트 Transformer가 캡션을 예측하게 했으나, 63M 파라미터 Transformer LM(이미 ResNet-50보다 연산 2배)은 같은 텍스트의 bag-of-words(BoW) 예측 기준선보다 ImageNet 제로샷 학습이 3배 느렸습니다(그림 2).
- BoW 예측을 **대조 목적**으로 바꾸면 효율이 다시 4배 좋아졌습니다(그림 2, L185–L200, L278). 이유로 드는 것은 정확한 단어를 맞추는 일이 어렵고(설명, 댓글, 관련 텍스트가 다양), "어느 텍스트가 이 이미지의 짝인가"가 더 쉬운 대리 과제라는 설명입니다(L262–L285). 근거는 Tian 외(2019), Chen 외(2020a)의 선행 관찰이고 이 논문 안에서 이유를 따로 검증하지는 않았습니다.
- 배치 N개 쌍에서 N x N 가능한 짝 중 실제 N개를 맞춥니다. 이미지와 텍스트 임베딩의 코사인 유사도를 정답 쌍에서는 키우고 N²−N개 오답 쌍에서는 줄이며, **대칭 cross entropy**를 최적화합니다. 이 배치 구성과 목적은 N-pair loss(Sohn 2016), InfoNCE(Oord 2018), ConVIRT(Zhang 2020)에서 왔다고 밝힙니다(L240–L250).
- **그림 3(의사 코드).** `I_e = l2_normalize(I_f @ W_i)`, `T_e = l2_normalize(T_f @ W_t)`, `logits = (I_e @ T_e.T) * exp(t)`, `loss = (CE_i + CE_t) / 2`. 식 번호는 없고 이 의사 코드가 정의입니다.
- ConVIRT 대비 단순화(§2.3 L250–L270): 처음부터 학습(ImageNet·사전학습 LM 초기화 없음), **비선형 투영 없이 선형 투영만**, 텍스트에서 한 문장을 뽑는 변환 없음, 이미지 증강은 무작위 정사각 crop뿐, **온도 τ는 log 매개변수화한 곱셈 스칼라로 직접 학습**(하이퍼파라미터로 튜닝하지 않음).
- 사전학습 한 스텝은 "클래스가 32,768개이고 클래스당 예시가 1개인 무작위 대리 데이터셋"의 최적화로 볼 수 있다고 적습니다(§3.1.2 L385–L392).

### 2.3 모델 (§2.4–2.5)

- 이미지 인코더: ResNet-50 변형(ResNet-D, antialiased blur pooling, 전역 평균 풀링을 attention pooling으로 교체) 5종(RN50, RN101, RN50x4/x16/x64), 또는 ViT 3종(B/32, B/16, L/14; 패치+위치 임베딩 뒤 LayerNorm 추가).
- 텍스트 인코더: 12층 512폭 8헤드 Transformer(63M), 소문자 BPE(어휘 49,152), 최대 길이 76, 앞뒤에 [SOS], [EOS]를 두고 **[EOS] 위치의 최상위 층 활성**을 LayerNorm 후 선형 투영해 텍스트 특징으로 씁니다. causal(masked) self-attention을 쓰는 이유는 사전학습 LM으로 초기화하거나 LM 보조 목적을 더할 가능성을 열어 두기 위해서입니다(L325–L345). 텍스트 인코더는 폭만 ResNet에 비례해 키우고 깊이는 키우지 않습니다("텍스트 인코더 용량에 덜 민감").
- 학습: 32 에폭, Adam(분리된 weight decay) + 코사인 스케줄, **τ는 0.07에 해당하는 값에서 시작하고 로짓 배율이 100을 넘지 않도록 clip**("학습 불안정을 막는 데 필요했다"), 배치 32,768, 혼합 정밀도, gradient checkpointing, 유사도 계산은 GPU별로 쪼갬. RN50x64는 V100 592장 18일, 가장 큰 ViT는 V100 256장 12일. 본문의 "CLIP"은 ViT-L/14@336px(336 해상도로 한 에폭 더)를 가리킵니다(§2.5 L305–L350).

### 2.4 제로샷 분류기 (§3.1.2, §3.1.4)

- 클래스 이름(또는 프롬프트에 끼운 이름)을 텍스트 인코더에 넣어 임베딩하고 이미지 임베딩과의 코사인 유사도를 τ로 곱한 뒤 softmax합니다. 이 예측층은 "L2 정규화된 입력, L2 정규화된 가중치, 편향 없음, 온도 배율"의 다항 로지스틱 회귀이고, 텍스트 인코더는 분류기 가중치를 만드는 hypernetwork입니다(L363–L385). 분류기는 한 번 계산해 캐시합니다.
- **프롬프트 엔지니어링.** 클래스 이름만 넣으면 다의어(crane, boxer) 구분이 안 되고, 학습 텍스트가 대개 문장이라 단어 하나는 분포가 다릅니다. "A photo of a {label}."만으로 ImageNet +1.3%(L462–L500). 데이터셋별 문맥("..., a type of pet", 위성 사진, OCR은 따옴표)이 더 도움이 됩니다.
- **앙상블.** 확률 공간이 아니라 **임베딩 공간**에서 평균해 평균 임베딩 하나만 캐시하므로 비용이 단일 분류기와 같습니다. ImageNet에서 80개 문맥 프롬프트를 쓰면 기본 프롬프트 대비 +3.5%이고 합쳐 거의 +5%(L505–L525). 36개 데이터셋 평균으로는 약 5점이며 연산을 4배 쓴 것과 비슷한 이득이라고 합니다(그림 4, L439).

## 4. 한계 (저자가 적은 것, §6 L1321–L1420)

- 세부 분류(자동차 모델, 꽃 종, 항공기 변형)에서 과제 전용 모델보다 약함. **물체 수 세기 같은 추상적, 체계적 과제에 약함.** 가장 가까운 자동차까지의 거리 같은 새 과제는 우연 수준에 가까움(L1385–L1395).
- 사전학습 분포 밖은 약함: 손글씨 MNIST 88%로 원시 픽셀 로지스틱 회귀보다 낮음. "전체를 분포 안으로 만들겠다"는 가정은 순진하다고 인정(L1400–L1415).
- 후보 개념 중에서만 고르는 분류기이지 생성이 아님. 대조와 생성 목적의 결합을 제안.
- 데이터 효율이 낮음(32 에폭 x 4억 = 128억 이미지, 초당 1장이면 405년). 자기지도·자기훈련과의 결합을 제안.
- **방법론의 약점.** 개발 중에 전체 검증 세트에서 성능을 반복 조회했고(제로샷 설정으로는 비현실적), 27개 데이터셋 묶음은 "다소 임의로 모은" 것이라 CLIP의 개발과 co-adapted. 제로샷 일반화를 직접 재는 새 벤치마크가 필요하다고 적음.
- 인터넷 쌍은 거르지 않아 사회적 편향을 학습함(§7).
- 라벨 없는 개념을 텍스트로 지정하기 어렵고, few-shot으로 가면 선형 프로브로 후퇴하는데 이때 제로샷보다 성능이 오히려 떨어지는 직관에 반하는 현상이 있음.

## 5. 우리가 읽다가 확인한 모호함과 불일치

1. **어휘 크기.** 논문은 BPE 어휘 49,152(L328), 공식 코드의 토크나이저는 병합 49,152−256−2개와 바이트 토큰 512개, 특수 토큰 2개로 모델 어휘가 49,408입니다(`clip/simple_tokenizer.py` L67와 `tokenize`). 논문 숫자는 병합 규칙 수 기준으로 읽히고 모델 입력 어휘와 다릅니다. 영향은 없습니다.
2. **문맥 길이.** 논문 "최대 76"(L335), 코드 `context_length=77`(`tokenize` 기본값). SOS·EOS 두 토큰을 포함한 길이 77로 보이며 76은 어느 쪽을 센 것인지 명시되어 있지 않습니다.
3. **활성 함수.** 논문은 GPT-2 수정 구조라고만 적고, 코드는 QuickGELU(`x * sigmoid(1.702x)`)를 씁니다(`model.py` L166–L179). 논문 본문에는 없는 구현 세부입니다.
4. **온도 상한.** 논문은 "clip"이라 했으나 공식 저장소의 모델 파일에는 clamp가 없습니다(학습 코드 자체가 없음, `03` §3 D2). OpenCLIP 학습 코드가 스텝 뒤에 `ln(100)=4.6052`로 자르는 방식을 구현했고 "as in the original paper"라고 주석을 답니다.
5. **"제로샷"의 의미.** 이 논문은 제로샷을 "보지 못한 범주"가 아니라 "보지 못한 데이터셋"으로 넓게 정의합니다(§3.1.1). 사전학습 텍스트에 클래스 이름이 이미 많이 나오므로 전통적 제로샷 학습(보지 못한 클래스)과 다른 설정입니다. 비교할 때 주의.
6. **평가 선택 효과.** 저자 자신이 검증 세트를 반복 조회했다고 쓰므로(§6), 프롬프트 템플릿(예: ImageNet 80개)은 해당 평가 세트를 보고 고른 것일 수 있습니다. 논문 본문에는 템플릿 선택 절차(어느 분할을 썼는지)가 적혀 있지 않습니다.
7. **그림 13의 "최대 75%".** 7개 분포 이동의 평균이 아니라 모델 중 최대치로 읽힙니다("by up to 75%"). 모델별 값은 논문에 표로 없고 그림으로만 있습니다.
