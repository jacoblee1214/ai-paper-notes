# 03. 식 검산과 최소 구현 결과: CLIP (arXiv:2103.00020)

## 0. 한눈에 보기

- **식 검산(§1)**: 무작위 임베딩의 손실은 log N + s²/(2d)(N이 크고 s²/d가 1 안팎 이하일 때 맞음), 정렬된 직교 쌍은 닫힌 식 log(1+(N−1)e^{−s}), InfoNCE 하한 log N − L은 이변량 정규에서 min(I, log N) 이하, ∂L/∂t는 s(Σ P_ij C_ij − C_ii) 형태이고 autograd와 일치(2.9866). 모두 pytest와 `derivation_results.json`으로 확인했습니다. 배율 상한 100은 N = 32,768, s = 100에서 오답 코사인이 0.9를 넘으면 손실이 0.9로 오를 만큼 의미가 있습니다.
- **최소 구현(§2)**: 작은 ViT + causal 텍스트 Transformer(EOT 풀링), 선형 투영, 학습되는 log 온도(초기 log(1/0.07), 상한 ln 100), 그림 3의 대칭 InfoNCE, 임베딩 공간 프롬프트 앙상블 제로샷. 21만 파라미터. **pytest 14개 통과**(CPU 약 4–5초).
- **공식 코드(§3)**: `openai/CLIP`에는 **학습 코드와 손실, 온도 상한이 없습니다**(모델·추론만). 학습 쪽은 OpenCLIP의 `ClipLoss`와 `train.py`(`ln(100)` clamp, 주석 "as in the original paper")로 대조했고 그림 3과 일치합니다. 논문과의 소소한 차이: 어휘 49,152 대 49,408, 문맥 76 대 77, QuickGELU.
- **토이(§4–§6, 3설정 x 5시드)**: 보지 못한 (색, 모양) 조합이 텍스트 이름만으로 64-way 95.3% [92.8, 97.9](본 조합 100%). 프롬프트 앙상블 효과는 토이에서 시험되지 않음(차이 0.1%p 이하). **속성 결합은 baseline에서 93.0% [91.5, 94.5](우연 50%)로 bag-of-words 경향이 약하게만 나오고**, 맞바꾼 캡션을 부정 예시로 넣으면 100%, 배치 32(본 이미지 수도 4분의 1)에서는 79.6% [73.3, 85.9]로 낮아집니다. 모달리티 간격은 초기화에서 1.48, 학습 후 0.097로 닫혔습니다.
- 토이일 뿐 논문 재현이 아닙니다. 논문 수치는 확인하지 않았습니다.

## 1. 식 검산 (`analysis/derivation_checks.py`, `derivation_results.json`, pytest)

표기: 이미지 임베딩 u_i, 텍스트 임베딩 v_j는 L2 정규화된 d차원 벡터, C_ij = u_i · v_j(코사인), 배율 s = exp(t)(t는 학습되는 log 온도, τ = 1/s), 로짓 z_ij = s C_ij.

### 1.1 손실의 정의와 그림 3

한 방향 손실은 행 i에서 정답 열 i를 고르는 N-way 분류입니다.

L_row = (1/N) Σ_i [ −z_ii + log Σ_j exp(z_ij) ], L_col = (1/N) Σ_j [ −z_jj + log Σ_i exp(z_ij) ], L = (L_row + L_col) / 2.

- 그림 3의 `loss_i`(axis=0), `loss_t`(axis=1)는 어느 쪽 축으로 softmax를 하느냐의 이름 붙이기이고, 평균하면 어느 쪽이 어느 쪽인지는 무관합니다. 최소 구현과 OpenCLIP 둘 다 `(CE(logits, labels) + CE(logits.T, labels)) / 2`입니다.
- 두 방향은 일반적으로 값이 다릅니다(정규화되는 집합이 행이냐 열이냐). 그래서 평균이 정보가 있습니다. pytest가 `I`, `T`를 바꿔도 손실이 같고(`test_loss_is_symmetric...`), 두 방향 값이 다름을 확인합니다.
- 그림 3을 softmax로 풀어 쓴 기준 구현과 같음을 pytest가 확인합니다(`test_matches_figure3_pseudocode`).

### 1.2 무작위 임베딩: 손실 ≈ log N + s² / (2d)

독립인 무작위 단위 벡터의 코사인 C_ij는 대략 평균 0, 분산 1/d입니다. 따라서 z_ij ~ (0, σ²), σ² = s²/d. 대각 항의 기대값은 E[−z_ii] = 0이고 log-sum-exp는 N이 크고 σ가 작을 때 log Σ_j e^{z_ij} ≈ log N + log (평균 e^z) ≈ log N + σ²/2입니다(로그정규 모멘트). 그러므로 L ≈ log N + s²/(2d)입니다.

| N | d | s | 측정 손실 | log N | 근사 log N + s²/2d |
|---|---|---|---|---|---|
| 256 | 512 | 1.0 | 5.5475 | 5.5452 | 5.5462 |
| 256 | 512 | 14.29 | 5.7613 | 5.5452 | 5.7445 |
| 4096 | 512 | 14.29 | 8.5054 | 8.3178 | 8.5171 |
| 4096 | 64 | 14.29 | 9.8972 | 8.3178 | 9.9122 |
| 16 | 64 | 14.29 | 3.5288 | 2.7726 | 4.367 (어긋남) |

- 근사가 맞는 조건은 "N이 크고 σ² = s²/d가 1 안팎 이하"입니다. N = 16, d = 64, s = 14.3(σ² = 3.2)에서는 Jensen 간격이 커서 어긋납니다(근사 4.37, 측정 3.53). 맞는 영역과 안 맞는 영역을 함께 적습니다.
- 초기 배율 1/0.07 = 14.29에서 d = 512이면 s²/(2d) = 0.20이므로 무작위 초기화의 손실은 log N 바로 위입니다. 이 폴더 모델의 초기 손실도 log N 근처입니다(pytest `test_initial_loss_is_log_N...`, 허용 ±0.5).
- 함의: 학습의 진행은 "log N에서 얼마나 내려왔는가"로 읽을 수 있고, 배치가 클수록 같은 정렬 품질에서 손실의 기준점(log N)이 올라갑니다. 논문의 N = 32,768이면 log N = 10.40입니다.

### 1.3 정렬된 쌍의 닫힌 식과 온도

정답 코사인이 1이고 오답 코사인이 모두 c이면 softmax 한 행은 정답 하나와 오답 N−1개뿐이라

L = log(1 + (N − 1) · exp(−s (1 − c))).

- c = 0(직교)이고 N = 32,768이면 s = 1에서 9.40, s = 1/0.07 = 14.29에서 0.0203, s = 30에서 0.0000입니다. pytest가 N = 8의 s = 0.5, 2, 8, 32, 100에서 식과 정확히 같음(상대 오차 1e-9)과 s에 대한 단조 감소를 확인합니다. 즉 "완벽히 정렬된 쌍에서 온도를 낮추면 손실이 0으로 갑니다".
- **배율 상한 100이 의미 있는 이유.** 오답 쌍이 코사인 c를 가질 때 N = 32,768, s = 100에서 손실은 c = 0.5이면 0.0000, 0.8이면 0.0001, 0.9이면 0.911, 0.95이면 5.40입니다. 정렬이 좋아지면 s를 키우는 쪽의 기울기가 계속 남으므로(1.5절) 상한이 없으면 s가 무한히 커질 수 있고, 논문이 상한을 "학습 불안정을 막는 데 필요했다"고 적은 이유와 맞습니다(§2.5). 불안정의 구체적 메커니즘(수치 폭발 등)은 논문도 설명하지 않았고 우리도 시험하지 않았습니다.
- 토이에서는 상한이 활성화되지 않았습니다(학습 후 배율 약 27–38). 상한 작동은 인위적 설정에서만 pytest로 확인했습니다(`test_logit_scale_stays_below_100...`).

### 1.4 InfoNCE의 상호정보 하한

배치 안의 정답 쌍에서 오답 N−1개를 고르는 손실 L에 대해 I(X;Y) ≥ log N − L입니다(Oord 외 2018, Poole 외 2019가 정리한 결과. 이 폴더는 증명하지 않고 수치로 확인했습니다). 두 가지 성질은 바로 보입니다.

1. L ≥ 0이므로 log N − L ≤ log N: **배치 크기가 추정 가능한 상호정보의 상한을 정합니다.** N = 32,768이면 10.4 nats, N = 128(토이)이면 4.85 nats입니다.
2. 최적 비판자 f* = log p(y|x)/p(y)를 쓰면 하한이 I에 가장 가까워집니다.

이변량 정규(상관 ρ, 참 I = −½ log(1 − ρ²))에서 f*를 해석식으로 넣어 확인했습니다(`derivation_results.json`).

| N | ρ | 참 I | log N | log N − L |
|---|---|---|---|---|
| 16 | 0.5 | 0.144 | 2.773 | 0.135 |
| 16 | 0.99 | 1.959 | 2.773 | 1.667 |
| 16 | 0.999 | 3.108 | 2.773 | 2.292 |
| 16 | 0.9999999 | 7.712 | 2.773 | 2.767 |
| 128 | 0.99 | 1.959 | 4.852 | 1.907 |
| 128 | 0.999 | 3.108 | 4.852 | 2.957 |

- 모든 행에서 log N − L ≤ min(I, log N)(모두 ≤ I와 ≤ log N). I가 log N보다 작은 구간(ρ ≤ 0.99, N = 128)에서는 하한이 I에 붙고(1.907 대 1.959), I가 훨씬 큰 구간에서는 log N에 포화합니다(N = 16에서 I = 7.7이어도 2.767). pytest가 같은 성질을 확인합니다.
- **CLIP에서의 의미.** 이미지와 캡션 사이의 상호정보가 크면 배치를 키워야 그 정보를 손실이 구별해 냅니다. 이 해석은 InfoNCE에 대한 일반 논의이고, CLIP 논문 자체는 상호정보 하한을 쓰지 않았습니다. 그림 3 아래에서 InfoNCE를 계보로 언급할 뿐입니다(§2.3).

### 1.5 온도에 대한 기울기

t = log s로 매개변수화하면 행 방향 손실의 i번째 항 L_i = −s C_ii + log Σ_j exp(s C_ij)에 대해

∂L_i/∂t = s · ( Σ_j P_ij C_ij − C_ii ), P_ij = softmax_j(s C_ij).

- 해석: 정답 코사인(C_ii)이 softmax 가중 평균 코사인(Σ_j P_ij C_ij)보다 크면 기울기가 음수라 t가 커지고(온도 하강) 날카로워집니다. 정답이 평균 이하이면 반대로 t가 줄어 분포를 평평하게 합니다. 대칭 손실은 이 식을 행·열 두 방향에서 평균합니다.
- autograd 값 2.9866과 위 식의 값 2.9866이 일치합니다(`derivation_results.json`, pytest `test_gradient_wrt_log_temperature...`는 상대 오차 1e-9로 확인).
- 이 식이 "온도를 직접 학습하면 하이퍼파라미터가 사라진다"(§2.3)의 내용입니다. 정렬이 잘된 뒤에는 기울기가 계속 음수라 s가 오르고, 위 1.3의 상한이 그것을 막습니다.

### 1.6 제로샷 분류기와 앙상블

- 제로샷 예측은 argmax_c cos(u, w_c) 입니다. 가중치 w_c는 클래스 프롬프트의 텍스트 임베딩이고, 이 예측층은 "L2 정규화된 입력, L2 정규화된 가중치, 편향 없음, 배율 s"의 다항 로지스틱 회귀입니다(§3.1.2). 배율 s는 argmax를 바꾸지 않으므로 분류에는 무관하고 확률의 날카로움에만 영향을 줍니다.
- **앙상블은 임베딩 공간의 평균입니다**(§3.1.4): w_c = normalize( (1/K) Σ_k normalize(e_{c,k}) ). 재정규화의 크기 ‖평균‖은 클래스마다 다르므로 이 결정 규칙은 "코사인 점수의 평균"과 일반적으로 같지 않습니다(프롬프트들이 서로 비슷할수록 ‖평균‖이 1에 가까워 같아집니다). 논문은 이것이 점수나 확률 평균과 다른 규칙이라는 점을 적지 않았고 비용 이득(평균 임베딩 하나만 캐시)만 강조합니다. 공식 notebook의 `zeroshot_classifier`가 위 식 그대로입니다(정규화, 평균, 정규화).
- pytest가 `zero_shot_predict`가 위 식으로 손수 만든 기준과 같은 argmax를 내는지(템플릿 1개, 2개, 3개)와 가중치의 열 노름이 1인지 확인합니다.

### 1.7 계산량: 대조 목적이 예측 목적보다 효율적이라는 주장 (그림 2, 개념 수준)

논문의 근거는 그림 2 하나입니다. 63M 파라미터 Transformer 캡션 모델은 BoW 예측보다 ImageNet 제로샷 학습이 3배 느리고, BoW 예측을 대조 목적으로 바꾸면 4배 더 효율적입니다(§2.3, L236–L285). 이유로 드는 설명은 정확한 단어 열의 예측이 어렵다는 것입니다.

- 개념적 정리: 예측 목적은 p(텍스트 | 이미지)를 모델링하므로 이미지로 설명되지 않는 텍스트의 변동(어순, 수식어, 파일 이름, 설정값)까지 손실에 들어옵니다. 이 부분은 이미지 표현을 좋게 만들어도 줄지 않는 값이라 기울기의 신호 대 잡음비를 낮춥니다. 대조 목적은 손실이 0과 log N 사이로 묶여 있고 "이 텍스트들 중 짝이 어느 것인가"라는 상대 판단만 요구합니다. 한 배치의 2N번 인코더 순전파로 N² 쌍의 비교(N−1개 부정 예시)를 얻으므로, N · d가 인코더 비용에 비해 작은 한 비교가 사실상 공짜입니다.
- **우리가 한 것과 못 한 것.** 이 설명은 개념 정리이고 시험하지 않았습니다. 토이에서 예측 목적과 대조 목적의 학습 효율을 비교하지 않았습니다(텍스트 어휘 24개, 캡션 길이 10 이하라 예측 목적의 어려움이 거의 없는 환경이라 비교 의미가 없다고 판단). 논문의 3배, 4배는 ImageNet 제로샷, 한 가지 모델 구성, 한 번의 학습 곡선(시드·구간 없음)입니다. 이후 문헌은 이 우열을 규모에서 뒤집었습니다(`04` C3).

## 3. 공식 코드와의 대조 (논문 ↔ `openai/CLIP` ↔ OpenCLIP ↔ 최소 구현)

- 공식 `openai/CLIP`(MIT, 커밋 `d05afc4`, 2026-03-25, 9.7 MB)은 **모델과 추론만** 있습니다. 파일은 `clip/model.py`, `clip.py`, `simple_tokenizer.py`와 notebook 2개, 일관성 시험 1개이고, `cross_entropy`, `clamp`, `backward`, 옵티마이저 호출이 저장소 전체에서 한 번도 나오지 않습니다(grep). 그림 3의 손실과 학습 설정은 논문이 유일한 출처입니다.
- 학습 쪽은 OpenCLIP(커밋 `57e8d63`)의 `loss.py`(`ClipLoss`)와 `train.py`를 필요한 파일만 `gh api`로 받아 읽었습니다. OpenCLIP은 "원 논문을 따랐다"고 주석에 적은 재구현이고 OpenAI의 내부 학습 코드가 아닙니다. 아래 "OpenCLIP" 열은 재구현이 논문을 어떻게 해석했는지이지 OpenAI 학습의 증거가 아닙니다.
- 실행하지 않았고 가중치는 받지 않았습니다.

- **D4의 뜻.** EOT를 `argmax`로 찾는 방식은 토크나이저가 EOT에 가장 큰 id를 준다는 암묵적 계약입니다. 최소 구현의 `test_eot_is_largest_token_id`와 `test_text_encoder_pools_eot...`가 이 계약과 "EOT 뒤 패딩을 바꿔도 출력이 같다"를 확인합니다. 패딩(id 0)이 EOT보다 작다는 것도 같은 계약에 속합니다.
- 논문에는 있는데 코드에서 대응을 찾지 못한 것: 가중치 감쇠에서 gain·bias 제외, 혼합 정밀도 세부, 데이터 증강(무작위 정사각 crop). 학습 코드가 없어서입니다.

## 4. 합성 쌍 토이: 설정과 제로샷 (`run_experiments.py`, `toy_results.json`)

**설정.** 16x16 RGB 장면에 도형을 그립니다. 색 8가지(red, green, blue, yellow, magenta, cyan, orange, white) x 모양 8가지(square, circle, triangle, cross, diamond, ring, hbar, vbar) = 64 조합입니다. 장면은 한 물체(위치 자유) 또는 두 물체(왼쪽 하나, 오른쪽 하나)이고 반반 섞습니다. 캡션은 `템플릿 + 색 모양 [and 색 모양]`이며 두 물체는 왼쪽부터 씁니다. 템플릿은 `a photo of`(50%), `a drawing of`(45%), 맨 이름(5%)입니다. **대각선 8개 조합(red square, green circle, ...)은 학습 이미지와 학습 캡션에서 모두 뺍니다.** 한 시드의 학습은 2,500스텝, AdamW, 학습률 2e-3 원사이클, 위 모델(21만 파라미터)이며 CPU에서 수 분입니다(3개 설정을 동시에 돌려 시드당 약 7–10분). 시드 0–4, 설정 3개입니다.

| 설정 | 배치 | 손실 | 뜻 |
|---|---|---|---|
| `baseline` | 128 | 표준 대칭 InfoNCE | 그림 3 그대로 |
| `hardneg` | 128 | 두 물체 장면마다 모양을 맞바꾼 캡션을 이미지 -> 텍스트 부정 후보로 추가 | NegCLIP식 처방 |
| `smallbatch` | 32 | 표준 | 배치 안 맞바꾼 쌍이 더 드문 조건 |

평가는 시드마다 별도 생성기로 만든 2,000개입니다(제로샷 보유 조합 2,000, 보지 못한 조합 2,000, 결합 시험 두 물체 2,000). 표의 구간은 **5시드의 평균에 대한 t 95% 구간**(자유도 4, t = 2.776)이고, 평가 표본 오차(2,000개)는 시드 간 변동보다 작습니다(이항 표준오차 최대 약 1.1%p).

| 평가 | smallbatch | baseline | hardneg |
|---|---|---|---|
| 본 조합, 템플릿 `photo` | 98.7 [98.1, 99.4] | 100.0 [100.0, 100.0] | 100.0 [100.0, 100.0] |

- **구성적 일반화.** 이미지에서 한 번도 본 적 없는 (색, 모양) 조합이 텍스트 이름만으로 95%(64-way)에서 분류됩니다. 본 조합 100%와의 간격이 약 5%p입니다. 텍스트 인코더가 "빨강"과 "정사각형"을 따로 알고 이미지 인코더가 색과 모양 특징을 따로 배우면 새 조합을 얻는다는, 논문 §3.1.2의 "텍스트 인코더가 분류기를 합성하는 hypernetwork" 해석과 같은 방향의 토이 증거입니다. 단 제외 조합이 8개이고 이 토이의 개념 공간이 곱 구조(색 x 모양)로 아주 규칙적이라 실제 CLIP의 제로샷(WIT 4억 쌍, 자연 이미지)이 같은 이유로 되는지는 말해 주지 않습니다.
- **프롬프트의 효과는 토이에서 없습니다.** baseline과 hardneg에서는 맨 이름, `photo`, 앙상블의 차이가 0.3%p 이하이고, smallbatch에서는 맨 이름이 `photo`보다 1.2%p 낮지만 구간이 겹칩니다. 앙상블이 `photo` 단독보다 낫지도 않았습니다(차이 0.1%p 이하). 논문의 "프롬프트 엔지니어링과 앙상블로 약 5점"(§3.1.4)은 사전학습 텍스트가 문장이고 평가 클래스 이름이 단어 하나인 분포 불일치와 다의어 문제에서 오는데, 토이에는 둘 다 없습니다(평가 템플릿이 학습 템플릿 그대로이고 다의어가 없음). **따라서 논문의 프롬프트 주장은 이 토이로 시험되지 않았고, 반박도 확인도 아닙니다.**
- 배치 32는 보지 못한 조합에서 5.7%p(구간 [1.4, 10.0]) 낮습니다(짝지은 t 검정 p = 0.027, 아래 교란 참조).

## 5. 속성 결합: 대조 손실은 결합을 얼마나 강제하는가

같은 두 물체 장면에 대해 참 캡션(`a photo of 색1 모양1 and 색2 모양2`)과 **같은 단어 가방의 다른 캡션**을 비교합니다. 모델이 참 캡션에 더 높은 코사인을 주면 정답입니다(우연 수준 50%).

- **결합(속성 맞바꿈):** `색1 모양2 and 색2 모양1`. 두 물체의 모양을 바꿨고 단어 집합이 같습니다(Winoground와 ARO의 속성 시험의 토이판).
- **순서:** `색2 모양2 and 색1 모양1`. 두 물체의 순서를 뒤집었고 역시 같은 단어 집합입니다(ARO의 순서 시험의 토이판). 왼쪽-오른쪽 대응을 요구합니다.
- 대조군으로 색 하나를 다른 색으로 바꾼 캡션(단어 집합이 다름)도 쟀고 모든 설정과 시드에서 99.8–100%였습니다. 즉 "물체 인식"은 문제가 아니고 아래 결과는 결합과 순서에 한정된 것입니다.

| 지표(우연 50%) | smallbatch | baseline | hardneg |
|---|---|---|---|
| 속성 결합 정확도 | 79.6 [73.3, 85.9] | 93.0 [91.5, 94.5] | 100.0 [100.0, 100.0] |
| 순서 정확도 | 64.3 [54.4, 74.2] | 97.9 [96.4, 99.3] | 99.7 [99.3, 100.0] |

시드별 값은 `toy_results.json`의 `per_seed`에 있습니다(결합: smallbatch 0.745–0.854, baseline 0.916–0.948, hardneg 0.999–1.000).

**짝지은 차이(같은 시드끼리, 양측 짝 t 검정)**

| 비교 | 지표 | 차이(%p) [95% 구간] | p |
|---|---|---|---|
| hardneg − baseline | 속성 결합 | +7.0 [5.4, 8.5] | 0.0003 |
| hardneg − baseline | 순서 | +1.8 [0.5, 3.1] | 0.022 |
| hardneg − baseline | 보지 못한 조합 제로샷 | −1.1 [−3.3, +1.0] | 0.24 |
| baseline − smallbatch | 속성 결합 | +13.4 [8.2, 18.6] | 0.0027 |
| baseline − smallbatch | 순서 | +33.6 [24.3, 42.9] | 0.0007 |
| baseline − smallbatch | 보지 못한 조합 제로샷 | +5.7 [1.4, 10.0] | 0.027 |

비교는 6개이고 시드가 5개뿐이라 Bonferroni(0.05/6 = 0.0083)로 보면 hardneg−baseline 속성 결합(0.0003), baseline−smallbatch 속성 결합(0.0027)과 순서(0.0007)만 남습니다. 나머지는 탐색적 수준입니다.

**읽는 법(과 한계).**

1. **bag-of-words 경향은 이 토이에서 기본 설정(baseline)에서는 약하게만 나옵니다.** 표준 손실로 학습한 baseline이 결합을 93%에서 구별합니다. "대조 학습 모델은 결합을 구별하지 못한다"는 문헌의 관찰(Winoground, ARO)이 이 토이에서는 재현되지 않았다는 뜻입니다. 이유 후보 둘: (a) 이 토이의 이미지 인코더는 위치 임베딩이 있는 ViT이고 두 물체가 서로 다른 화면 반쪽에 있어 "왼쪽 물체의 색과 모양"을 위치로 묶기 쉽습니다(실제 이미지에서 같은 물체 위치가 임의인 것과 다름). (b) 캡션이 왼쪽부터 쓰여 있어 순서 정보를 정렬 신호로 직접 줍니다. 실제 CLIP이 겪는 자연 캡션은 이런 규칙성이 없습니다.
2. **그래도 결합 오류가 남습니다.** baseline의 7%는 쉬운 구성에서의 오류율이고 batch 32에서는 20%, 순서 오류는 36%까지 커집니다. 배치 안에 맞바꾼 쌍이 들어올 확률을 장면 생성 분포로 직접 세어 보면(`derivation_results.json`, `swap_twin_in_batch`) 두 물체 장면 중 맞바꾼 쌍(twin)이 같은 배치에 있는 비율이 배치 128에서 1.4%, 배치 32에서 0.4%입니다. 표준 손실이 결합을 **직접** 구별하게 압박하는 부정 예시가 배치의 1% 안팎에서만 나오는데도 baseline이 93%를 맞히는 것은 위 (a), (b)의 귀납 편향이 큰 몫을 한다는 간접 증거입니다. 이 해석은 분리 실험 없이 읽은 것입니다.
3. **맞바꾼 캡션을 부정 예시로 넣으면 결합이 100%가 됩니다(5시드 모두).** 이는 ARO가 처방한 hard negative 구성과 같은 방향이고(초록 수준, `04` C8), 결합을 "배울 수 없는" 것이 아니라 "표준 배치 구성이 요구하지 않는 것"이라는 해석과 맞습니다. 이때 보지 못한 조합 제로샷은 −1.1%p로 구별되지 않습니다(p = 0.24).
4. **배치 크기 효과는 교란됩니다.** `smallbatch`는 배치가 4배 작을 뿐 아니라 2,500스텝 동안 본 이미지 수가 4배 적습니다(8만 대 32만). 결합·순서·제로샷이 모두 낮은 것은 twin의 희소성뿐 아니라 총 학습량, 더 노이즈한 기울기 등이 섞인 결과입니다. 이 토이는 "배치가 클수록 결합이 낫다"가 아니라 "이 설정에서 작은 배치·적은 학습량 조합이 결합과 순서를 더 못 배운다"까지만 말합니다. 본 이미지 수를 맞춘 설정(배치 32를 10,000스텝)은 시험하지 않았습니다.
5. 이 결과는 **표준 손실이 결합을 못 배운다는 증거가 아니며**, 손실의 부정 예시 구성이 결합 학습에 영향을 준다는 것까지입니다. 실제 CLIP이 40번 Eyes Wide Shut 분석의 CLIP-blind 쌍(방향·수 세기)에서 실패하는 이유를 이 토이가 설명하는 것은 아닙니다. 그 실패의 원인은 대조 목적, 풀링(CLS 하나), 데이터의 캡션 통계 중 무엇인지 분리되지 않았습니다.

## 6. 모달리티 간격 (`gap_results.json`, 3시드)

Liang 외(2203.02053)는 초기화에서 두 인코더의 표현이 좁은 원뿔에 갇혀 모달리티가 떨어져 있고 대조 학습이 이를 유지한다고 주장합니다(초록). 같은 정의(이미지 임베딩 평균과 텍스트 임베딩 평균 사이의 유클리드 거리, 단위 벡터)로 토이를 쟀습니다.

| 시점 | 평균 간격 | 짝 코사인 | 이미지끼리 평균 코사인 | 텍스트끼리 평균 코사인 |
|---|---|---|---|---|
| 초기화 직후(3시드 평균) | 1.48 | −0.11 | 0.995 | 0.988 |
| 학습 후(2,500스텝, 배율 33–35) | 0.097 | 0.968 | 0.281 | 0.284 |

- **초기화의 원뿔 효과는 확인됩니다.** 무작위 초기화 모델의 서로 다른 입력 쌍이 평균 코사인 0.99–0.995로 거의 한 방향에 몰려 있고(그래서 1.2절에서 초기 손실이 log N 근처), 두 모달리티의 평균이 1.4–1.6 떨어져 있습니다. 이 수치는 학습 전 임의 초기화에 대한 것입니다.
- **학습 후 간격은 거의 사라졌습니다**(0.10, 단위 벡터에서 최대 2). Liang 외는 대조 학습이 간격을 유지한다고 했고, 그 크기는 온도에 영향받는다고 초록이 말합니다(정확히는 "온도가 영향"). 이 토이는 쉬운 과제, 작은 모델, 배율 약 34(τ ≈ 0.03)에서 간격이 닫혔습니다. 즉 **원뿔 부분은 확인, "간격이 유지된다"는 이 토이에서 확인되지 않음**입니다. 반박도 아닙니다. 온도·초기화·모델 크기를 바꾼 시험을 하지 않았고 실제 CLIP의 간격은 시험하지 않았습니다.

## 7. 한계

- **토이일 뿐 논문 재현이 아닙니다.** 21만 파라미터, 64 조합, 합성 도형, 2,500스텝입니다. 논문의 어떤 수치도 이 토이로 확인되지 않았습니다. 식 검산(§1)이 가장 이식성이 높은 부분이고, 토이 결과(§4–§6)는 "이 설정에서의 성질"입니다.
- 5시드의 t 구간은 자유도 4라 넓고, 시드가 독립인 표본이라는 가정(같은 코드와 하이퍼파라미터, 시드만 다름)에 기댑니다. 일부 짝 비교는 시드가 같아서 짝지었습니다.
- 하이퍼파라미터(학습률 2e-3, 2,500스텝)는 시드 0의 몇 회 예비 실행(배치 128, 1,500–2,500스텝, hard negative 유무)을 본 뒤 정했고 설정 간 튜닝은 하지 않았습니다. 예비 실행에서 색 4 x 모양 4일 때 baseline의 결합이 거의 100%였고(조합 공간이 작아 twin이 흔했음), 그래서 8 x 8로 키웠습니다. 이 선택은 "결합이 어려운 쪽"으로 설정을 옮긴 것이라 결과(baseline 93%)는 설정 선택에 의존합니다.
- 두 물체가 항상 화면 좌우로 분리되고 캡션이 왼쪽부터라는 구조적 단서가 결합을 쉽게 했을 수 있습니다(§5의 1).
