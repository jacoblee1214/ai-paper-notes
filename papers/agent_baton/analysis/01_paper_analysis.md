# 01. 논문 분석: AgentBaton (arXiv:2610.35959)

분석 판은 arXiv v1(2026-10-25, 유일한 판)입니다. 이 논문에는 번호가 붙은 식이 없습니다. 방법은 글과 표로만 서술되어 있어서, 아래 근거 위치는 절·표·그림 번호입니다.

## 1. 문제

긴 에이전트 과제는 비싼 강한(capable) 모델로 풀어야 믿을 만하지만 비용이 큽니다. 싸고 약한(efficient) 모델이 있습니다(하위 등급 클라우드 모델, 로컬 오픈 웨이트). 기존 라우팅·캐스케이드는 **과제 시작 때 질의만 보고** 모델 하나를 고릅니다(§1, §5). 이 논문의 질문은 "한 과제 안에서 두 모델이 일을 넘겨받으면(handoff) 비용을 크게 줄이면서 정확도를 지킬 수 있는가"입니다(초록, §1). 설계 선택으로 **인계 방향**(강→약, 약→강), **문맥 전달 방식**, **인계 시점**을 봅니다.

## 3. 결과 (§3)

### 3.1 방향과 전달 방식 (표 1, 30%·75% 시점)

- 원천 모델의 **단독 실행 궤적을 재생**해 선택한 턴까지의 작업 공간을 복원하고, 그 지점에서 수신 모델이 이어받습니다. 인계 시점은 "원천 모델 단독 궤적 길이의 30% 또는 75%"입니다(§3.1).
- 약→강: 로그 파일이 문맥 안보다 정확도가 같거나 높고 비용이 낮은 경우가 많음(§3.1). 강→약: GLM·Kimi는 문맥 안이, GPT-5.6 Sol은 혼합. 논문의 가설은 Sol이 추론 과정을 노출하지 않아서라는 것(§3.1, "may partly stem").
- 결론 문장: 약→강은 로그 파일이 유리, 강→약은 모델과 시점에 따라 다름(§3.1).

### 3.2 인계 시점 (그림 3, 그림 6, 15–90% 여섯 지점)

- 약→강: 이른 인계는 강한 단독과 비슷해도 절감이 작고(Sol 30%: 정확도 70.8% 대 68.1%, 비용 6.1%만 감소), 늦은 인계는 GLM·Kimi에서 정확도가 떨어짐(§3.2).
- 강→약: Kimi 45%에서 72.57% 대 73.45%, 비용 61.5% 감소. Sol 60%에서 67.26% 대 68.10%, 47.9% 감소. GLM 30%에서 61.1%로 단독과 같고 82.4% 감소(§3.2).
- Terminal-Bench는 "모델과 시점에 따라 덜 일관적이고, 늦은 인계가 정확도를 단조롭게 올리지 않는다"(부록 A).
- 논문의 해석: "한 방향 의존"이라 턴마다 바꾸는 라우팅은 오류가 쌓여 어려울 수 있다(§1, §3.2). 이 주장을 직접 검증하는 실험은 §4.4의 MTRouter 비교 하나입니다(`03` §6).

### 3.3 성공하는 인계의 패턴 (그림 4)

Qwen이 이른 인계에서는 실패하고 다음 인계에서는 성공한 궤적 세 개(사례)를 보고 세 신호를 뽑습니다: ① 실질적 구현 또는 실행 가능한 산출물이 있음, ② 실행·테스트·점검으로 과제 관련 피드백이 있음, ③ 남은 일이 국소 진단·수리·검증·마무리로 좁혀짐. 피드백이 긍정적일 필요는 없고 실패한 실행도 문제를 좁히면 유익하다고 합니다(§3.3). **사례 세 개로 얻은 정성적 규칙이며 정량 검증은 없습니다.**

## 4. AgentBaton (§4)

### 4.1 프롬프트만으로 인계 (표 2)

강한 모델에게 인계하라고 지시하면 Kimi K3는 0/113, GLM-5.3은 6/113만 인계합니다. GPT-5.6 Sol은 113/113 인계하지만 비용 3.75달러로 단독 5.32달러 대비 29.5% 절감에 그치고 정확도 62.8%(단독 68.1%)입니다(§4.1).

### 4.2 학습 (§4.2, 부록 B)

| 항목 | 내용 |
|---|---|
| 데이터 | SWE-rebench V2에서 무작위 2,000과제. 과제마다 5개 강한 모델(GPT-6 Astra, GPT-5.6 Sol, Claude Opus 5, Kimi K3, GLM-5.3) 중 2개를 무작위로 골라 궤적 4,000개 (Astra는 medium, 나머지 max) |
| 라벨 | Codex(OpenAI)가 궤적을 **사후에** 읽고 "가장 이른 적합 인계 턴"을 표시. 증거는 도구 호출과 응답만(비공개 추론, 검증 결과, 최종 보상, 수신 모델 결과는 제외). 세 조건이 모두 처음 성립하는 턴. 없으면 `no_clear_handoff_point` |
| 모델 | Qwen 3.5 2B 초기화(9B는 개선 없음, 각주 2). 입력은 시스템 지시문 + 원래 과제 + 강한 모델의 행동·관찰 + 이전 판정들 |
| 출력 | 턴마다 `{"judgement":"HANDOFF_NOT_READY"}` 또는 `HANDOFF_READY` |
| 학습 | h턴 이전은 NOT_READY, h턴은 READY, **h 이후 모든 턴도 READY 예시로 추가**(놓친 인계를 이후 턴에 만회하도록). 2 에폭, 최대 32K 토큰, H100 16장, FSDP2, bf16, 전역 배치 16 packed 시퀀스, AdamW 1e-5 |
| 추론 | 매 턴 판정, 첫 READY에서 수신 모델에 이관. 문맥이 한도를 넘으면 가장 오래된 절반을 버림. 중앙 지연 338 ms, p95 1.11 s(H100 1장, 입력 2K–121K 토큰 360회) |

평가 벤치마크(Terminal-Bench 2.1, DeepSWE v1.1)와 **학습 데이터(SWE-rebench V2)는 다른 데이터셋**입니다. 같은 벤치마크 과제로 학습하지 않았습니다.

### 4.3 주요 결과 (표 3)

- 모델 쌍 11개(강한 5 × 싼 2 + Luna→Qwen) × 벤치마크 2개 = 22칸. 평균 비용 절감 65.9%, 정확도는 12/22칸에서 "개선 또는 상대 손실 5% 미만", 강한 모델 단독 대비 최대 +8.8%p(Opus 5 → Luna, DeepSWE 67.3 → 76.1).
- 평균 인계 진행률은 DeepSWE 26.6–41.1%, Terminal-Bench 55.6–68.9%.
- 표 3은 원천 모델마다 전달 방식을 하나로 고정(Sol·Luna는 로그 파일, 나머지는 문맥 안)합니다. 부록 표 5에 두 방식의 전체 값이 있고, **고정 규칙은 데이터를 본 뒤 정한 것으로 보입니다**(§3.1 결과와 같은 데이터에서 고름, `03` §6).

### 4.4 비교 (§4.4, 표 4)

- 질의 단계 라우터(Qwen 3.5 2B를 SWE-rebench V2 2,000과제의 성공 라벨로 학습, 균형 표본): 학습 정확도 99.55%이나 Qwen을 고르는 과제는 하나뿐이라 사실상 강한 단독. 라우터의 평가 데이터 정확도는 보고하지 않았습니다.
- MTRouter(턴 단위 라우팅) 재현: GLM·Kimi 쌍에서 AgentBaton이 비용 46.7–86.6% 낮고 정확도는 같거나 높음.
- 고정 진행률(AgentBaton의 평균 인계 진행률을 임계값으로, 단 **미래 정보인 원천 궤적 총길이 필요**)과 고정 턴: 고정 진행률과 정확도 비슷, 고정 턴보다 높음.

### 4.5 파레토 확장 (그림 1, 표 6)

DeepSWE에서 추론 노력 수준을 바꿔 가며(Sol·Opus: low–max 5단계 등) AgentBaton을 붙이고, 단일 모델 구성들이 이루는 경험적 파레토 프론티어를 넘는다고 주장합니다(§4.5). 예: Kimi→Luna(high) 79.6% / 1.60달러, 단일 최고 Opus xhigh 75.2% / 8.90달러.

## 5. 저자가 적은 한계

본문 한계 절은 없습니다. 본문에서 한 번씩 언급한 것: 인계 시점은 원천 궤적 길이에 상대적이고 한 번만 인계(§2), 비용은 로컬 모델에 0을 매기는 "우리의 회계 규약"(§2), 정확도 보존은 모델 쌍과 벤치마크에 따라 다름(§4.3), 고정 진행률 기준선은 미래 정보를 씀(§4.4).

## 6. 읽을 때 걸리는 점 (검증은 `03`, `04`)

1. 문항 수가 DeepSWE 113, Terminal-Bench 89인데 반복 실행과 시드가 보고되지 않습니다. 정확도 차이를 표본 오차와 비교할 수 없습니다.
2. 표 3과 표 6에 같은 구성(DeepSWE, max 노력)인데 값이 다른 칸이 있습니다(GLM 단독 61.1 대 69.0 등).
3. "비용 65.9%"는 22칸 단순 평균이고 비교 기준이 "max 노력 단독 강한 모델"입니다. 같은 표에 있는 싼 모델 단독(Luna)이 일부 인계 설정을 지배합니다.
4. 방향 비대칭의 설명(진행의 질, 문맥 전달, 강한 모델의 적응)을 가르는 통제 실험이 없습니다.
5. 공식 코드·가중치·궤적·학습 데이터 라벨이 공개되어 있다는 언급이 없습니다.
