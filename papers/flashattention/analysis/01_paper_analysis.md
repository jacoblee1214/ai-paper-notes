# FlashAttention (arXiv:2205.14135) 논문 분석

분석 판: arXiv v2(2022-06-23, 최신). v1은 2022-05-27. 분석일 2026-11-28. 구현 모드(기여가 알고리즘·IO 분석이고 이미 널리 재현된 고전).
한 줄: **정확한 attention을 바꾸지 않고, N×N 행렬을 HBM에 쓰지 않도록 타일링과 재계산으로 HBM 읽기·쓰기 수를 Θ(N²d²/M)로 줄인 IO 인식 알고리즘.**

## 1. 문제

- 표준 attention(Alg. 0)은 S = QKᵀ와 P = softmax(S)를 HBM에 쓰고 다시 읽는다. 메모리 O(N²), HBM 접근 Θ(Nd + N²)(Thm. 2). (§2.2)
- 근사 attention(희소, 저랭크)은 FLOPs를 줄여도 **벽시계 시간이 줄지 않는 경우가 많다**. 이유로 메모리 접근 비용을 지목한다. (초록, §1)
- GPU 연산은 메모리보다 빨리 빨라졌고 트랜스포머 연산 대부분이 메모리 병목이다(§2.1, A100: HBM 1.5–2.0 TB/s, SRAM 192 KB × 108 SM, 대역폭 약 19 TB/s). softmax, 마스크, 드롭아웃 같은 원소별·축소 연산이 memory-bound의 예다(§2.1).

## 2. 방법

| 요소 | 내용 | 위치 |
|---|---|---|
| 타일링 + online softmax | softmax를 블록 통계 (m, ℓ)로 분해: m = max(m⁽¹⁾, m⁽²⁾), ℓ = e^{m⁽¹⁾−m} ℓ⁽¹⁾ + e^{m⁽²⁾−m} ℓ⁽²⁾ | §3.1 |
| Alg. 1 (순전파) | 바깥 루프 K_j, V_j (SRAM 적재), 안쪽 루프 Q_i, O_i, ℓ_i, m_i 적재 → S_ij, P̃_ij를 온칩 계산 → O_i를 갱신해 HBM에 쓴다. 블록 크기 B_c = ⌈M/4d⌉, B_r = min(⌈M/4d⌉, d) | §3.1, 부록 B.3 Alg. 2 (마스크·드롭아웃 포함) |
| 재계산 | 역전파에서 S, P를 저장하지 않고 O와 (m, ℓ)로 블록마다 다시 만든다. 선택적 gradient checkpointing으로 설명 | §3.1, 부록 B.4 Alg. 4 |
| 역전파 식 | dV = PᵀdO, dP = dOVᵀ, dS_ij = P_ij(dP_ij − D_i), **D_i = P_i:ᵀ dP_i: = dO_iᵀ o_i** (식 (3)–(6)). D_i를 길이 d 내적으로 구해 길이 N 합을 피한다 | 부록 B.2, B.4 |
| 커널 융합 | 모든 단계를 CUDA 커널 하나로. 마스크와 드롭아웃은 PRNG 상태 R만 저장해 역전파에서 마스크를 다시 만든다 | §3.1, 부록 B.4 |
| 블록 희소 | 블록 마스크 M ∈ {0,1}^{N/B_r × N/B_c}에서 0인 블록을 건너뛴다(Alg. 5). 실험은 butterfly 희소 패턴 | §3.3, 부록 D.1 |

### 이론 결과

- **Thm. 1**: Alg. 1은 O = softmax(QKᵀ)V를 O(N²d) FLOPs와 O(N) 추가 메모리로 계산한다(증명 부록 C, 루프 불변식 귀납).
- **Thm. 2**: d ≤ M ≤ Nd일 때 표준 Θ(Nd + N²), Flash Θ(N²d²M⁻¹). 증명: K, V는 한 번 읽고 Q, O를 T_c = Θ(Nd/M)번 훑는다 → Θ(Nd·T_c).
- **Prop. 3 (하한)**: 모든 M ∈ [d, Nd]에서 동시에 o(N²d²M⁻¹) HBM 접근인 정확 attention 알고리즘은 없다. 증명은 M = Θ(Nd)에서 입출력 크기 Ω(Nd)만 쓴다(부록 C). 논문 자신이 "M에 대한 매개변수 하한은 미래 과제"라고 적는다.
- **Thm. 5**: 역전파도 표준 Θ(Nd + N²), Flash Θ(N²d²M⁻¹).
- **Prop. 4**: 블록 희소는 Θ(Nd + N²d²M⁻¹ s), s는 0이 아닌 블록 비율. s = N^{-1/2}이면 Θ(N√N), s = N⁻¹ log N이면 Θ(N log N).

## 5. 한계 (논문이 적은 것과 우리가 본 것)

논문이 적은 것(§5): 새 attention마다 CUDA 커널을 새로 써야 함(고수준 언어에서 컴파일하는 방법이 필요), 다른 모듈의 IO 인식화, 다중 GPU.
우리가 본 것(근거는 `03`):
1. **Thm. 2의 이득 조건**: Θ 안에 상수가 숨어 있어, 순전파 접근 수 기준으로 M ≳ 3d²일 때만 표준보다 적다(`03` §3.2). 논문은 "d²가 M보다 훨씬 작다"고만 쓴다(§3.2).
2. **블록 크기 규칙은 SRAM을 M의 1.28배까지 쓴다**(`03` §3.4). Θ에서는 무해하지만 M을 엄밀한 용량으로 읽으면 안 된다.
3. Prop. 3은 M = Θ(Nd) 한 점의 자명한 하한이다. 초록의 "optimal for a range of SRAM sizes"는 이 증명이 보장하는 것보다 강한 표현이다(이후 문헌의 정밀한 하한은 `04` C2).
4. Fig. 2 왼쪽의 66.6 GFLOPs는 보고된 설정에서 우리가 센 값과 12배 다르고 단위·계측법이 적혀 있지 않다(`03` §6.4).
5. 속도 주장의 보고 방식: 초록·서론의 "3× on GPT-2"는 Table 2의 3.0–3.5×(HF 대비), "1.8× over Megatron"은 Table 2 비율 1.67–1.74와 다르다(`03` §6.2). Table 1의 ±가 표준편차인지 표준오차인지 적혀 있지 않아 유의성이 갈린다(`03` §6.1).
6. 공식 코드는 이 논문 시점(v1 CUDA, Apex FMHA 기반)이 아니라 FlashAttention-2/3 이후 구조로 바뀌었다(`04` D1).
