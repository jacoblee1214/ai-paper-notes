# 04. 이후 문헌의 확인·수정·반박 (C1–C8)과 공식 코드 정적 대조 (D1)

범위: 구현 모드라서 논문 ↔ 코드 전수 대조 대신 (a) 논문의 핵심 주장을 이후 문헌과 우리 계산이 어떻게 다루는지(C), (b) 공식 저장소 현재 판을 정적으로 읽은 소견(D)을 적는다. 공식 코드는 **실행하지 않았다.** 이후 문헌은 arXiv 초록까지만 읽었다(본문 미확인은 아래에 명시). 웹 검색은 쓰지 않았고 arXiv API와 GitHub API만 썼다.

## C. 주장 검증

| ID | 논문 주장 (위치) | 이후 문헌 / 우리 검증 | 판정 |
|---|---|---|---|
| C1 | 근사 없이 정확한 attention을 O(N) 추가 메모리로 계산 (Thm. 1, §3.1) | **우리**: float64에서 정답과 1e-12, 역전파 1e-11 일치, float32 1e-5 이내(`03` §1, §5). FA2 초록도 "no approximation" 서술 | **확인** (수학적 정확성. 수치 정밀도는 C7) |
| C2 | HBM 접근 Θ(N²d²/M)이고 "SRAM 크기 범위에서 최적" (초록, Thm. 2, Prop. 3) | **Saha & Ye 2024 (arXiv:2402.07443, 초록)**: M ≥ d²에서 FlashAttention과 상수 배 안에서 맞는 하한을 증명. 논문의 Prop. 3은 M = Θ(Nd)에서의 Ω(Nd)만 막는다고 지적. **M < d²에서는 더 적은 I/O의 알고리즘이 있고 그것이 최적**. 행렬곱을 빠른 알고리즘으로 바꿔도 하한은 유지. **우리**: 상수까지 보면 M ≲ 3d²에서 Flash가 표준보다 접근을 줄이지 못한다(`03` §3) | **수정**: Θ는 M ≥ d² 영역에서만 최적. 논문의 최적성 문구는 그 영역으로 한정해 인용. Saha & Ye의 증명 본문은 읽지 않았다(초록 수준) |
| C3 | 벽시계 2–4×(표준 대비), GPT-2 최대 3×, BERT 15% (초록, Table 1–4, Fig. 3) | **FA2 (arXiv:2307.08691, 초록)**: 2–4× "compared to optimized baselines"를 되풀이하면서 v1이 이론 최대 FLOPs/s의 **25–40%**에 그친다고 진단. **FA3 (arXiv:2407.08608, 초록)**: FA2가 H100에서 35% 활용, FA3는 1.5–2.0×, 최대 740 TFLOPs/s. **우리**: Table 2·4 속도비를 시간 열에서 재계산해 일치(`03` §6.2). GPU 속도는 재현 불가 | **확인(속도 자체) + 수정(상한)**: 속도 이득은 인정되나 v1은 하드웨어 한계에 한참 못 미쳤고 후속이 올림. 인용할 때 "v1 수치"임을 적을 것 |
| C4 | 메모리가 시퀀스 길이에 선형 (Thm. 1, Fig. 3 오른쪽) | FA2 초록: "linear instead of quadratic". **우리**: CPU에서 N = 4096 → 8192 때 naive 메모리 5.5배, 타일 커널 1.4배(`03` §7). 닫힌 식에서 추가 메모리 2N(`03` §1.3 표) | **확인** (우리 측정은 PyTorch CPU 타일 커널이지 논문 커널이 아님) |
| C5 | 재계산으로 FLOPs가 늘어도 HBM 접근이 줄어 역전파가 빨라진다 (§3.1–3.2, Fig. 2) | **우리**: 행렬곱 FLOPs 비 14/12 = 1.17(`03` §6.4), 접근 수 비 6.2×(모형, M = 98,304, N = 1024, d = 64). 단 d = 128에서는 접근 수 이득이 1.8×로 작고 M이 3d² 아래면 사라짐(`03` §3). 공식 코드가 역전파에서 S를 다시 계산함은 정적으로 확인(D1) | **부분 확인**: 방향은 우리 모형과 일치하나 GPU 시간은 재현하지 않았음 |
| C6 | 블록 희소가 알려진 모든 근사 attention보다 빠르고 HBM 접근이 s에 비례 (Prop. 4, §4.3) | **우리**: 접근 수가 2Nd + s·T_c·N(3d+4)로 **정확히 선형**(`03` §4). 속도 우위, LRA 품질은 확인하지 못함. 공식 저장소에 `flash_blocksparse_attention.py`가 있음(정적으로 존재만 확인, 현재 사용 여부 모름) | **부분 확인**: IO 항만 확인 |
| C7 | 모델 정의를 안 바꾸므로 학습 곡선과 ppl이 baseline과 같다 (§4.1, Fig. 4) | **Golden et al. 2024 (arXiv:2405.02803, 초록)**: 고립된 순전파에서 BF16일 때 Flash가 Baseline attention보다 **약 한 자릿수 큰 수치 편차**를 보인다고 보고. **우리** (fp16, S·P를 fp16으로 저장하는 naive 기준): flash가 더 정확(20/20 시드, GPT-2 헤드 720개 중 99.2%, 오차비 약 2.5배)(`03` §5). 기준 구현과 정밀도(bf16 대 fp16, fp32 softmax 여부)가 달라 모순이라 단정할 수 없다 | **조건부**: "곡선이 같다"는 관찰이지 수치 동일이 아님. 비교 기준(baseline의 중간 정밀도)에 따라 방향이 달라질 수 있음. 해소하지 못함 |
| C8 | BERT-large가 MLPerf 1.1 기록보다 15% 빠름 (Table 1) | **우리**: 20.0/17.4 = 1.149 일치. ±가 표준편차면 p = 0.0008, 표준오차면 p = 0.22(`03` §6.1). 이후 문헌에서 독립 재현은 이 폴더에서 찾지 않았다 | **보류**: 보고 방식이 모호해 유의성이 갈림 |

## D. 공식 코드 정적 대조 (D1)

대상: `Dao-AILab/flash-attention` HEAD `2676a7be000545279a692d97151eac0762df6842`(2026-11-25), BSD-3-Clause. 읽은 곳: `csrc/flash_attn/src/flash_fwd_launch_template.h`, `flash_fwd_kernel.h`, `flash_bwd_kernel.h`, `flash_attn/flash_attn_interface.py`, `README.md`. **이 HEAD는 FlashAttention-2/3 이후 구조이고 논문(v1)의 코드가 아니다.** 논문 시점 코드와의 대조는 하지 않았다(역사 커밋을 열지 않음).

| ID | 논문(Alg. 1/4) | 현재 코드 | 의미 |
|---|---|---|---|
| D1a | 바깥 루프 K_j, V_j, 안쪽 루프 Q_i (줄 5–7), O를 안쪽 반복마다 HBM에 읽고 쓴다 | 커널 grid가 `dim3 grid(num_m_block, b, h)` 즉 **Q 블록(m_block)이 병렬 축**이고 `n_block`(K 블록)이 커널 안의 루프(`flash_fwd_kernel.h:745`) | FA2의 작업 분할 변경과 일치(`02` §3). O가 반복마다 HBM을 오가지 않아 Thm. 2의 T_c번 Q·O 훑기 항이 달라진다. 우리 시뮬레이터는 논문 Alg. 1 그대로라서 **현재 커널의 접근 수가 아니다** |
| D1b | 블록 크기 B_c = ⌈M/4d⌉, B_r = min(B_c, d) | 헤드 차원별 고정 타일 `Flash_fwd_kernel_traits<Headdim, kBlockM, kBlockN, ...>`, head dim 64에서 128×128 (`flash_fwd_launch_template.h` run_mha_fwd_hdim64) | M에서 유도한 이론 규칙이 아니라 튜닝된 상수 |
| D1c | ℓ, m 두 벡터 저장 | `softmax_lse` 하나(float32, 형상 batch×heads×seqlen_q) (`flash_attn_interface.py`) | `03` §1.2의 "L 하나면 충분"과 같다 |
| D1d | 역전파 줄 10: dQ_i를 HBM에서 읽어 더하고 다시 쓴다 | 역전파 커널에 `dq_accum` 누적 버퍼(`flash_bwd_kernel.h`, dq_accum 오프셋) | dQ를 별도 누적 버퍼로 모음. 접근 수 항이 달라지나 세부는 읽지 않음 |
| D1e | 인과 마스크는 원소 −∞(부록 B.3 mask) | `n_block_max`를 인과·국소일 때 줄여 완전히 가려진 K 블록을 건너뜀(`flash_fwd_kernel.h:93–95`) | 우리 구현의 인과 블록 건너뜀과 같은 최적화 |
| D1f | 드롭아웃은 PRNG 상태 R만 저장 (부록 B.4) | 인터페이스가 `rng_state`를 반환(`flash_attn_interface.py:99`) | 일치(구현은 읽지 않음) |

우리 구현과 공식 코드의 차이는 구조 수준에서 D1a–D1b가 크다. 우리 구현은 논문 Alg. 1/4의 IO 분석 모형이고 현재 CUDA 커널의 모형이 아니다. 이 점은 `03` §2–3의 접근 수를 인용할 때 반드시 붙일 단서다.
